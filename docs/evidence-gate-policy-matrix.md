# AppSurface evidence gate policy and producer matrix

This is the implementation inventory for [issue #777](plans/issue-777-policy-driven-ci-evidence-gate-implementation.md). A selected profile may become a required claim only after every producer, resource, assertion, artifact slot, deadline, and cleanup action in its row has an explicit registration and a passing failure-path proof. Existing workflow success is not an EvidenceHost producer result. The reference gate remains non-required until the [rollout pilot](evidence-gate-rollout.md) proves current-head association and strict freshness.

The existing [build workflow](https://github.com/forge-trust/AppSurface/blob/main/.github/workflows/build.yml), [package gate](https://github.com/forge-trust/AppSurface/blob/main/.github/workflows/package-gate.yml), and [release checks](https://github.com/forge-trust/AppSurface/tree/main/.github/workflows) remain independently necessary. No job is removed with #777. During the pilot, record each existing job's assertion overlap, outcome, and added runtime. A later migration can assign steady-state ownership only after equivalent success and failure behavior is observed and separately reviewed.

The AppSurface-specific policy must put unknown paths and mixed changes into a conservative profile containing the union of every targeted PR obligation. The [planner](../Evidence/ForgeTrust.AppSurface.Evidence.Planner/README.md) validates this property before a trusted gate run. Release-preparation PRs use a targeted PR profile; only the protected release invocation may select `ReleaseComplete` from the validated V2 preparation-base/tag diff. A missing safe producer keeps its profile fail-closed and prevents ruleset activation; deleting its obligation to get a green check is not a valid fallback.

The policy uses the same conservative union for package project and lock files inside the PostgreSQL and Keycloak resource trees. Those paths change both dependency supply and an integration surface; the more specific project/lock rules carry explicit precedence so the resource rule cannot silently drop the package obligation. Non-.NET executable assets without a dedicated producer also select the conservative profile and remain incomplete.

Resource provisioning belongs to the base-owned supervisor, with only declared service endpoints exposed to the credentialless subject VM. Restore, build hooks, and all head-controlled execution stay in that VM with pinned SDK/OCI images and locked dependencies. Exact per-profile deadlines and an overall workflow budget will be fixed from the cold-cache pilot before the check becomes required. The trusted verifier checks the current PR base/head or protected tag after the subject result, so an earlier successful producer cannot authorize a changed revision.
