# AppSurface policy-shadow fixtures

[`fixtures.json`](fixtures.json) is the reviewed case set for the [non-claiming policy-shadow comparison](../../../Evidence/ForgeTrust.AppSurface.Evidence.Planner/README.md#non-claiming-policy-shadow-comparison). The file is a JSON array of `EvidencePolicyShadowFixture` records. Each record has a unique `id`, a base-owned `kind` (`Documentation`, `Code`, `Resource`, `ControlPlane`, or `Unknown`), and a `changedPath` object with a repository-relative `path`. A rename also supplies `kind: "renamed"` and `previousPath` inside `changedPath`. The canonical API shape and limits are in the [planner reference](../../../Evidence/ForgeTrust.AppSurface.Evidence.Planner/README.md#non-claiming-policy-shadow-comparison).

The protected base revision must supply this file and the reviewed [AppSurface policy](../../../.appsurface/evidence/evidence.policy.json) to the trusted comparison. Candidate revisions may supply a copy as additional data, but removing or editing a base case is a finding and never removes the original case. The checked-in policy explicitly treats this fixture directory as control-plane material. The [rollout record](../../evidence-gate-rollout.md) tracks the separate live pilot and explains why a branch-owned shadow result is not a required-check verdict.

The fixture set covers a docs-only path, ordinary code, PostgreSQL and Keycloak resources, package artifacts, workflows, the first-party runner, the release tool, this fixture file, an unknown extension, and a resource-to-code rename. The adjacent `AppSurfaceEvidencePolicyTests` resolve all cases under the checked-in policy. A base-owned workflow still needs to supply trusted input provenance and classify actual changed paths before this comparison can authorize any control-plane transition.
