Issue: [#815](https://github.com/forge-trust/AppSurface/issues/815)

## Problem Statement

AppSurface promises that each repeatable --test-argument contributes one literal dotnet test argument. CliFx currently rejects both --test-argument "--blame-hang" and --test-argument=--blame-hang before coverage discovery. The reported Skoolit coverage host can then sit without progress for 180 seconds and leave only the project name or last completed test. Fix the broken forwarding contract and make actionable, bounded hang evidence an AppSurface default, so each downstream consumer does not have to invent its own VSTest setup and XML reader.

## What Makes This Cool

A failed coverage run should tell the operator which test was last started and where its VSTest sequence artifact lives. The operator can distinguish that observation from a proven culprit. AppSurface owns the timing, no-dump policy, artifact containment, and summary once for CLI and first-party Evidence coverage.

## Constraints and premises

- Scope is the supported VSTest coverage path, for both collector and explicit msbuild drivers. Do not imply Microsoft.Testing.Platform support.
- Keep the private Evidence.Coverage engine private. CliFx parsing stays in the CLI; Evidence.Contracts and Evidence.Aspire do not gain a general coverage configuration API.
- Preserve the exact order and bytes of user-supplied test argument tokens and existing collector-owned option rejection before discovery or output mutation. Continue passing a token array through CliWrap, never a shell command string.
- AppSurface automatic blame uses --blame-hang, --blame-hang-timeout, and --blame-hang-dump-type none. VSTest may terminate the test host at its timeout; the sequence records started tests and does not prove which test hung. No sequence is guaranteed when the host dies before flushing, a phase other than tests stalls, or another deadline wins.
- --watchdog fail becomes the CLI default, retaining the existing 10m no-progress timeout and terminal exit 124 / ASCOV121 when the AppSurface watchdog wins. Explicit warn and off remain available. The first-party Evidence producer uses fail as its fixed default, with its existing producer deadline still authoritative.
- VSTest hang timeout is a per-test timer (with adapter-specific behavior for data-driven tests), separate from AppSurface's output-sensitive progress clock. It can terminate a legitimate long-running test even when the wrapper sees other output. Conversely, AppSurface's watchdog can win during a series of shorter tests. State this compatibility change in help, README, release notes, and migration guidance.

## Cross-model perspective

An independent cold read supported putting the default in AppSurface and preserving manual pass-through. It challenged the assumption that every quiet test is hung: default fail can terminate valid long tests, so the design needs an opt-out and a real long-test regression. It suggested deferring msbuild and raw Sequence interpretation. We keep both because msbuild is a supported VSTest driver and a raw XML path alone leaves the original downstream integration work undone. The Evidence producer deadline is an additional race the design must account for.

## Approaches considered

- A. Parser fix and raw artifact only: smallest change, but every consumer still has to interpret Sequence.xml and msbuild users lack the same default.
- B. Shared diagnostic policy and bounded interpretation: selected. One private-core policy sets no-dump VSTest options, retains scoped artifacts, and publishes a safe last-started-test observation for both drivers and Evidence.
- C. Generated combined runsettings: rejected. It changes the existing collector runsettings boundary and adds an unnecessary configuration surface for this issue.

## Recommended approach

### Command boundary

Add a coverage-run-only argv normalization step before CliFx binds options in AppSurfaceCliApp. Recognize the registered two-token command route coverage run at the start of argv, using the same case handling as CliFx; this command has no alias. Other routes, incomplete routes, and standalone help/version invocations pass through unchanged. For this route, recognize exact --test-argument split and --test-argument=VALUE joined forms only. Rewrite a joined form to split option plus an opaque safe placeholder; rewrite the split value to that placeholder. Bind through the existing CommandOption, then restore the original exact values in their bound order before constructing CoverageRunRequest. The per-invocation map is immutable and local to one command execution; choose placeholders absent from the entire incoming argv and reject any collision. A value of --help immediately after --test-argument is a literal value; an unattached --help remains CliFx help. The split form always consumes the immediately following argv token as its literal value, even if it resembles an AppSurface option; only end-of-argv is a missing value. This explicit one-token contract must be stated in help. Reject missing or empty values with an actionable command diagnostic. Preserve repeatability, interleaving, argument order, and direct constructor/test behavior. After restoration, run the existing owned-switch guard before discovery. Test the whole public command path, including split and joined forms.

### Shared default and manual precedence

Set CoverageRunCommand.Watchdog to fail and change the Evidence coverage request from warn to fail through one internal coverage default constant/policy. Do not broaden the public Evidence declaration. This coupling is deliberate: fail requests automatic no-dump VSTest blame during tests when the remaining test-phase budget is at least 90 seconds. A shorter budget keeps fail-mode watchdog behavior but records skipped-short-budget and promises no sequence artifact. Explicit warn/off disables the automatic blame timer and the fail-mode wrapper response, leaving only any independent Evidence/caller deadline. Document that choosing warn/off opts out of the automatic hang sequence, not just the wrapper response.

For a fail-mode VSTest invocation, append AppSurface's --blame-hang, --blame-hang-timeout, and --blame-hang-dump-type none tuple before collector runsettings and after driver-owned arguments. Define a manual blame token as --blame or a token beginning --blame- (case-insensitive), optionally followed by = or : and a value. This covers --blame-hang, --blame-hang-timeout, --blame-hang-dump-type, --blame-crash, crash dump settings, and future blame switches. Any such token claims the entire group: forward all user tokens untouched and suppress the automatic tuple, even if the manual group is incomplete. In msbuild mode, a user --settings/-s file also claims the group because its blame configuration cannot be inspected here. Document that manual settings can produce dumps and that the caller owns timing and disk impact. Existing coverage-driver ownership rules remain in force.

### Time budget

At Evidence producer start, use one injected TimeProvider to record a monotonic start timestamp and create an internal CoverageProducerDeadline (start timestamp, positive TimeoutSeconds duration, same clock). Pass the deadline through the private run request into Evidence.Coverage. Retain the producer's linked cancellation as the authoritative outer deadline; derive remaining time at each test process launch as duration minus clock.GetElapsedTime(start), clamped at zero. Tests inject a fake clock and a controlled cancellation source. The ordinary CLI has no producer deadline.

Immediately before starting the supervisor's project operation, compute the budget as the smaller of the configured no-progress timeout and the remaining Evidence deadline. Each project operation starts a fresh no-progress clock at this point; progress in discovery/build and other projects does not consume its interval. The VSTest timeout is fixed for that invocation and is not recalculated when output later resets the watchdog clock. For a remaining test-phase budget of at least 90 seconds, reserve the smaller of 60 seconds and one third of that budget, round the VSTest timeout down to whole seconds, and append --blame-hang-timeout with that duration. A full 180-second remaining test-phase budget yields 120 seconds; if a 180-second Evidence deadline spent 30 seconds in discovery/build, the 150-second remainder yields 100 seconds. The 10-minute CLI default yields 9 minutes. Reserve time is a best-effort opportunity for Sequence.xml to flush and for AppSurface to summarize it, not a completion guarantee. When the budget is shorter than 90 seconds, do not auto-enable VSTest blame; keep the outer watchdog/deadline and record why no automatic sequence was expected. If remaining time is already exhausted, allow the existing deadline cancellation to win. Do not start a VSTest timer for discovery, build, merge, or gate phases.

### Invocation artifacts and safe summary

Use collector's already unique raw results directory. In msbuild mode, allocate a unique AppSurface-owned results directory per project invocation only when automatic blame is active, then pass --results-directory. For msbuild in fail mode without a manual blame switch or settings file, reserve results-directory ownership before discovery even if a later short budget prevents auto blame. Reject case-insensitive --results-directory, --results-directory=VALUE, and --results-directory:VALUE user tokens with ASCOV101 before discovery; reject a missing split value with the existing incomplete-option form. If manual blame or a msbuild settings file suppresses automatic blame, preserve the current msbuild results-directory pass-through and make no claim about a user-chosen directory. Explicit warn/off likewise preserves current msbuild pass-through. Do not make a stale file from --no-clean look current.

Extend CoverageRunProjectExecutionState with an invocation identifier, verified owned results-directory path, planned diagnostic source/timeout, and mutable diagnostic status. Set this state before starting dotnet test, not only when a CoverageProjectRunResult completes. After a normal process exit, inspect sequence files before artifact normalization can fail. On cancellation, the supervisor first terminates and drains child process leases within its existing cleanup budget; then the terminal handler inspects each launched state's owned directory using a bounded read and writes the existing best-effort terminal timings snapshot. Extend the existing OperationCanceledException catch to run this same post-drain best-effort snapshot path before rethrowing the original cancellation; never change Evidence's TimedOut mapping or a caller's cancellation into a test failure. If draining cannot be confirmed, record inspection unavailable instead of reading a file still being written. A cancelled project may have no completed result, but its invocation and diagnostic state remain in the snapshot. No operation waits indefinitely to create diagnostics, and inspection failures cannot replace the primary failure.

Inspect only Sequence.xml candidates beneath the current invocation's verified directory. Bound traversal to depth 4 and 256 entries per directory, accept at most 8 sequence files, at most 1 MiB per file/8 MiB total, at most 10,000 test entries total, XML depth 8, and 256 display characters per name. Reuse physical containment and regular-file opening; prohibit DTDs/external resolution; parse only TestSequence/Test Name and discard Source host paths. Record explicit missing, malformed, oversized, escaping, duplicate, unreadable, and inspection-limited states without changing the original test/watchdog outcome. For parallel hosts, record one bounded observation per sequence, each labeled “last started test,” never “hung test.”

Treat XML names as untrusted local metadata. For console and timings.json, display a last-started name only if it is 1–256 characters and matches a conservative identifier allowlist (ASCII letters/digits, underscore, period, and plus, starting with a letter or underscore); otherwise omit the name and retain the relative sequence path with status name-omitted. This rule prevents control, bidi, newline, path, and parameter-value injection; it does not promise to detect secrets embedded in a valid identifier. Evidence results never include test names or XML contents.

Add an optional per-project hangDiagnostics object to timings.json with its own schemaVersion: 1, source (automatic/manual/none), status, scoped relative sequence paths, safe last-started names when available, and effective VSTest timeout. Do not version or break the existing top-level timings format: existing schedule readers continue using projects and seconds and ignore the new field. A consumer that parses hangDiagnostics must ignore the optional object when its schemaVersion is unknown while continuing to use the base timings. Source automatic means the no-dump tuple was actually appended; manual means a user blame switch or msbuild settings file claimed the group, whether or not it enables blame; none means no blame was requested. For collector manual runs, inspect the still-owned invocation directory and report found, missing, or the applicable invalid/limited state. For msbuild manual runs, report unscoped because AppSurface does not own the results directory; do not claim a sequence was absent. With source none use disabled, skipped-short-budget, or not-started as applicable. Use in-flight state when the completed project result is absent. For a failed test or watchdog incident, print a short safe summary with a relative artifact path after inspection. Preserve raw Sequence.xml in the owned invocation directory for local operator inspection. VSTest host termination remains the existing failed-test outcome (usually ASCOV120); only AppSurface watchdog termination is ASCOV121/124. An Evidence producer deadline still returns TimedOut with no assertions. Once the core has unwound, its message may point to the fixed relative coverage/timings.json path only if that regular owned artifact exists; otherwise retain the current generic timeout message. Do not embed XML, test names, raw logs, or unverified paths in Evidence results.

## Success criteria

1. Both forms from #815 reach dotnet test as literal dash-prefixed tokens; the owned-option guard still fails before discovery.
2. An ordinary VSTest coverage run defaults to watchdog fail and automatic no-dump blame for collector and msbuild; explicit warn/off has no automatic blame. Evidence uses the same fail policy within its remaining producer deadline.
3. A controlled hang yields a scoped Sequence.xml and bounded “last started test” observation before a 180-second remaining test-phase budget expires in the reproduced case. Missing evidence is represented honestly.
4. Existing failure codes and exit behavior remain attributable to the actor that terminated the run. Normal coverage, manual blame, and legitimate long-test opt-out paths are covered.
