## Acceptance procedure

1. Run the focused `TailwindArtifactProvenanceTests` command in the implementation
   plan on a prepared .NET 10 host. Keep expected valid/invalid fixture summaries;
   record cold/warm duration. It uses actual temporary packages and recording push
   seams and cannot publish to NuGet.
2. Run the entire PackageIndex xUnit project, then affected Tailwind tests and
   solution tests. Run formatting and analyzer/documentation validation. Use
   `./scripts/coverage-solution.sh` when practical; inspect changed branch coverage
   and account for every uncovered failure branch. Do not use reflection tests.
3. Execute resolver fixtures through its actual Bash entrypoint with a fake `gh`
   response executable, including multi-page history and all H01-H08 transitions.
   Parse workflow YAML and test dependencies, pinned actions, exact env/output
   mappings, source checkout, permissions, retention and protected token ordering.
   String-presence assertions alone do not prove identity dataflow.
4. On the implementation branch, use the existing package-artifacts manual
   dispatch to pack once and call the native workflow on five trusted runners.
   Manual rehearsal must never run NuGet login/push or export release secrets.
   Keep PR-triggered jobs from invoking trusted self-hosted native runners.
5. Collect full native evidence, run the same aggregate/preflight services, and
   exercise original-ID interrupted publication via a recording publisher in
   tests. Perform native mutations against isolated fixture copies only; do not
   mutate the frozen candidate or success evidence. Retain rejected diagnostics.
6. Exercise one failed native invocation and a full rerun. Verify frozen producer
   reuse and five fresh matching receipts. Show incomplete failed-only rerun
   rejection in fixture or manual rehearsal. Verify actual retention/runner setup
   before enabling either protected publish workflow.

No LLM or prompt behavior changes: eval suites are not applicable. Browser QA is
not applicable. Existing package, solution, workflow and native tests are required;
a passing mock suite alone cannot approve the release gate.

## Exit criteria and retained evidence

Every matrix row has an implemented passing case, including its stated negative
variants. All five native hosts pass the valid candidate and relevant projection
mutation probes. The original-candidate retry fixture proves zero publication
with bad/stale/missing evidence. Existing #790 CSS/cache/no-native-output behavior,
non-Tailwind publication, stable readiness and smoke-install behavior remain green.
Retain command/test output, branch coverage, actual SDK/host identity, artifact IDs,
subject/aggregate hashes, native reports and bounded failure diagnostics. Record
what was executed versus simulated. No real NuGet publication is required to
satisfy this test plan.
