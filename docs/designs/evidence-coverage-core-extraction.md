## Problem Statement

[#776](https://github.com/forge-trust/AppSurface/issues/776) must make the existing AppSurface coverage implementation available to the first-party Evidence path **without** reimplementing coverage behavior or starting a second `appsurface` process.

Today `CoverageRunWorkflow`, `CoverageGateEvaluator`, and their coupled filesystem, artifact, merge, watchdog, and patch-diff helpers live under `Cli/ForgeTrust.AppSurface.Cli`. The first Evidence command added in #775 reaches directly into those CLI internals: `EvidenceRunCommand` injects `CoverageRunWorkflow` and calls the static gate evaluator. That proves the product path, but it leaves the reusable engine in the wrong assembly and couples EvidenceHost to CLI implementation details.

The result should be a single private coverage engine that the public coverage commands and the first-party Evidence coverage producer call in-process. Existing CLI behavior remains authoritative and unchanged at its public boundary.

## What Makes This Cool

EvidenceHost becomes trustworthy for coverage because it is not an imitation of the CLI. The same discovery, scheduling, process supervision, Cobertura merge, patch-target analysis, threshold evaluation, artifacts, and cleanup run once in both paths. A coverage claim is therefore evidence about the command users already rely on, not about a parallel runner that happens to look similar in happy-path tests.

## Constraints

- The extraction is implementation-only. It adds no public coverage orchestration API and no consumer extension point.
- Do not shell out from Evidence to `appsurface`; use the extracted code in-process.
- Preserve `coverage run`, `coverage merge`, `coverage gate`, and `coverage clean` command syntax, defaults, artifacts, exit semantics, diagnostics, scheduling, watchdog behavior, and cleanup behavior.
- Keep `CliFx` commands, option parsing, stdout/GitHub-summary presentation, and command-specific exception mapping in `ForgeTrust.AppSurface.Cli`.
- Keep Evidence contracts and `IEvidenceProducer` translation outside the coverage core. The core must not depend on `Evidence.Contracts`, `Evidence.Planner`, `Evidence.Aspire`, or consumer code.
- Replace every core `CommandException` use with one internal structured coverage failure type carrying the existing stable code, rendered message, and optional exit code. The CLI alone maps that type back to the exact current `CommandException` contract.
- Preserve the current explicit `--diff-file` flow. A patch gate in `evidence run` must continue to use the same bounded unified-diff artifact that planning consumed; normalized changed paths alone are insufficient for line-level patch coverage.
- The Evidence result must remain bounded and secret-safe. It may name controlled relative coverage artifacts and stable failure classes, but must not place raw test logs or host paths in the manifest diagnostic.
- The existing `ReportGenerator` tool payload remains owned by the CLI tool package. The extracted runtime locates that known payload through the host layout; it must not create a second tool-payload distribution path.
- Tests use public or intentionally friend-visible seams only. No reflection or wall-clock sleeps.

## Premises

1. One implementation must own run, merge, gate, and artifact safety. A facade that independently reconstructs either the runner or gate violates the feature's reason for existing.
2. A pair of caller-owned `TextWriter` values is a sufficient shared progress boundary. `IConsole` is a CLI adapter concern; normal progress must retain its existing stdout routing and watchdog/critical diagnostics must retain stderr routing.
3. `ForgeTrust.AppSurface.Evidence.Cli` is the first-party adapter layer. It can translate a core result to `EvidenceProducerResult` because it already owns Evidence planning/CLI workflow code, while `Evidence.Aspire` remains a generic explicit-registration lifecycle host.
4. The package graph may carry an internal implementation assembly as a dependency, but every type intended for that assembly's consumers remains `internal`. Publishing a package artifact is not permission to publish an API contract.

## Approaches Considered

### A. Project-cut extraction

Move the coverage code almost unchanged and retain its `CliFx.IConsole` dependency. This is fast, but turns CLI presentation plumbing into a permanent dependency of the reusable engine. Rejected because it makes the wrong boundary easy to preserve.

### B. Cohesive private coverage core — selected

Move the mutually coupled coverage implementation to `ForgeTrust.AppSurface.Evidence.Coverage`, replace its `IConsole` dependency with `TextWriter`, and keep CLI and Evidence adapters thin. This is the smallest boundary that retains one engine while preventing CLI and Evidence contracts from leaking into each other.

### C. Public coverage contracts package

Create public request/result abstractions before extraction. Rejected because no external consumer has demonstrated a compatibility need, and #776 explicitly prohibits a new general-purpose coverage API.

## Recommended Approach

### Package and dependency graph

Add two implementation projects and keep dependency direction inward:

```text
ForgeTrust.AppSurface.Cli ────────────────> ForgeTrust.AppSurface.Evidence.Cli ──> Evidence.Contracts
            │                                           │
            └───────────────────────────────────────────┼──────────────> Evidence.Coverage
                                                        │
                                                        └──> Evidence.Contracts

ForgeTrust.AppSurface.Evidence.Aspire ───────────────────────────────────> Evidence.Contracts

Evidence.Coverage ──> CliWrap and BCL only
  no reference to CLI, CliFx, Evidence.Contracts, Evidence.Planner,
  Evidence.Cli, Evidence.Aspire, or consumer assemblies
```

Each arrow denotes a `ProjectReference`. The CLI is the only composition root that supplies CLI-owned implementations. `ForgeTrust.AppSurface.Evidence.Cli` references `Evidence.Coverage` to implement the first-party adapter, while `Evidence.Aspire` continues to reference only Evidence contracts and explicit lifecycle abstractions. It must not gain a dependency on the coverage core: it executes whichever typed producer the trusted first-party command/bootstrap registers.

The coverage project is shipped only as an implementation dependency of first-party packages. Its coverage types stay `internal`; classify it only as a transitive support package, never as a direct-install/user-facing package-index offering. Its exact friend matrix is:

| Assembly | Allowed friends | Reason |
| --- | --- | --- |
| `ForgeTrust.AppSurface.Evidence.Coverage` | `ForgeTrust.AppSurface.Cli`, `ForgeTrust.AppSurface.Evidence.Cli`, `ForgeTrust.AppSurface.Cli.Tests` | Command adapters, first-party Evidence adapter, and the established consolidated coverage regression suite only. |
| `ForgeTrust.AppSurface.Evidence.Cli` | `ForgeTrust.AppSurface.Cli`, `ForgeTrust.AppSurface.Evidence.Cli.Tests` | Existing command assembly and adapter tests only. |
| `ForgeTrust.AppSurface.Cli` | `ForgeTrust.AppSurface.Cli.Tests` | Existing public-command regression test boundary. |

Existing direct workflow tests remain in the established `ForgeTrust.AppSurface.Cli.Tests` coverage regression suite, which receives intentional first-party friend visibility alongside command contract tests. No dynamic-proxy or consumer-package friend is added. A compile-time package-API check verifies that the new assembly exposes no public coverage orchestration type or CliFx signature.

### Core shape

Keep the existing coverage value types and workflows internal, moving them as a coherent unit rather than translating through newly public DTOs. Introduce one internal composition entry point for Evidence, conceptually:

```csharp
internal Task<CoverageEvidenceExecutionResult> RunAndGateAsync(
    CoverageRunRequest run,
    CoverageGateRequest gate,
    CoverageTextWriters writers,
    CancellationToken cancellationToken);
```

The entry point does not own command defaults or policy interpretation. It runs the existing workflow, stops before the gate when the run failed, evaluates the supplied gate request only after a successful merged Cobertura result, writes the existing controlled gate artifacts, and returns enough internal information for the adapter to select a stable evidence outcome.

`CoverageRunWorkflow` and `CoverageMergeWorkflow` remain the implementation owners of their present operations. The new composition entry point prevents the Evidence adapter from recreating the required ordering, but it must delegate to those workflows rather than duplicate their logic.

Replace the core's `IConsole` parameters, including watchdog output, with an internal `CoverageTextWriters(TextWriter Output, TextWriter Error)` record. Both writers are caller-owned: core code never disposes, flushes, or retains either after the operation finishes. Existing normal progress continues to `Output`; watchdog incidents and critical diagnostics continue to `Error`, preserving output routing and ordering. The core cannot write GitHub summaries, parse CLI options, construct `CommandException`, or determine process exit behavior. The CLI passes `new(console.Output, console.Error)`; focused tests pass two deterministic `StringWriter` instances and prove both routing and ordering.

Replace `CommandException` throughout moved run, merge, gate, watchdog, output-safety, and cleanup code with an internal `CoverageExecutionException`. It carries the existing rendered diagnostic and optional nonzero exit code, including the watchdog's `124`. A CLI-only `CoverageCommandExceptionMapper` converts it to the same `CommandException` message and exit code at each command boundary. Core tests assert the structured coverage failure; CLI regression tests assert byte-for-byte stable public diagnostics and exit behavior.

`Evidence.Coverage` owns `ICoverageRunReportGenerator`, `CoverageRunReportGenerator`, and `IReportGeneratorPackageLocator` as internal merge abstractions. The CLI keeps the `ReportGenerator` package reference, `GeneratePathProperty`, packed `tools/.../reportgenerator` payload, and concrete `ReportGeneratorPackageLocator`. The CLI composition root registers that locator and one report-generator implementation once; both ordinary coverage commands and `CoverageEvidenceProducer` receive the same core services. `Evidence.Cli` must not add a ReportGenerator package reference, copy the payload, or probe a second package layout.

Move the following coupled source units with their tests, splitting only their command adapters from their execution code:

- `CoverageRun.cs`: keep `CoverageRunCommand` and `CoverageRunDiagnostics` in CLI; move request/result models, `CoverageRunWorkflow`, process execution, output guard, sandbox guard, and internal helpers. Replace core `CommandException` paths with `CoverageExecutionException`.
- `CoverageMerge.cs`: keep the command wrapper in CLI; move merge request/result/workflow, source resolver, output guard, path-safety, staging, and report-generator abstractions. Replace core command exceptions with coverage failures.
- `CoverageGate.cs`: keep command option parsing, command-level diff-source selection, GitHub-summary opt-in/appending, and CLI failure mapping in CLI; move the core-only gate request/model, Cobertura evaluator, patch parser, artifact/report writer, diff readers, and output-path policy to core. Remove `WriteGithubSummary` and `GithubStepSummaryPath` from the core request. The core writes the bounded Markdown artifact; the CLI-only summary adapter appends that artifact when requested and maps its existing `ASCOV008` failure. Replace core command exceptions with coverage failures.
- `CoverageProjectManifest.cs`, `CoverageRunArtifactReader.cs`, `CoverageRunDrivers.cs`, `CoverageRunOutputLease.cs`, `CoverageRunSlowTestDiagnostics.cs`, `CoverageRunWatchdog.cs`, and any coverage-only filesystem interop to core.
- Keep `CoverageCleanCommand` in CLI, but make it consume the moved output-safety types so its current behavior remains part of the same safety model.

The destination namespace is `ForgeTrust.AppSurface.Evidence.Coverage` for every moved type. Private and file-local helpers move with their owner. No type may have two owners, no file in the core may reference CliFx, and no CLI command-layer file may retain coverage execution, merge, gate evaluation, patch parsing, or artifact-write logic.

| Source unit | CLI remains | Core owns after move |
| --- | --- | --- |
| `CoverageRun.cs` | `CoverageRunCommand`, CLI exception mapper/diagnostics | `CoverageRunRequest`, `CoverageRunResult`, schedules/projects/process models, run workflow, process runner, merge abstraction/implementation, report-generator interface/locator interface, output/sandbox guards, all execution helpers |
| `CoverageMerge.cs` | `CoverageMergeCommand` | `CoverageMergeRequest`, `CoverageMergeResult`, merge workflow, source resolver, output guard, path safety, staging |
| `CoverageGate.cs` | `CoverageGateCommand`, flag validation, CLI diff-source construction, GitHub-summary appender and `ASCOV008` mapping | gate/patch request and result models, evaluator, patch parser, diff reader, repository-root resolver, report/artifact writer, output-path policy |
| `CoverageRunWatchdog.cs` | none | watchdog mode/configuration, text-writer sink, supervisor, operation, process lease, incident helpers |
| Remaining coverage support files | `CoverageCleanCommand` only | project manifest, artifact reader, driver strategy/preflight, output lease, slow-test diagnostics, coverage-only filesystem interop |

### Evidence producer path

Add an internal `CoverageEvidenceProducer` to `ForgeTrust.AppSurface.Evidence.Cli`. `EvidenceRunCommand` parses and resolves CLI inputs into one immutable `CoverageEvidenceRequest`; it contains every currently hard-coded Evidence coverage default, the selected producer declaration, solution path, controlled output directory, caller-owned `CoverageTextWriters`, deadline, and resolved diff snapshot. The producer receives only that request plus the extracted core composition service:

- repository/solution path and controlled producer output directory;
- the selected producer declaration and its required `EvidenceCoverageGateRequirements`;
- the same immutable diff snapshot used for the plan when the declaration requires patch thresholds; and
- the CLI output writer and producer deadline/cancellation token.

The producer maps the explicit request to `CoverageRunRequest` and `CoverageGateRequest`; it invents no defaults and owns no CLI option parsing. It maps results exactly:

- successful run and passing gate → `Passed` with the declaration's assertion IDs;
- run failure, merge/artifact failure, gate failure, or safe nonfatal core exception → `Failed` with no assertions;
- missing solution, missing gate requirements, or required patch gate without `--diff-file` → `Unavailable` or `Invalid` with the present stable, payload-free diagnostic intent;
- producer deadline expiry → `TimedOut` with no assertions;
- caller cancellation → propagate cancellation to the EvidenceHost lifecycle, which already emits the host-owned cancellation outcome.

The producer should not emit raw coverage log content into the evidence manifest. If a policy declares coverage artifacts, copy only those declared files through the provided `EvidenceArtifactWriter`; otherwise keep existing coverage artifacts inside the controlled producer output directory and expose only their safe relative names in command output.

`EvidenceRunCommand` becomes a command adapter: it asks `EvidenceCliWorkflow` for the plan, delegates coverage work to `CoverageEvidenceProducer`, and retains plan/manifest file writing plus CLI-specific summary output. It no longer references `CoverageRunWorkflow` or `CoverageGateEvaluator` directly.

### Immutable patch-diff snapshot

For `evidence run`, `EvidenceCliWorkflow.ResolveRunAsync` reads `--diff-file` once before planning, applies the existing byte limit and regular-file/path policy, and returns an internal `EvidencePlanningResolution(EvidencePlan Plan, EvidenceDiffSnapshot? DiffSnapshot)`. The `Evidence.Cli`-owned snapshot contains exact bytes, safe display name, byte count, and SHA-256. Planning derives normalized changed paths from that snapshot. Because the core cannot reference Evidence.Cli types, the producer passes the snapshot's primitive bytes, display name, length, and hash to the internal `PatchDiffSource.ForSnapshot(...)` factory in Evidence.Coverage; that factory serves the same bytes and never reopens the filesystem path.

The snapshot is retained only for the bounded command execution. File replacement, deletion, relative-path retargeting, or symlink retargeting after planning cannot alter the gate's measured input. Snapshot acquisition failures retain the existing Evidence CLI diagnostic family; a missing required snapshot makes the producer return `Unavailable` with no assertions. No evidence claim may pass after falling back to a second file read. `evidence explain` and `evidence doctor` may call the shared input resolver and discard their snapshot after planning because they never gate coverage.

### Diagnostic and composition seams

`Evidence.Coverage` owns an internal `CoverageExecutionDiagnostic` record with the exact rendered message, stable code when one exists, and optional exit code, plus `CoverageExecutionDiagnostics.Create(...)` to render the present problem/cause/fix/docs/log form. `CoverageExecutionException` carries that record. Every moved `CommandException` site becomes this core exception, including merge/output safety, gate parsing/evaluation, ReportGenerator resolution, and watchdog terminal failure. `CoverageCommandExceptionMapper`, owned by CLI, is the *only* code that creates `CommandException`; it preserves the existing message and the watchdog's exit code `124`. No moved code calls `CoverageRunDiagnostics` after extraction.

`Evidence.Coverage` also owns a transient internal `CoverageEvidenceExecutionWorkflow`. Its constructor receives the registered `CoverageRunWorkflow` and a new internal `CoverageGateWorkflow` that delegates to the existing evaluator/report writer. `RunAndGateAsync` accepts fully resolved run/gate requests plus `CoverageTextWriters`, invokes the run workflow once, stops on a failed run, invokes the gate workflow only after success, and returns a core result without Evidence contracts. `AppSurfaceCliApp` registers one singleton each of `ICoverageRunProcessRunner`, `IReportGeneratorPackageLocator`, and `ICoverageRunReportGenerator`; one transient each of `CoverageRunWorkflow`, `CoverageMergeWorkflow`, `CoverageGateWorkflow`, `CoverageEvidenceExecutionWorkflow`, and `CoverageEvidenceProducer`; and no coverage service in `Evidence.Aspire`.

Ordinary `coverage run` and `coverage merge` command adapters continue to call their named core workflows directly. `coverage gate` calls the core gate workflow then the CLI-only GitHub-summary adapter when selected. `evidence run` is the only command that calls `CoverageEvidenceProducer`, which calls the same registered `CoverageEvidenceExecutionWorkflow`; it does not construct a second process runner, report generator, run workflow, or gate evaluator.

### Migration order

1. Add `Evidence.Coverage` to the solution, project locks, package validation graph, and internal-friend declarations. Keep direct core behavior in the established first-party coverage regression suite. Do not change command behavior yet.
2. Move coverage execution types as a dependency-closed set. Replace `IConsole` with caller-owned `CoverageTextWriters` at the core boundary. Keep all existing requests, artifact names, diagnostics, stdout/stderr routing, and file layouts intact.
3. Change CLI composition in `AppSurfaceCliApp` and the four coverage commands to use the core. Register exactly one core composition service, one CLI-owned `ReportGeneratorPackageLocator`, one report-generator implementation, and one Evidence adapter. Retain command options, help text, command exception mapping, and ReportGenerator tool payload ownership. `Evidence.Aspire` receives no coverage-core registration.
4. Keep focused workflow, guard, watchdog, and manifest tests in the existing friend-visible coverage regression suite. Continue to assert exact public diagnostics through command-level tests.
5. Add `CoverageEvidenceProducer` and immutable-snapshot tests. Change `EvidenceRunCommand` to delegate to that producer and remove its direct CLI-coverage references.
6. Add packed-consumer tests that restore/build the CLI plus internal dependency graph and run the existing package coverage proof. Confirm the actual tool layout still locates ReportGenerator and produces the canonical merge/gate artifacts.
7. Update package, CLI, and Evidence documentation plus the append-only release entry. State explicitly that normal `coverage` commands remain compatible and that `Evidence.Coverage` is not a supported consumer API.

## Success Criteria

1. The CLI and Evidence producer execute the same extracted run/merge/gate implementation in-process.
2. The core has no `CliFx`, Evidence contract, Aspire, or consumer dependency; all intended API remains internal and the exact friend matrix is enforced.
3. `evidence run` contains no direct `CoverageRunWorkflow` injection or direct `CoverageGateEvaluator` call.
4. Every current coverage command retains its public contract, controlled artifacts, exit semantics, diagnostics, watchdog behavior, scheduling, and cleanup behavior.
5. A coverage declaration can close its assertions only after the extracted workflow succeeds and the existing gate passes.
6. Patch coverage uses the same immutable bounded diff snapshot consumed by Evidence planning; source mutation after planning and missing required diff input cannot create a passing claim.
7. Core, adapter, CLI regression, and packed-consumer tests cover success, failure, timeout, cancellation, safety, and compatibility branches without reflection.
8. Documentation and release notes make the private boundary and rollback path clear: removing Evidence adoption leaves ordinary coverage commands unchanged.

### Sections 1–10 review

1. **Architecture:** the inward project graph and exact friends prevent CLI, Aspire, and public contract leakage; keep the dependency graph in the design as the implementation contract.
2. **Errors:** the named core failure model closes the current `CommandException` coupling; preserve existing rendered messages and exit codes at CLI boundaries.
3. **Security:** the main new trust boundary is file input and manifest output; immutable diff bytes, bounded artifacts, and no raw logs address it without adding an authorization surface.
4. **Data flow:** the run-to-gate path has explicit missing, empty, failure, and success outcomes; the required snapshot tests cover post-plan replacement, deletion, and symlink retargeting.
5. **Quality:** a cohesive move is cleaner than facade duplication; the `CoverageTextWriters` pair is an explicit narrow seam rather than a new abstraction hierarchy.
6. **Tests:** every moved branch needs a core unit test, while public behavior stays covered by CLI regressions and package proof.
7. **Performance:** the design adds no second process, no repeated diff read, and no duplicated ReportGenerator discovery; this is the preferred performance posture.
8. **Observability:** keep stable diagnostics and controlled artifacts; do not add a dashboard or general telemetry system to this extraction.
9. **Deployment:** package validation and packed-consumer proof are the rollout gate; rollback is removing Evidence adoption while retaining unchanged CLI commands.
10. **Trajectory:** reversibility is 4/5 because the private core is internal, but extraction sequencing must not land a half-moved graph.
