# Design: Fail-Closed Structural Line Classifier Pilot

Generated by `/office-hours` on 2026-09-05

## Problem Statement

The [coverage gate](../../Cli/ForgeTrust.AppSurface.Cli/README.md) currently calculates patch coverage by joining a unified diff with Cobertura line evidence. It treats every changed line reported by Cobertura as a normal measurable coverage obligation. The original Skoolit failure showed that untouched `DbContext`-style structural accessors can appear as patch lines even when branch coverage is already complete.

Issue #781 asks whether AppSurface can identify a deliberately tiny category of non-behavioral C# source lines without creating a way to hide risk or improve coverage results. This is a research spike, not a coverage-policy change. It must prove the candidate rule mechanically with Roslyn semantic binding, demonstrate hostile failure cases, measure cost, and close with no arithmetic change if the evidence is weak.

## What Makes This Cool

The useful result is not a smarter exclusion switch. It is a classifier that has **no power** over CI: it can explain why a line is a candidate or why it is rejected, but cannot change a hit count, a denominator, a threshold, a report used today, or a pass/fail result.

A reviewer should be able to inspect one deterministic audit entry and answer all of these questions without trusting a text heuristic:

- Which changed Cobertura line was examined?
- Which exact source bytes and compiler context were used?
- Which property symbol, if any, did Roslyn bind?
- Which versioned rule accepted or rejected it?
- Why did uncertainty leave the existing coverage obligation intact?

The pilot does **not** claim that an auto-property is semantically inert. A public property can matter to serialization, reflection, ORM mapping, binary compatibility, and object state even when its accessors are compiler generated. The narrow question is whether a particular coverage-provider line attribution is uninformative enough to justify a later, separately reviewed policy; v0 only gathers evidence and has no authority to suppress that obligation.

## Constraints

- Preserve the current behavior of [`CoverageGateEvaluator.EvaluateAsync`](../../Cli/ForgeTrust.AppSurface.Cli/CoverageGate.cs) and the stable `coverage gate` command.
- Do not change raw Cobertura parsing, `PatchCoverageLine.IsMeasured`, line hits, branch conditions, patch metrics, thresholds, tolerance, existing patch-target artifacts, or command exit status.
- Do not add a CLI option, public API, MSBuildWorkspace integration, project discovery, coverage-collector configuration, or coverage exclusion mechanism.
- Add a direct `Microsoft.CodeAnalysis.CSharp` package reference to the CLI **test** project and reuse the existing central `5.0.0` pin in [`Directory.Packages.props`](../../Directory.Packages.props); update that test project's lock file from its current central-transitive entry. v0 must not add compiler assemblies to the packed CLI tool or rely on a transitive Roslyn dependency.
- Build compiler context only from explicit, test-owned source trees, metadata references, parse options, and source identities. Arbitrary checkout analysis is deferred.
- Do not add an EF-specific, `DbContext`-specific, generated-file-name, or handwritten exclusion catalog. The Skoolit-style accessor is a reviewed fixture, not a policy condition.

## Settled Premises

1. **Observational-only:** classifier test invocations must leave all existing coverage-gate metrics, reports, patch targets, and pass/fail decisions byte-for-byte identical to a no-classifier control run.
2. **Test-only v0:** the spike consists of test-owned classifier, policy, audit, and Roslyn-fixture types. It publishes no command, CLI-package type, package API, switch, project loader, or persisted audit artifact.
3. **Single eligible source shape:** the only possible acceptance is a source-declared, non-indexer C# auto-property with exactly declaration-only `get;` and `set;` or `init;` accessors, no property initializer, no accessor body, and no expression body.
4. **Source-to-symbol proof:** an accepted line must have an exact repository-relative source path, exact source fingerprint, one source-tree association, a declared fixture compilation with matching source tree and parse options, one declared `IPropertySymbol`, and one changed-line-to-property association.
5. **Fail closed:** source-missing, non-C# paths, unmeasured lines, generated or synthesized source, stale source identity, partial types, inherited or overridden members, indexers, attributes, unsupported modifiers, initializers, expression bodies, accessor bodies, diagnostics that affect binding, conditional-compilation divergence, ambiguous locations, and unexpected failures are rejections. They remain ordinary coverage obligations.
6. **Auditability:** every evaluated changed line produces a deterministic internal audit entry. A rejection is evidence, not an omission.
7. **Evidence gates policy:** a future versioned policy or user-visible audit surface is proposed only if the hostile corpus has no unsafe acceptance and the measured overhead stays within the agreed budget.

## Existing Seam

[`PatchCoverageEvaluator.AnalyzeAsync`](../../Cli/ForgeTrust.AppSurface.Cli/CoverageGate.cs) already constructs a deterministic [`PatchCoverageAnalysis`](../../Cli/ForgeTrust.AppSurface.Cli/CoverageGate.cs) from:

1. a bounded unified diff;
2. normalized repository-relative paths and changed lines; and
3. the merged Cobertura line map.

Its output is a sorted list of `PatchCoverageLine` records containing path, line number, raw measured state, hit state, and optional condition counts. The evaluator derives patch metrics from that list, while [`CoverageGateReportWriter`](../../Cli/ForgeTrust.AppSurface.Cli/CoverageGate.cs) renders existing coverage and patch-target artifacts.

The test harness first obtains a completed `PatchCoverageAnalysis` through the existing evaluator, then passes its immutable lines to the test-only classifier alongside an explicit Roslyn compilation. The production evaluator and `CoverageGateCommand.ExecuteAsync` never invoke the classifier, and the classifier neither calls back into metric calculation nor changes `CoverageGateReportWriter`.

## Recommended Approach: In-Memory Sidecar over Actual Patch Evidence

### Components

| Component | Responsibility | Explicit non-responsibility |
| --- | --- | --- |
| `StructuralLineClassificationPolicy` | Test-owned policy identifier `appsurface.structural-line`, version `v0`, and eligibility constraints. | It does not configure Coverlet, change thresholds, or select source projects. |
| `StructuralLineClassifier` | Test-only evaluator over immutable patch-line evidence, a supplied fixture compilation, and a source manifest. It converts internal faults into rejection entries. | It does not run from production coverage-gate execution, load `.csproj` files, call MSBuild, read a checkout, or alter `PatchCoverageLine`. |
| `StructuralSourceManifest` | Maps a normalized source path to exact source bytes, SHA-256 fingerprint, explicit UTF-8 decoding contract, parse options, generated/authored provenance, and one syntax tree. Fixtures construct `SourceText` from those same bytes and decoder, so source identity cannot silently normalize different encodings. It normalizes separators to `/` and compares paths with `StringComparer.Ordinal` on every platform. | It does not infer generated status from a filename or accept an unmapped tree. |
| `StructuralLineClassificationAudit` | Holds sorted, immutable per-line audit entries for test inspection and deterministic serialization assertions. | It is not a CLI artifact, production result, or public contract in v0. |
| `TestCompilationFixture` | Creates explicit C# compilations, controlled metadata references, documents, conditional symbols, and changed-line/Cobertura fixtures. | It is not a production project loader. |

### Candidate Evaluation

For every line in `PatchCoverageAnalysis.Lines`, the classifier creates exactly one audit entry. It evaluates in this order:

1. First reject a path whose normalized extension is not `.cs` as `not-csharp`. Then reject `PatchCoverageLine.IsMeasured == false` as `not-measured`. That precedence is stable when both conditions apply.
2. Resolve the normalized path to exactly one authored source-manifest document. Reject missing, duplicate, generated, synthesized, stale, or fingerprint-mismatched source.
3. Verify that the manifest's source tree and parse options are the exact tree and options present in the supplied compilation. Reject any conditional-symbol divergence.
4. Convert the one-based changed line to the matching zero-based `SourceText.Lines` entry. First locate a single `PropertyDeclarationSyntax` whose `Span` overlaps that line, never `FullSpan`. Then require the line to overlap at least one of that property's descendant tokens **other than** its accessor-list opening or closing brace. This preserves an accepted same-line `set; }` because it contains the semicolon token, but rejects a line containing only a declaration brace. Documentation comments, leading/trailing trivia, blank lines, and brace-only lines cannot qualify. Reject zero or multiple declarations as `location-unmatched` or `location-ambiguous`.
5. Bind the single declaration through its semantic model. Reject a null or error symbol, inherited or overridden member, virtual/abstract/explicit-interface member, interface member, record positional property, partial property/type, or property whose type is `IErrorTypeSymbol`. Reject as `semantic-diagnostic` only when `semanticModel.GetDiagnostics(property.Span)` contains `DiagnosticSeverity.Error`; unrelated warnings and errors outside the property span do not disqualify it.
6. Accept only a non-indexer property with no attributes or initializer; no expression body; a property modifier list limited to declared accessibility; and exactly two semicolon-only accessors, `get` plus `set` or `init`, where both accessors have zero modifiers. Reject get-only properties, accessor accessibility modifiers, `required`, `static`, `virtual`, `abstract`, `override`, `sealed`, `new`, `unsafe`, `extern`, partial, accessor bodies, or unexpected syntax.
7. Emit an accepted entry only after all checks succeed. Any exception becomes a stable `analysis-fault` rejection entry with sanitized diagnostic metadata.

The rule is deliberately stricter than C# needs to be. v0 is proving that a category can be safe, not maximizing how many lines it recognizes.

### Audit Contract

Each internal audit entry contains:

- policy identifier and version;
- normalized path and one-based changed line;
- raw Cobertura evidence: measured state, line-hit state, and condition counts;
- source fingerprint and authored/generated provenance;
- parse-option identity, including defined conditional symbols;
- symbol identity using `IPropertySymbol.GetDocumentationCommentId()` plus `SymbolDisplayFormat.FullyQualifiedFormat` when binding succeeds; the single declaring syntax reference and syntax-tree identity are also recorded;
- disposition: `accepted` or `rejected`;
- exactly one stable reason code, `structural-auto-property` for an acceptance; and
- sanitized supporting metadata needed to reproduce the decision.

Entries sort by path, line, and reason code with ordinal comparison. Tests serialize the in-memory model deterministically, but v0 does not create `coverage-structural-audit.json`, add report-writer behavior, or expose a command option. The future policy decision can use this model as evidence without prematurely publishing an artifact contract.

### Stable Rejection Reasons

The initial reason-code vocabulary is `structural-auto-property` for the sole accepted shape, plus `not-csharp`, `not-measured`, `source-missing`, `source-ambiguous`, `source-generated`, `source-fingerprint-mismatch`, `compilation-mismatch`, `conditional-compilation-mismatch`, `location-unmatched`, `location-ambiguous`, `property-unbound`, `property-inherited-or-overridden`, `partial-type`, `unsupported-property-shape`, `property-initializer`, `property-attributes`, `property-modifiers`, `accessor-modifiers`, `accessor-body`, `accessor-expression-body`, `semantic-diagnostic`, and `analysis-fault`.

Reason codes are intentionally more stable than message text. Messages may improve for diagnostics; tests and any later policy must rely on the code.

## Fixture Matrix

| Fixture | Expected disposition | What it proves |
| --- | --- | --- |
| Plain `get; set;` auto-property, one line | Accepted | Basic positive case and same-line declaration/accessor mapping. |
| Plain multi-line `get; init;` auto-property | Accepted | `init` support and multi-line source mapping. |
| A diff touching a token-bearing property header, accessor, or same-line closing brace | Accepted | The line overlaps both the property's `Span` and a non-brace descendant token; a same-line closing brace is accepted only when it shares a line with an eligible token such as `set;`. |
| A diff touching only leading/trailing trivia, a documentation comment, blank line, or standalone closing brace | Rejected as `location-unmatched` | Trivia and non-declaration lines cannot borrow nearby property semantics. |
| Skoolit-style context with a locally declared `DbSet<T>` fixture | Accepted only because of the language shape | The original accessor scenario is reproduced without an ORM-specific rule. |
| Getter/setter body, expression body, invocation, assignment, or throwing accessor | Rejected | Executable behavior is never called structural. |
| Get-only auto-property, property initializer, indexer, record positional property, interface property, C# partial property, `required`, static, virtual, abstract, override, explicit-interface member, or attributes | Rejected | Nearby-looking modern C# constructs cannot widen v0 accidentally. |
| Accessor accessibility modifier such as `private set;` or `protected init;` | Rejected as `accessor-modifiers` | v0 accepts only unmodified declaration-only accessors. |
| Property inherited from a base type | Rejected | A line must bind to a declaration in the current authored source evidence. |
| Type declared across multiple source trees | Rejected | Partial types cannot receive a partial proof. |
| Missing path, duplicate normalized path, stale fingerprint, non-C# path, or a changed line outside the declaration | Rejected | Path and line correspondence are evidence, not assumptions. |
| Manifest-marked generated or synthesized tree | Rejected | Generated source never becomes a quiet exclusion path. |
| Parse options or preprocessor symbols differing from the supplied compilation | Rejected | Conditional builds cannot silently bind a different program. |
| One-based line `0`, a line past EOF, or a line that overlaps two candidate declarations | Rejected as `location-unmatched` or `location-ambiguous` | Invalid and ambiguous coordinate conversion has no fallback guess. |
| Invalid source or error symbol | Rejected | Binding failures fail closed. |
| Exception injected by an internal test seam | Rejected as `analysis-fault` | The sidecar never destabilizes the gate. |

## Anti-Gaming Proofs

The pilot must establish these invariants with the same Cobertura and diff fixtures before and after classification:

1. `CoverageGateResult`, all line and branch metrics, threshold decisions, exit behavior, and the existing report/patch-target content are unchanged.
2. The classifier never mutates `PatchCoverageLine`, the Cobertura map, or a diff source.
3. A missing Cobertura line is audited as `not-measured`; it cannot become an accepted structural line.
4. Adding a redundant accessor test may change raw Coverlet hit data, as any test legitimately can, but invoking the classifier cannot produce a different raw or patch metric from the same inputs.
5. No Coverlet exclude, `SkipAutoProps`, source-filter, or threshold setting is added, read, or depended on by the classifier. Existing collector-level exclusions remain outside this pilot and must be documented as such.

## Performance Measurement

Measure two different costs so a fast classifier does not hide expensive compilation creation:

1. **Classification-only cost:** reuse an already-created explicit compilation and manifest, then classify a corpus of at least 200 changed-line candidates across the required fixture shapes. Automated tests assert an allocation bound of no more than 1 MiB per warmed corpus run. A dedicated non-gating benchmark records warm median, p95, min, and max for the classifier itself. This is a test-only observation, not an incremental coverage-gate baseline or a production performance threshold.
2. **Compilation-construction cost:** measure explicit fixture-compilation creation separately and report it without folding it into classifier throughput. It is research-harness cost, not evidence that arbitrary project loading is acceptable.

Run sufficient warmed iterations to report median, p95, min, max, and allocation measurements. Record the host, runtime, Roslyn version, corpus size, raw timings, and allocation measurement method in [`issue-781-structural-line-classifier-results.md`](issue-781-structural-line-classifier-results.md). The automated allocation check uses an isolated warmed measurement window so setup allocations are not mistaken for classification allocations. Any allocation-budget failure or unstable benchmark result blocks a policy proposal; a future proposal must define a representative-workload timing budget separately.

## Approaches Considered

- **Test-only semantic harness:** rejected because it proves a C# predicate but not that the real Cobertura-plus-diff evidence model reaches the classifier correctly.
- **Shadow audit artifact:** rejected because it begins a user-visible reporting contract before the classifier meets its safety and performance gates.

## Success Criteria

The pilot is successful only if all conditions hold:

1. The full fixture matrix passes with no unsafe acceptance and every rejection has the expected stable reason code.
2. The positive cases bind to the expected property symbol, record exact source provenance, and use `structural-auto-property` as their stable reason code.
3. All anti-gaming parity checks prove unchanged raw metrics, patch metrics, pass/fail outcomes, and existing report content.
4. Conditional-compilation, source-identity, partial-type, generated-source, inheritance, side-effect, and binding-failure tests reject deterministically.
5. The warmed classifier stays within the 1 MiB allocation budget and produces stable observations; any future policy proposal defines a representative-workload timing budget separately.
6. The Skoolit-style accessor fixture is reviewed as evidence of a language-level rule, not as an ORM exception.
7. The evidence corpus includes the existing Cobertura provider path plus explicit C# parse-option, nullable, generated-source, and conditional-compilation profiles; it cannot infer general language support from one default fixture.
8. The final spike report recommends exactly one outcome: propose a separately reviewed policy/audit design, collect more evidence, or close #781 without changing coverage arithmetic.

#### Sections 1–10

**1. Architecture.** The architecture is intentionally a sidecar, not a new production dependency:

```text
Cobertura + unified diff
         │
         v
PatchCoverageEvaluator.AnalyzeAsync ──> PatchCoverageAnalysis ──> existing metrics/reports/exit
         │                                         ▲
         │ test fixture only                       │ immutable, never mutated
         v                                         │
explicit source bytes ──> SourceText/SyntaxTree ──> StructuralLineClassifier ──> audit assertions
                               │                              │
                               └── compilation + symbols ──────┘
```

Happy path emits an accepted audit record only after every proof check. Missing path, empty/invalid coordinate, and ambiguous source emit a rejection record. A classifier fault emits `analysis-fault` and cannot affect the already-produced gate result because production code never invokes it. There is no persistent state machine, endpoint, database, background worker, user data, or deploy-time integration. The only coupling is the test project’s existing friend access to the immutable production record, which is justified and reversible by removing the test-only folder.

**2. Error & Rescue Map.** The following registry is complete for the proposed classifier code paths.

| Code path | What can go wrong | Class / condition | Rescue action | Consumer sees |
| --- | --- | --- | --- | --- |
| Manifest lookup | Missing, duplicate, generated, stale source | provenance mismatch | Stable rejection reason; no fallback search | Deterministic audit entry |
| Source line conversion | Line `0`, past EOF, no non-brace token, multiple properties | coordinate mismatch | `location-unmatched` or `location-ambiguous` | Deterministic audit entry |
| Semantic binding | Null/error symbol, diagnostic, unsupported property | semantic mismatch | Specific rejection reason | Deterministic audit entry |
| Classifier implementation | Unexpected parser/manifest exception | internal analysis fault | Catch only at the sidecar boundary, sanitize metadata, emit `analysis-fault` | Deterministic audit entry; gate unaffected |
| Benchmark harness | Allocation/time threshold misses or unstable timings | evidence failure | Mark policy proposal blocked; do not loosen target | Results note recommends collect/close |

The catch-all is acceptable only at the test-side classifier boundary because it converts a non-authoritative test analysis failure into an explicit rejection. It must not be copied into `CoverageGateEvaluator`.

**3. Security and threat model.** The pilot adds no remote input, authorization path, secret, endpoint, shell command, persistence, or production package flow. Its risks are provenance confusion and dependency drift: the manifest prevents path/fingerprint/tree substitution, the test lock file constrains Roslyn restore, and the packed-tool proof guards distribution. Audit metadata stays in-memory and sanitized, so a source path or exception detail never becomes a new report artifact. Risk is low only while that boundary remains intact.

**4. Data-flow edge cases.** `PatchCoverageAnalysis.Lines` can be empty, unmeasured, non-C#, or ordered across files. Each line must still produce one ordered audit result, with no grouping or skipped entry. ### Phase 3 — Engineering Review (FULL_REVIEW)

#### Scope Challenge and Existing-Code Verification

`CoverageGateEvaluator.EvaluateAsync` creates a `PatchCoverageAnalysis` only for existing patch coverage and derives pass/fail entirely from its metrics. `PatchCoverageEvaluator.AnalyzeAsync` already creates the sorted `PatchCoverageLine` list from a unified diff and Cobertura map, and `CoverageGateReportWriter` consumes that same analysis for current artifacts. The test project already has friend access, while `Microsoft.CodeAnalysis.CSharp` is centrally pinned but not direct in that test project. The plan correctly reuses these seams and must not touch the evaluator, report writer, CLI project, or command parser.
