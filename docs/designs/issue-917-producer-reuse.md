## Problem and payoff

Local Evidence runs repeat coverage and browser producers after commits, upstream merges and worktree switches even when the consumed inputs are identical. The issue reports redundant CPU, disk and disposable-resource startup; this session did not measure their cost. Doing nothing preserves correct fresh execution but leaves that repeated cost in place.

With explicit opt-in, a producer runs once for its declared computation. Another worktree restores verified results, displays their origin, and avoids starting resources used only by restored producers. A changed file invalidates only the producers that include it. This extends the existing [EvidenceHost](appsurface-evidencehost-contract-first.md), [local coverage storage](coverage-artifact-storage.md), and [runtime reporting proposal](https://github.com/forge-trust/AppSurface/issues/909); it supersedes none of them.

## Selected approach and boundaries

The user selected A: cache complete validated producer results and their outputs. Patch coverage receipts include the exact captured diff digest, so a changed patch or gate threshold reruns coverage. The alternative, separately caching coverage collection and evaluating gates afresh, was declined because it adds a collection contract and more lifecycle states. It is outside this delivery.

Reuse is off by default and requires both producer `Inputs` and invocation `--reuse` or equivalent host options. It remains local to one user and repository, with no network or telemetry. Preserve the existing executable and packages; add no daemon, service, mandatory tool, public coverage engine or public `EvidenceCliWorkflow`. The plain CLI does not begin provisioning consumer-owned resource topologies. No automatic build-graph inference, test-level selection, remote cache, protected-CI reuse, or reuse of Failed/Flaky/Unavailable outcomes is added.

The issue's automatic merge-base selection is explicitly deferred: current commands consume explicit paths or a diff file. Existing captured-diff behavior remains authoritative. Committing, amending or merging unrelated files must not invalidate a producer through a commit, index or plan digest.

## Accepted premises

1. A run containing reuse can be locally complete but is informational, never PR- or release-gate eligible.
2. Input completeness is an explicit producer-owner promise, including configuration, tools and fixtures; it is not proven by a sandbox.
3. Decide reuse before resource startup and start only the transitive prerequisites of producers that execute.
4. Restore producer evidence, then evaluate the current plan; never replay a previous manifest claim.
5. Share reuse semantics between CLI and host inside existing packages, with a separate receipt namespace and shared native filesystem primitives.
6. Preserve reuse provenance and exclude restored durations from fresh runtime baseline samples.

## Contract and compatibility

Add non-positional, init-only `EvidenceProducerDeclaration.Inputs`, nullable and omitted when absent. Its typed record contains `Include` and `Exclude` lists. Reuse the [planner's existing path-pattern grammar](../../Evidence/ForgeTrust.AppSurface.Evidence.Planner/README.md): repository-relative forward-slash paths, `*` within a segment and `**` across segments. Reject absolute paths, traversal, malformed patterns, empty includes and an empty final file set. Static grammar validation belongs to planning; filesystem match validation belongs to preparation, leaving deterministic planning independent of the checkout. Missing `Inputs` is ordinary ineligibility, not an error.

Append `EvidenceProducerOutcome.Reused`, `EvidenceResourceOutcome.NotRequiredForExecution`, and `EvidenceClaimKind.LocalReusedComplete` without renumbering existing enum values. Add optional init-only result provenance (`ProducerKey`, `OriginManifestDigest`, `OriginCompletedAt`) and a manifest reuse count. Preserve positional constructors. The host overwrites producer-supplied reuse/provenance metadata with framework-owned values; producer callbacks cannot return Reused as a fresh outcome. Counts are derived and validated against the actual result list.

Use contract version 1.1 for plans containing Inputs and manifests using the new reuse data. Continue reading and emitting 1.0 for legacy policies and ordinary runs that use no additions. Keep current property naming, canonical ordering and digest rules. Omit absent additions so unchanged legacy inputs preserve canonical bytes and digests. Explicitly version schemas, readers, validators and verifier admission; unsupported versions fail closed. Old readers must reject new claim/outcome strings instead of treating them as Passed. Compatibility tests bind these claims to exact emitted bytes and old-constructor consumers.

An optional `IEvidenceProducerKeyMaterial.GetKeyMaterialAsync(context, cancellationToken)` supplies additional execution identity before resources exist. Its context exposes the frozen plan/declaration and clock, with no artifact writer or ready-resource access. Document that it must be local, side-effect-free and cancellation-aware. The host owns the actual callback task. Its wait deadline is the declared producer timeout capped at 30 seconds; expiry requests cancellation, then uses the existing ProducerCleanupTimeout grace period to join it. A nonfatal failure, invalid material or timeout permits ineligible/fresh fallback only after the task actually settles. If it remains active, preparation is Unavailable and the invocation is incomplete: invoke no resource factory or fresh producer, publish nothing, and retain callback/registration ownership until actual settlement. Never describe a bounded wait as forcibly terminating in-process code. Observe eventual faults under the existing fatal-exception policy; a late task cannot supply a key or authorize execution. Invocation cancellation follows the same ownership rule and remains cancellation. Bound material to 64 unique ordinal keys of at most 128 characters, 4 KiB per value and 256 KiB total. Persist component hashes, never raw environment values or rendered commands.

All public and internal additions require reference, decision and pitfall documentation, including defaults, ownership, failure results and ordering. Proposed API names may be refined during engineering planning without changing the behavior approved here.

## Input identity

Within a repository namespace, hash a versioned canonical envelope containing the full normalized producer declaration; transitive required-resource declarations and effective fixture/image identities; effective adapter/tool versions and execution arguments; OS/architecture; producer key material; and sorted `(relative path, relevant file mode, SHA-256 of on-disk bytes)` entries. Include `EvidenceDiffSnapshot.Sha256` for a patch gate, never `Plan.DiffDigest`, which hashes changed paths. A patch producer without its exact captured diff cannot reuse; preserve existing missing/oversized diff diagnostics rather than silently dropping patch requirements.

Enumerate tracked paths as they exist on disk, including modified tracked files, plus nonignored untracked files. Deletions, additions, renames and mode changes alter the inventory. Preserve actual path identity, including meaningful whitespace; do not apply a trimming normalizer to filesystem names. Refuse ambiguous normalized/case-colliding paths. Stream hashes with cancellation and finite preparation limits; default to at most 100,000 files, 16 MiB of inventory metadata and 60 seconds of enumeration/hashing per producer. Exceeding these optional-optimization limits is reported as ineligible and executes fresh, never a partially hashed hit. Shared in-memory hashing may avoid rereading the same file without using timestamps as proof of unchanged bytes.

Symlinks, linked ancestors within the selected input subtree, submodules and nonregular selected files are ineligible in v1; never follow them outside the declared boundary. Ignored files, generated outputs, mutable package feeds, external services, clocks, randomness and host-installed tools are not magically covered by file globs. Producers must identify all influential non-file state or remain nonreusable. A producer that reads plan fields such as ChangedPaths must include that dependency in key material; patch coverage is not the only possible custom diff-dependent producer. Ephemeral resource ports and timestamps are not fixture identity. Include the resolved solution/configuration and actual tool versions for built-in coverage; require explicit source/build/lock/fixture file declarations like other producers.

Partition storage by a verified local Git common-directory identity so linked worktrees share receipts while unrelated repositories and independent clones do not accidentally share authority. The producer content key itself excludes checkout paths and Git history. Independent-clone sharing is not promised. Resource configuration and custom implementation identity must be available without starting either; unavailable identity makes reuse ineligible.

## Preparation, execution and resources

Place one private reuse coordinator in the existing Evidence support assembly, consumed by the CLI and Aspire adapters. Contracts owns records and structural validation; Planner owns declaration grammar; support code owns enumeration, keys, store and leases; adapters own effective execution settings and artifact inventories. Share lower-level native operations with the coverage store rather than copying its implementation or using its archive schema as a receipt database.

Add a prepared-run host entry alongside the existing [host lifecycle](../../Evidence/ForgeTrust.AppSurface.Evidence.Aspire/README.md). It registers side-effect-free producer and resource-identity descriptors, validates the plan and envelope, resolves receipts, and returns an owned single-use preparation lease with decisions and RequiredResourceIds. Execution accepts an explicit consumer resource factory for that required set. The factory composes only those resources and returns owned readiness registrations; the framework invokes it only after preparation, and not at all for an empty set. The example must conditionally compose Aspire resources before Build/Start. Filtering readiness after starting an existing application does not meet acceptance.

Existing eager Create/StartAsync callers retain their current behavior without reuse. They must adopt the prepared entry to request selective startup; reject reuse on an eager topology before producer execution with a clear migration diagnostic. The framework cannot undo side effects a consumer performs before calling it and makes no sandbox claim. Validate descriptor closure and producer registrations even on an all-hit run, but require runtime readiness registrations only for the active resource closure. Resource identities may be registered without starting them.

The lifecycle is: validate admission; snapshot declarations and inputs; coordinate receipt decisions; restore and validate hits into a fresh per-run output root; compute the active resource closure; invoke the resource factory; await readiness; execute misses; validate assertions and artifacts; rehash inputs; join execution and owned cleanup; build the current manifest; publish eligible receipts. Restore failure becomes a miss before deciding resource closure, so its resources are included. Revalidate inputs after any lock wait and before using a hit. Detected changes invalidate preparation; release affected leases and reprepare once, then return an incomplete diagnostic if the source keeps changing. This bounds retries without claiming a filesystem snapshot.

For mixed runs, a resource readiness failure affects its dependent fresh producers; verified reused results remain reported as Reused, while the invocation is incomplete. Resources outside the active closure receive NotRequiredForExecution with no readiness measurement. A resource needed by any fresh producer still starts and must pass ordinary readiness. Preserve cancellation, fatal-error propagation, deadlines and cleanup semantics.

## Receipt custody, concurrency and storage

Use the platform's user-local application-data directory under `ForgeTrust/AppSurface/evidence-receipts/v1`, a sibling of the [coverage store](../../guides/coverage-storage.md). `--receipt-store` overrides `APPSURFACE_EVIDENCE_RECEIPT_STORE`, which overrides the default; a host explicit setting has the same precedence. Overrides create separate coordination/budget domains and must be safe local owned directories outside source inputs and current artifact outputs. No migration or deletion of unrelated data is allowed.

Defaults are 2 GiB of retained receipt data and seven days since original completion. Count metadata, artifact bytes and reserved staging against the quota; reads never extend the original maximum age. Track successful use for LRU ordering among eligible unleased receipts, with key order as tie-breaker. Maintain only marked supported entries with short quota/index locks; never hold a global store lock across producer execution. Busy or foreign/unknown-version entries are preserved and reported. A full quota suppresses publication; it does not turn a fresh pass into failure or remove active evidence.

Acquire cancellable native per-key leases, recheck after acquiring, and keep execution ownership through actual task settlement and publication or abandonment. Acquire multiple keys in canonical order to prevent lock cycles. Default receipt-wait budget is 30 minutes, configurable to a finite positive duration; timeout is Unavailable, never duplicate execution beside a possible live holder. Failed/cancelled holders publish nothing; the next owner may execute fresh after proved settlement and release. Never steal a lock based on PID or age. If an in-process producer ignores cancellation, preserve its execution lease with the still-running task until it settles; host return alone cannot release that protection.

Before any admitted resource factory or producer can start, flush an owned per-key InFlight record with a unique execution ID while holding the lease. Clear it only after the actual producer task and all producer-owned children/resources are confirmed settled; a timeout or unsuccessful cleanup cannot clear it. A normal failed producer with confirmed cleanup may clear it and allow the next owner to run. Publish a receipt only after this settlement condition. The InFlight record survives process death even when its native lock is released. An unlocked InFlight record is therefore abandoned/unknown, not proof that work stopped: the next owner reports Unavailable and neither starts resources nor executes that key. Maintenance never deletes this record by age.

V1 chooses conservative recovery rather than claiming a universal process-tree supervisor. Automatic recovery in the same namespace requires a supported adapter's execution-ID-bound settlement proof covering its children; absent that proof, the key remains Unavailable. The documented operator recovery is to stop the affected EvidenceHost and its producer execution environment, verify that its processes/containers have stopped, and explicitly choose a fresh owned receipt store. Preserve the old marker for inspection; do not offer PID-only reset or silent marker deletion. This is a deliberate change of coordination domain, not automatic recovery of an unknown execution. Native interruption tests on Windows, Linux and macOS must kill a holder while a controlled child remains alive and show that a contender refuses execution; prove safe normal completion and the documented stopped-environment/fresh-domain recovery separately. No deduplication-after-crash claim is made without that proof. Deduplication otherwise applies to cooperating runs sharing the same supported store and key, not runs explicitly disabling reuse or using another store.

Receipt reads hold a lease through verification/copy. Verify the version, key envelope, Passed origin result, required assertions, artifact inventory, sizes, digests and origin-manifest binding. Keep the canonical origin manifest so its digest and producer association can be checked, without implying attestation. Only fully successful, settled, cleaned invocations publish receipts in v1; a producer pass in a failed/incomplete invocation is not admitted. New Reused results do not create another receipt or reset origin time.

Restore via the existing bounded artifact writer into exclusive per-invocation directories and validate the resulting custody metadata. A retained coverage receipt also needs an explicit versioned inventory of the managed reports required by current gates/readers, including requested retained outputs; today's built-in pass/fail result contains no such inventory. Define that adapter inventory and its declared slots without silently adding requirements to legacy policies. Preserve original artifact bytes and provenance, and make report paths available under the current run's established output layout. Do not guess which arbitrary output directories are safe to cache.

Stage publication in an owned sibling, verify copied bytes, flush and atomically rename. Rehash the full input inventory and key material after execution and before publication; changed/added/deleted inputs suppress publication. Never publish on an unsettled timeout, cancellation, cleanup failure or artifact/assertion invalidity. Pre/post equality detects observed changes, not a file changed and restored between observations; this remains declared local compatibility, not isolated execution.

Missing, expired, truncated or tampered owned receipts are misses; invalidate/remove only the confirmed owned bad entry under its lease and execute fresh. Unsupported receipt versions are preserved and ignored. Output custody failure is not a hit. If trustworthy key coordination cannot be acquired, report Unavailable rather than bypassing a potentially live owner; storage publication/maintenance failures after safe execution are secondary diagnostics. Document retry without reuse as an explicit user choice.

## Claims, audit and presentation

Validate Reused provenance and custody before it can satisfy a local obligation. A targeted run with at least one Reused result, all obligations locally satisfied, required active resources Ready and successful cleanup emits Passed / LocalReusedComplete / Informational. Skipped resource states are valid only outside the recomputed active closure. Missing or forged structural provenance makes the result Invalid. Failed or missing fresh work still prevents completeness. Existing fresh-only claims and their eligibility remain unchanged. Reject --reuse for release-scope profiles before callbacks/resources; protected CI recipes remain fresh and verifier admission explicitly rejects reused manifests.

Expose `appsurface evidence explain --reuse`, `run --reuse`, `run --reuse --verify-reuse`, and the store override on the existing tool. Add --solution to evidence explain, with exactly the same path resolution as evidence run; existing explain without reuse stays valid without it. For reuse-aware built-in coverage, callers supply the same --policy, --solution and --path/--diff-file inputs to explain and run. Configuration, parallelism and retention come from the selected producer declaration's existing CoverageExecution/CoverageArtifactRetention fields, not a new implicit environment or invented --configuration flag. One shared effective-execution resolver feeds the same key preparation logic for both commands. Missing --solution in reuse-aware coverage explain yields ineligible/solution_required, never a guessed hit; run preserves its existing missing-solution diagnostic. Test explain/run key equality for explicit/default declaration settings and mismatches when the solution or configuration changes.

Explain is read-only: no store creation, locks for producer execution, LRU writes, resources, tests or restoration. Report verified candidate hit, miss or ineligible with fixed reasons; run revalidates. Custom producers whose registration/key material is unavailable to plain CLI explain are ineligible there, with a pointer to the consumer host preparation summary. Against a recent compatible producer receipt, compare bounded component hashes and name the first differing path; otherwise say configuration/toolchain/diff changed or no comparable receipt. Never print environment values.

Run prints each reused producer, original completion age and current restoration time. Keep origin elapsed time as historical provenance; current metrics measure actual preparation, lock wait and restoration. Never emit reused producer/project/method durations as fresh #909 samples. Record unused resources without manufactured zero-duration readiness observations. Mixed invocations may report real fresh timings, but restored rows cannot enter runtime baselines.

Verify-reuse requires --reuse and executes every candidate hit freshly under the same coordination and ordinary lifecycle. Compare terminal outcome and the exact satisfied assertion set after normal validation; artifact digests are still checked for custody, but logs/timings and nondeterministic diagnostic bytes are not semantic equality. This audits the issue's declared outcome guarantee, not full behavioral equivalence. Any mismatch fails the audit, invalidates the affected receipt and suppresses publication for that producer in this invocation even if the fresh outcome Passed. Recovery requires a later explicit audit invocation with a successful fresh run; do not immediately replace the mismatching receipt and call the audit successful. Non-hits execute normally. Audit failure prevents history admission and a complete claim.
