## S1. Purpose and scope

Some changed paths have no production code to cover: workflows, scripts, release tooling. The truthful evidence for them is that the tests a policy selects all ran and passed. Today the only built-in producer that runs tests is `coverage`, which always makes a coverage claim and cannot be narrowed by a policy.

This delivery adds a built-in producer kind `test` to the `appsurface evidence` CLI, in one pull request based on `origin/main`, labeled preview [uc1a, amendment 1].

**The claim.** `appsurface/test/discovery-complete@1` means selection completeness: every test the declared projects and filters selected ran and passed [V2]. It does not show that those tests exercise the changed files, and it is never a coverage claim.

**Preview.** The kind `test`, the assertion id and receipt schema version 1 may change without a compatibility step until a real route has closed with them in this repository or at a named adopter [V7].

**In this delivery**

- Contracts and planner: the `test` block and its validation (S3, S4).
- A pure reconciler and a `dotnet` CLI test-run source (S5, S6).
- The producer (S7 to S10).
- CLI `run` dispatch, artifact writing, output and `explain` (S11).
- CLI `verify --artifact-root` and one shared artifact check (S12).
- Documentation (S14) and tests (S15).

**Not in this delivery** (each tracked in [TODOS.md](../../TODOS.md) unless noted)

- A route in this repository's own policy, with its validation-tool, CI and Windows-skip changes [D15].
- A registration surface or documentation for outside Aspire hosts [D1]. Only CLI `run` dispatches the producer [C11].
- A `test` producer in `init --sample` and per-project `doctor` checks [V5, which withdrew E2, E3, C5, C8, C13, C14, C17, C19 and the doctor parts of C12 and C16].
- A typed VSTest source, and Microsoft.Testing.Platform execution [D7, V6].

- Flaky retry and the `Flaky` outcome; test impact analysis; any coverage measurement (issue non-goals).
- A producer-id rule for kinds other than `test`; #930; renumbering PR 922 (that pull request absorbs it).

## S2. Constraints

1. A policy without a `test` block keeps byte-identical canonical JSON, `PolicyDigest` and `PlanDigest` before and after this change.
2. VSTest only. No new package dependency.
3. Contract version stays `1.0` [uc2a]. Mixed-version behavior and the upgrade order are in S13.
4. **Privacy.** Discovered test names and result test names never enter the manifest, the receipt, `Diagnostic`, `evidence-summary.json`, the GitHub step summary, the artifact root, the diagnostics directory or the producer's console output. Filter text is public plan data: it appears in the policy, the plan, `explain`, the summary and the rerun hint. The receipt's filter hash binds the receipt to the plan; it is not confidentiality [C3].
5. Kind `test` producers run sequentially. The producer writes build output into the working tree and must not run beside another build of the same project [ENG-16].
6. `run` builds and executes repository code with the caller's environment [ENG-13].

## S3. Declaration

`EvidenceProducerDeclaration` gains an optional init-only property `Test`, omitted from JSON when null. Inside it, `filter` and `minimumTests` are also omitted when null.

```json
{
  "id": "release-tooling-tests",
  "kind": "test",
  "version": "1.0.0",
  "requiredResources": [],
  "assertionIds": ["appsurface/test/discovery-complete@1"],
  "artifactSlots": [
    { "logicalName": "test-receipt", "relativeRoot": "test", "mediaType": "application/json", "required": true, "maximumBytes": 65536 }
  ],
  "timeoutSeconds": 900,
  "test": {
    "projects": [
      { "path": "tests/Tooling.Tests/Tooling.Tests.csproj", "filter": "FullyQualifiedName~ReleaseWorkflowPolicyTests", "minimumTests": 10 }
    ]
  }
}
```

| Field | Rule |
|---|---|
| `test.projects` | 1 to 32 entries |
| `path` | repository-relative, forward slashes, the planner's existing path grammar, at most 512 characters, ends in `.csproj`, `.fsproj` or `.vbproj`; no absolute path, no traversal, no segment starting with `-`, no `:`, no control character; unique within the producer, compared without regard to case |
| `filter` | optional VSTest filter expression; not blank; at most 1024 characters; no control character or line break; passed to the child process as one argument, never through a shell |
| `minimumTests` | optional integer, 1 or greater; default 1 |

The whole declaration feeds `PolicyDigest` and `PlanDigest` through the existing canonical serialization, so changing a project, filter or minimum changes both with no digest code added.

The probe showed that `,` `;` `%` `!` `(` `)` `&` `|` and spaces reach the test platform unchanged, so the planner rejects none of them. `&` and `|` inside a filter value need a backslash, as VSTest documents [ENG-13].

| Code | Condition (kind `test` unless stated) |

| `ASEVD138` | more than 32 projects |

| `ASEVD140` | a project path is declared twice |
| `ASEVD141` | a filter is longer than 1024 characters or holds a control character or line break |

`ASEVD144` is what keeps a `test` producer from carrying a coverage gate. `ASEVD145` is what keeps it from closing any other assertion. Other kinds keep validating exactly as today.

## S5. Reconciler

`TestRunReconciler` is a pure function, internal to `Evidence.Cli`:

`Reconcile(inventory, results, minimumTests) -> reason + counts`

- `inventory`: the discovered identities for one project, with multiplicity.
- `results`: one terminal outcome per result identity, with multiplicity.
- It returns `Complete` only when the inventory count is at least `minimumTests`, every inventory identity is unique, every result identity is unique, every inventory identity has exactly one result, no result lacks an inventory identity, and every result is passed.
- Otherwise it returns the first of `EmptyDiscovery`, `BelowMinimum`, `AmbiguousIdentity`, `MissingResult`, `UnexpectedResult`, `TestsFailed`, `TestsSkipped` that applies (S8).
- `AmbiguousIdentity` is the fail-closed rule: when two inventory entries or two results share an identity, the producer does not guess.

Counts: `discovered` is the inventory count; `passed`, `failed` and `skipped` count results by outcome; `executed` is `passed` plus `failed`.

## S6. Test-run source

One internal interface, `ITestRunSource`, supplies the inventory and the results for a project. The v1 implementation, `DotnetCliTestRunSource`, defines identity as the printed test name, compared ordinally and case-sensitively.

**Child processes.** Every child is started through one internal bounded runner [ENG-20]: the coverage source's existing runner if it is reachable from `Evidence.Cli` with process-tree kill, otherwise one new internal type in `Evidence.Cli`. For every child:

- the executable is the producer option `DotnetPath`; the working directory is the project file's directory [ENG-10];
- standard input is closed [DX-8];
- the environment adds `DOTNET_CLI_USE_MSBUILD_SERVER=0`, `MSBUILDDISABLENODEREUSE=1`, `DOTNET_NOLOGO=1`, `DOTNET_SKIP_FIRST_TIME_EXPERIENCE=1`, `VSLANG=1033`, `DOTNET_CLI_UI_LANGUAGE=en` [ENG-2];
- standard output and error are captured in memory, at most 8 MiB per stream (a named constant), and never forwarded to the console or a log [ENG-24];
- after exit or kill, output drain waits at most 5 seconds and then abandons the stream [ENG-2];
- a kill stops the whole process tree.

**Commands**, with `<P>` the project file name and `<c>` the configuration. These are the forms the probe ran on SDK 10.0.402:

```
dotnet msbuild <P> -property:Configuration=<c> -getProperty:TargetFrameworks -getProperty:TargetFramework -getProperty:RunSettingsFilePath -getProperty:VSTestSetting -getProperty:TestingPlatformDotnetTestSupport -nologo
dotnet restore <P> -property:Configuration=<c> --disable-build-servers -nodeReuse:false -tl:off --nologo
dotnet build <P> -c <c> --no-restore --disable-build-servers -nodeReuse:false -tl:off --nologo
dotnet test <P> -c <c> --no-build --nologo --disable-build-servers -nodeReuse:false -tl:off --list-tests [--filter <expr>]
dotnet test <P> -c <c> --no-build --nologo --disable-build-servers -nodeReuse:false -tl:off [--filter <expr>] --logger "trx;LogFileName=results.trx" --results-directory <fresh dir>
```

T5 confirmed by an end-to-end test on SDK 10.0.402 that `dotnet restore` accepts these flags and that the property read works with `-property:Configuration`.

**Listing parse** [ENG-8, amendment 7]. Split standard output on LF and strip one trailing CR. Exit code must be 0. Exactly one line must equal `The following Tests are available:`. After it, every non-empty line must be either an identity line (exactly four leading spaces, then a character that is not a space; the identity is the text after the four spaces, with no other trimming) or a line starting with `No test matches the given testcase filter`. Lines before the marker are not inspected.

| Observation | Result |
|---|---|
| non-zero exit | `DiscoveryFailed` / `ExitCode` |
| zero or more than one marker line, or any other line after the marker, including five or more leading spaces | `DiscoveryFailed` / `ListingShapeUnrecognized` |
| a stream reached the 8 MiB cap | `DiscoveryFailed` / `OutputTooLarge` |
| zero identity lines | `EmptyDiscovery`; the run pass is skipped |

**Results parse** [ENG-11, ENG-12, amendment 7]. The producer creates one new empty results directory per project under scratch. It is `ResultsMissingOrStale` if the directory already exists, or if after the run it does not hold exactly one file, named `results.trx`. The TRX is read as a stream of at most 256 MiB (a named constant) with DTDs prohibited. Only `UnitTestResult` elements directly under `Results` count; nested `InnerResults` are ignored. Each contributes `testName` as identity and `outcome` as outcome: `Passed` is passed, `NotExecuted` is skipped, `Failed`, any other value and a missing attribute are failed. The `ResultSummary` counter `total` must equal the parsed count. Malformed XML, a counter mismatch or reaching the stream bound is `ResultsMissingOrStale`.

**Run exit.** A non-zero exit from the run pass with no failed result parsed, or a test host crash, is `RunAborted`. A non-zero exit with failed results goes to the reconciler.

## S7. Producer

`TestEvidenceProducer` is internal to `Evidence.Cli` and implements `IEvidenceProducer`. Its options [C18, amendment 14]:

| Option | CLI value |
|---|---|
| `RepositoryRoot` | `GitRepositoryRootResolver.FindRepositoryRoot(Directory.GetCurrentDirectory())` |
| `ScratchRoot` | a new unique directory under the system temporary directory, owner-only permissions on Unix |
| `Configuration` | `Debug` |
| `DotnetPath` | `dotnet`; only tests pass another value in this delivery |

**Sequence** [C1, DX-5, DX-9, DX-14, ENG-9, ENG-10, ENG-17]

1. **File checks, all projects, no process.** The project file exists, and its path after link resolution stays inside `RepositoryRoot`. Otherwise `ProjectNotFound`.
2. **Property evaluation, all projects, one `dotnet msbuild` each.** In order: the host cannot start or reports no compatible SDK, `ToolchainUnavailable`; evaluated `TargetFrameworks` names more than one framework, `MultiTargetUnsupported`; evaluated `RunSettingsFilePath` is non-empty, `RunSettingsUnsupported`; the nearest `global.json` (walk starts at the project directory, existing `FindNearestGlobalJson` unchanged) is unreadable or selects a runner other than VSTest, or `TestingPlatformDotnetTestSupport` is true, `UnsupportedRunner`.
3. **Per project that passed steps 1 and 2, in declaration order:** restore, build with `--no-restore`, list, run unless the listing is empty, reconcile.

Steps 1 and 2 finish for every project before the first restore, so a mistake in the last declared project is reported before any build. Every declared project is attempted even after an earlier one is incomplete. The exceptions are the internal deadline and cancellation.

**Runner helper** [D6, C12, C16, DX-15]. The `global.json` runner check and the `TestingPlatformDotnetTestSupport` read move from the coverage preflight in `CoverageRunDrivers.cs` into one internal helper compiled into `Evidence.Coverage`, without the coverlet requirement. It has a file-only entry point that takes a start directory and an evaluated-property entry point, and returns a classification; each caller owns its message. A characterization test pins the existing coverage preflight messages before the move. The `test` message says Microsoft.Testing.Platform is not supported in this preview and links the tracking entry.

**Deadline** [D7, ENG-18]. The planner guarantees `timeoutSeconds` of at least 30. The internal deadline is `TimeoutSeconds` minus a reserve of one tenth of `TimeoutSeconds` rounded up to whole seconds, at least 1 and at most 30, measured with the injected `TimeProvider`. At the internal deadline the producer stops the child's process tree, records the project in flight as `DeadlineExceeded` and every later project as `NotRun`, writes the receipt and returns `TimedOut`. In the CLI nothing else enforces the deadline. Cancellation propagates as it does in the coverage adapter.

**Progress** [DX-13]. One line per project and phase on standard error, for example `[2/3] building`, `[2/3] running 41 tests`, with counts and no test names.

**Unhandled exception** [DX-9, ENG-15]. The producer writes a trace file holding the exception type and stack frames only under `<output>/diagnostics`, never under `artifacts`, and prints its path.

## S8. Reasons, precedence and outcomes

Each project gets exactly one reason: the first that applies in this order. One enum, one mapping function that returns the outcome and the recovery class, and a test that every value maps [amendment 7, DX-12].

| Order | Reason | Outcome | Recovery | Owner |
|---|---|---|---|---|
| 1 | `ProjectNotFound` | `Unavailable` | fix and rerun | producer |
| 2 | `ToolchainUnavailable` | `Unavailable` | fix and rerun | producer |
| 3 | `MultiTargetUnsupported` | `Unavailable` | needs a decision | producer |
| 4 | `RunSettingsUnsupported` | `Unavailable` | needs a decision | producer |
| 5 | `UnsupportedRunner` | `Unavailable` | needs a decision | producer |
| 6 | `RestoreFailed` | `Unavailable` | rerun unchanged | producer |
| 7 | `BuildFailed` | `Failed` | fix and rerun | producer |
| 8 | `DiscoveryFailed` (sub-reason `ExitCode`, `ListingShapeUnrecognized` or `OutputTooLarge`) | `Unavailable` | needs a decision | source |
| 9 | `RunAborted` | `Failed` | rerun unchanged | source |
| 10 | `ResultsMissingOrStale` | `Unavailable` | rerun unchanged | source |
| 11 | `EmptyDiscovery` | `Failed` | fix and rerun | reconciler |
| 12 | `BelowMinimum` | `Failed` | fix and rerun | reconciler |
| 13 | `AmbiguousIdentity` | `Failed` | needs a decision | reconciler |
| 14 | `MissingResult` | `Failed` | fix and rerun | reconciler |
| 15 | `UnexpectedResult` | `Failed` | fix and rerun | reconciler |
| 16 | `TestsFailed` | `Failed` | fix and rerun | reconciler |
| 17 | `TestsSkipped` | `Failed` | fix and rerun | reconciler |
| 18 | `Complete` | `Passed` | none | reconciler |
| n/a | `DeadlineExceeded` (project in flight at the internal deadline) | `TimedOut` | fix and rerun | producer |
| n/a | `NotRun` (project not reached) | `TimedOut` | fix and rerun | producer |

**The rule separating outcomes** [C4]. `Unavailable` when the producer could not observe the project: missing project, missing toolchain, unsupported shape or runner, failed restore, unparseable listing, missing or stale results. `Failed` when it observed the project and the assertion does not hold, including a build failure and an aborted run. The producer never returns `Invalid`; that stays the manifest builder's verdict for a contract violation.

**Aggregate.** The producer outcome is the most severe project outcome in the order `TimedOut`, `Unavailable`, `Failed`, `Passed` [ENG-19]. Only `Passed` returns the declared assertion id, so no other outcome can yield a gate-eligible claim.

**Known shapes** (from the probe). Deferred theory rows give `MissingResult` or `AmbiguousIdentity` depending on row names. Two tests with one display name give `AmbiguousIdentity`. A display name that starts with a space gives `DiscoveryFailed` / `ListingShapeUnrecognized` for the whole project. A zero-match filter gives `EmptyDiscovery`. A multi-targeted project is caught by evaluated `TargetFrameworks`, including when set only in `Directory.Build.props`, with the two-marker rule as backstop.

## S9. Receipt

`test-receipt.json`, schema version 1, written to the declared `test-receipt` slot through `EvidenceArtifactWriter`.

| Field | Meaning |
|---|---|
| `schemaVersion` | `1`; preview, see S1 |
| `projects[]` | one entry per declared project, in declaration order |
| `projects[].path` | the declared path |
| `projects[].filterSha256` | lowercase hex SHA-256 of the UTF-8 filter text; null when no filter |
| `projects[].minimumTests` | the effective minimum |
| `projects[].discovered`, `executed`, `passed`, `failed`, `skipped` | counts as defined in S5; zero where a step never ran |
| `projects[].reason` | a value from S8 |
| `projects[].subReason` | set for `DiscoveryFailed`; null otherwise |

No test names, no filter text, no console output.

- The receipt is written for every outcome the producer returns, because the manifest builder treats a missing required artifact as `Invalid`.
- It is written to a temporary name and moved into place, before scratch deletion [ENG-18].
- `Diagnostic` carries one bounded line, for example `2 projects, 41 discovered, 41 executed. No coverage claim was made.`, and gives the number of projects with failing tests whenever it is above zero [ENG-19].

## S10. Scratch

The TRX, the results directories and anything else transient live under `ScratchRoot`, never under the evidence output. The producer deletes scratch on every exit path it controls. Deletion is best effort: it cannot change the outcome or throw [ENG-18].

## S11. CLI `run`, output and `explain`

**`run`, in order**

1. Resolve the plan.
2. Reject, with a stable `ASEVD2xx` code each (next free numbers at implementation): a profile that selects a `test` producer and declares resources, with a message that the `test` kind is not available through a resource-backed profile in this delivery [DX-10]; and two artifact-writing producers whose ids differ only by case [ENG-7].
3. Delete `evidence-manifest.json`, `evidence-summary.json` and the selected producers' directories under `<output>/artifacts` [ENG-6]. This also changes coverage-only runs: after a cancelled rerun, `verify` reports a missing manifest.
4. Write the plan.
5. Run the selected producers sequentially. Dispatch is by `Kind`: `coverage` and `test` are built in; any other kind keeps today's `Unavailable` message. A `test` producer gets an `EvidenceArtifactWriter` rooted at `<output>/artifacts/<producer id>` through `EvidenceProducerContext.Artifacts`, and returns the written artifact in `EvidenceProducerResult.Artifacts`.
6. For every required artifact a producer returned, run the shared artifact check (S12). If it fails, replace that producer's result with outcome `Unavailable`, no satisfied assertion ids and no artifacts. The manifest verdict is then `Invalid`, the obligation is not closed, and `run` exits non-zero with a message that names the missing receipt and says to rerun [DX-7, ENG-5].
7. Build and write the manifest and summary.

**Output** for a `test` producer [E4, C6, DX-3, DX-6, DX-9, DX-15, ENG-19, ENG-23]

- One preview line when a `test` producer is selected.
- A counts table read back from the receipt: Project, Discovered, Executed, Passed, Failed, Skipped, Reason, followed by `No coverage claim was made.` The same table goes to the console and the GitHub step summary.
- On an incomplete run, the first line names the operation and the project and gives the number of projects with failing tests when above zero. Then one line per incomplete project with: producer id, project path, phase, reason, sub-reason if any, next action, documentation anchor.
- A rerun hint: the exact argument list the producer used for the failing phase, one argument per line, and a single shell line only when every argument can be quoted safely for POSIX shells. `BuildFailed` prints the `dotnet build` list. `ToolchainUnavailable` prints the host path used and the SDK version `global.json` requires. `ProjectNotFound` says "policy error".
- A notice when `minimumTests` is unset and more than one test was discovered.
- Compiler and test output are not forwarded, because they can hold test names.
- The `ASEVD211` text does not tell a `test` user to inspect producer output that is not kept.
- When a host deadline fires before the producer returns, the summary diagnostic names the timeout as the cause of the `Invalid` verdict. In this delivery that path is reached only by the test that runs the producer through `EvidenceHostBootstrap`.

**`explain`** and `evidence-summary.json` list, for each `test` producer, its projects, filters and minimums, and print the preview line. `explain` starts no process.

## S12. Artifact check and `verify`

One documented public static method is added beside `EvidenceArtifactValidation` in `Evidence.Contracts` [ENG-14]. Given an artifact root and a manifest artifact entry, it rejects an absolute or traversing path and a link at any path component, compares length before hashing, and hashes at most the recorded length. Three callers: CLI `verify`, the `run` check in S11 step 6, and the validation tool's `VerifyAsync`, whose existing tests must pass unchanged.

CLI `verify` gains `--artifact-root`, default the `artifacts` directory beside the manifest file [D14, C7]. It fails when a manifest-listed artifact is missing or its length or SHA-256 differs. A manifest that lists no artifacts verifies as before.

`verify` proves integrity, not that the gate passed: it exits 0 on an intact manifest whose claim is `None` [V3]. One test pins that.

## S13. Mixed versions and upgrade order

Recorded by run on 2026-11-22 with released CLI 0.2.0-preview.14 [V1, DX-11, ENG-3, uc2a].

- A released CLI plans a policy with a `test` block without complaint, reports the producer `Unavailable` at `run`, and yields claim `None`. It cannot produce a gate-eligible claim from a `test` profile.
- A CLI that does not know the `test` property fails `verify` with `ASEVD203` on every plan written by a CLI that does, once the policy holds a `test` block. That includes plans for changes that select no `test` producer.
- 0.2.0-preview.14 and `origin/main` already fail `verify` on each other's plans with no `test` block, because of `CoverageArtifactRetention`. The upgrade rule below is therefore needed for the next release regardless.
- A plan written by an older CLI from a policy with a `test` block verifies on a newer CLI. Its `PolicyDigest` is that of the policy without the block.

**Upgrade order.** Upgrade every CLI that runs `run` or `verify` to the release that holds this change. Only then add a `test` block to a shared policy. **Rollback:** remove the `test` block from the policy first, then downgrade. A consumer that must know the `test` block was in force compares the plan's `PolicyDigest` with one computed by an upgraded CLI.

PR 1 also tests the mechanism with current code [C7]: a policy with an unknown extra property loads and plans; an unknown kind returns `Unavailable` and claim `None`; a manifest whose plan digest does not match fails `verify`.

## S19. Choices made while consolidating

Accepted items left these open or in tension. Each is settled here so the text is single-valued; none changes an owner decision.

1. **Precedence of the new reasons.** C1 and DX-9 each called their reason "first", and ENG-1 asked for `RestoreFailed` to sit before `UnsupportedRunner`. A project's reason is its first failing step, so the order has to follow the step sequence of ENG-10 and ENG-17: file checks, property evaluation, then restore. That puts `ProjectNotFound` first, `ToolchainUnavailable` second, and `RestoreFailed` after `UnsupportedRunner`.
2. **Diagnostic numbers.** The accepted items required one code per condition and a start at `ASEVD137`; the assignment in S4 is this specification's.
3. **Recovery classes** in S8 and the receipt field names in S9 are this specification's; the accepted items required that they exist.
4. **Path and filter details** added at T2: project file extensions are fixed at `.csproj`, `.fsproj` and `.vbproj`; a path is at most 512 characters and may not hold `:` or a control character; duplicate paths are compared without regard to case; a blank filter is rejected.
5. **Details settled at T5 and T10.** A project whose property evaluation fails for a reason other than a missing toolchain is `BuildFailed` at phase `evaluate`. `EvidenceArtifactWriter` now writes in-memory artifacts to a temporary name and moves them into place, for every producer. The fixture project for the end-to-end test is generated at test time by `TestEvidenceProducerProcessTests` (one passing fact, a two-row theory, a failing fact and a skipped fact), so T16 needs a checked-in fixture or uses that generated shape. The host-deadline test shortens the declared timeout to 1 second on a hand-built plan, because the host uses wall-clock time.
6. **Details settled at T6 and T14.** The rerun hint for the run phase leaves out the TRX logger and the scratch results directory, because scratch is deleted after the run; the remaining arguments select the same tests. Commands in the hint use the project file name and are run from the project directory. The counts table is Markdown on both the console and the step summary. `evidence-summary.json` gains a `testProducers` property only when a `test` producer is selected.
7. **Changes from pull request review (2026-11-22).** The receipt floor counts six bytes per path character, the worst case of the receipt's JSON escaping, where ENG-4 said UTF-8 bytes. `ASEVD146` also requires `relativeRoot` `test`. The run-settings check reads `VSTestSetting` as well as `RunSettingsFilePath`. Only `test` producers' artifact directories are retired, and a linked artifact directory stops `run` with `ASEVD216`. A results directory may hold attachment subdirectories; exactly one file, `results.trx`, is still required. A project interrupted by the deadline after its listing keeps its discovered count.
8. **Known limit, not closed.** Property evaluation runs before restore, so a property supplied only by a restored package's build files is not seen. A package that switches the project to Microsoft.Testing.Platform still fails closed at the listing parse. A package that supplies a run-settings file would not be detected. No project in this repository does either.

# History (not normative)

Everything below is the record of how the specification above was reached: the original design, the reviews and the decision trail. The probe and mixed-version sections are the evidence the specification cites. Task lists, tables and diagrams below are superseded by S1 to S19.

## Problem Statement

Some changed paths have no production code to cover: workflows, scripts, release tooling and the tests of that tooling. The truthful evidence for them is "the tests that exercise them ran, all of them, and passed". Today the only built-in producer that runs tests is `coverage`, which always makes a coverage claim, and a policy cannot narrow it ([CoverageEvidenceProducer.cs:174](../../Evidence/ForgeTrust.AppSurface.Evidence.Cli/CoverageEvidenceProducer.cs)).

The cost is concrete in this repository. [`.github/evidence.policy.json`](https://github.com/forge-trust/AppSurface/blob/main/.github/evidence.policy.json) has no rule for `.sh`, `.yml`, `.github/**`, `scripts/**` or `eng/**`, so a script-only change falls to the conservative `native-acceptance` profile: all four producers, with declared timeouts totalling about 3.2 hours. That figure is a budget, not a measured duration. The tests that exercise those files already exist, for example `tools/ForgeTrust.AppSurface.Release.Tests`.

## What Makes This Cool

"Everything selected ran and passed" is a reusable receipt, and coverage is one consumer of it. Built as its own piece, the same receipt serves [#930](https://github.com/forge-trust/AppSurface/issues/930) (patch coverage for a declared project subset) and is the first code that enforces the [Evidence CLI README](../../Evidence/ForgeTrust.AppSurface.Evidence.Cli/README.md) promise that a partial test selection cannot pass as a full claim.

## Constraints

- Preserve existing canonical bytes and digests for policies that do not use the new fields ([Contracts README](../../Evidence/ForgeTrust.AppSurface.Evidence.Contracts/README.md)).
- VSTest only, matching the coverage path. No item tracks Microsoft.Testing.Platform execution support today; [TODOS.md](../../TODOS.md) only notes that it is unsupported.
- No new package dependency in v1. If the pinned-SDK probe (see Probe evidence) contradicts the scratch probe, this design stops and the dependency decision returns to the owner; approach B is not adopted silently.
- Test names never enter the manifest, the receipt, `Diagnostic`, `evidence-summary.json`, the GitHub step summary or the evidence artifact root. They do exist transiently in a private scratch directory and in captured child-process output; see Scratch and privacy.
- No test impact analysis, no coverage measurement, no flaky retry.
- Coordinate with the approved [#917 design](https://github.com/forge-trust/AppSurface/issues/917), which adds `Inputs` to the same declaration record and a contract version step.

## Premises

1. The payoff is routing: tooling paths get a targeted profile that runs only the tests that exercise them.
2. The claim is scoped by assertion, never a weaker coverage claim. A `test` producer cannot carry a coverage gate or close a coverage assertion.
3. "Built-in" means one shared producer class plus a small kind dispatch in CLI `run`, registered by Id in the Aspire host and in the repository validation tool. There is no assertion registry; `appsurface/test/discovery-complete@1` is a documented convention the policy declares.
4. Completeness comes from an independent discovery inventory reconciled with results by case identity and multiplicity. A crash, an abort, missing or stale results, or any skipped case leaves the assertion open. (Revised at D6. The first version of this premise read results only; Codex showed a results file cannot report a selected test that produced no result.)
5. v1 rejects a Microsoft.Testing.Platform project with a stable diagnostic.
6. A failed test is `Failed`. `Flaky` stays unproduced. `minimumTests` per project is in, optional.
7. New declaration fields are additive and omitted when absent.

## Cross-Model Perspective

Codex (gpt-6.2-astra) read a structured summary cold. The gstack result checker marked the run `unverified` because it could not parse severity tags; the response itself was complete.

- **Challenged premise 4 (Critical).** A TRX file counts a test when a result event arrives, so a selected case with no result is absent from both total and executed. Accepted; premise revised.
- **Suggested the typed VSTest API** so case identities are exact. Kept as the follow-up source (approach B).
- **Found a platform guard.** [ReleaseWorkflowPolicyTests.cs:709](../../tools/ForgeTrust.AppSurface.Release.Tests/ReleaseWorkflowPolicyTests.cs) and `:759` return early on Windows and report Passed. Verified by reading the file. No accounting detects a test that passes without doing its work.
- **Suggested replaying a known regression per route** to test the policy itself. Good idea, outside the producer contract; see Next Steps.

## Approaches Considered

- **A, two-pass `dotnet` CLI matched by display name:** rejected because duplicate names and deferred theory rows would let the assertion close on an ambiguous match.
- **B, typed VSTest translation layer:** deferred because it adds a package dependency and a second test execution path before a probe shows v1 needs it.
- **C, receipt core with a swappable inventory source:** selected at D7. In v1, C reads the same `dotnet` CLI output as A. It differs in three ways: an identity that is ambiguous leaves the assertion open instead of matching by count; reconciliation is a pure function tested without a test host; and the source sits behind one interface so B can replace it.

## Recommended Approach

### Declaration

Add an optional, init-only `Test` property to [`EvidenceProducerDeclaration`](../../Evidence/ForgeTrust.AppSurface.Evidence.Contracts/EvidenceContracts.cs), omitted from JSON when null:

```json
{
  "id": "release-tooling-tests",
  "kind": "test",
  "version": "1.0.0",
  "requiredResources": [],
  "assertionIds": ["appsurface/test/discovery-complete@1"],
  "artifactSlots": [
    { "logicalName": "test-receipt", "relativeRoot": "test", "mediaType": "application/json", "required": true, "maximumBytes": 65536 }
  ],
  "timeoutSeconds": 900,
  "test": {
    "projects": [
      { "path": "tools/ForgeTrust.AppSurface.Release.Tests/ForgeTrust.AppSurface.Release.Tests.csproj", "filter": "FullyQualifiedName~ReleaseWorkflowPolicyTests", "minimumTests": 10 }
    ]
  }
}
```

- `projects`: 1 to 32 entries, unique repository-relative forward-slash paths ending in a project file extension. Reuse the [planner's path grammar](../../Evidence/ForgeTrust.AppSurface.Evidence.Planner/README.md); reject absolute paths and traversal.
- `filter`: optional VSTest filter expression, at most 1024 characters, passed as one argument and never through a shell.
- `minimumTests`: optional integer, 1 or greater. Default is 1, which is the non-empty rule.
- Because the whole declaration feeds `PolicyDigest` and `PlanDigest`, changing a project, filter or minimum changes both with no extra digest code.

### Planner validation

New `ASEVD1xx` codes, taking the next free numbers after the #917 branch lands, each added to the [planner diagnostic table](../../Evidence/ForgeTrust.AppSurface.Evidence.Planner/README.md):

| Condition | Result |
| --- | --- |
| Kind `test` with missing or empty `test.projects` | rejected |
| Invalid, duplicate or out-of-bounds project path, filter or minimum | rejected |
| `test` block on any other kind | rejected |
| Kind `test` with `coverageGate`, `coverageExecution` or non-default `coverageArtifactRetention` | rejected |
| Kind `test` without a required `test-receipt` artifact slot | rejected |

The fourth row is what enforces premise 2. Today `CoverageGate` is accepted on any kind; this design restricts only kind `test` and leaves the repository's `repository-validation` producers alone.

### Receipt core

A pure function in the Evidence support code shared by the CLI and Aspire adapters:

`Reconcile(inventory, results, minimumTests) -> verdict + counts`

- `inventory`: the discovered case identities for one project, with multiplicity.
- `results`: terminal outcome per case identity, with multiplicity.
- The pure function owns these reason codes: `EmptyDiscovery`, `BelowMinimum`, `AmbiguousIdentity`, `MissingResult`, `UnexpectedResult`, `Failed`, `Skipped`. It returns complete only when inventory count is at least `minimumTests`, every inventory identity is unique, every inventory identity has exactly one result, no result lacks an inventory identity, and every result is Passed.
- The adapter owns the reason codes that mean reconciliation never had trustworthy inputs: `UnsupportedRunner`, `BuildFailed`, `DiscoveryFailed`, `RunAborted`, `ResultsMissingOrStale`, `DeadlineExceeded`, `NotRun`.
- `AmbiguousIdentity` is the fail-closed rule: if two inventory entries or two results share an identity, the assertion stays open. The producer does not guess.

**v1 identity.** One internal interface supplies `inventory` and `results`. The v1 implementation defines identity as the test name string, compared ordinally and case-sensitively:

- Inventory: `dotnet test <project> -c <configuration> --no-build --list-tests` plus `--filter <expr>` when declared, run with `DOTNET_CLI_UI_LANGUAGE=en`. Standard output must contain exactly one line equal to `The following Tests are available:`. Each following line that starts with exactly four spaces is one identity, taken as the text after those four spaces with no other trimming. Following lines of any other shape are ignored, which is how the zero-match notice is skipped. Zero identities after the marker is `EmptyDiscovery`, so a zero-match filter produces `EmptyDiscovery` and outcome `Failed`. A non-zero exit, zero marker lines or more than one marker line is `DiscoveryFailed`. A multi-targeted test project prints one marker per target framework and is therefore rejected as `DiscoveryFailed` in v1; the documentation states that `test` projects must target one framework. A test name containing a line break loses its continuation line here and then fails reconciliation as `MissingResult`, so it also fails closed.
- Results: the same command without `--list-tests`, with `--logger "trx;LogFileName=<fixed name>"` and `--results-directory <scratch>`. Each `UnitTestResult` element contributes its `testName` attribute as identity and its `outcome` attribute as outcome. `Passed` is passed, `Failed` is failed, `NotExecuted` is skipped, and any other outcome value is treated as failed.

### Execution, outcomes and precedence

The producer class takes options at construction: `RepositoryRoot`, `ScratchRoot` and `Configuration` (default `Debug`). The CLI supplies the root the way the coverage adapter does, `GitRepositoryRootResolver.FindRepositoryRoot(Directory.GetCurrentDirectory())` ([CoverageEvidenceProducer.cs:216](../../Evidence/ForgeTrust.AppSurface.Evidence.Cli/CoverageEvidenceProducer.cs)). The validation tool supplies its existing `--repository` argument. An Aspire host consumer supplies both when it registers the producer. `ScratchRoot` defaults to a new unique directory under the system temporary directory.

Per declared project, in declaration order:

1. Reject a non-VSTest runner with the same checks the coverage path applies in [CoverageRunDrivers.cs](../../Cli/ForgeTrust.AppSurface.Cli/CoverageRunDrivers.cs) (the `global.json` `test.runner` check and the `TestingPlatformDotnetTestSupport` check).
2. `dotnet build <project> -c <configuration>` once, with implicit restore.
3. Discover with `--no-build`. When discovery yields zero identities the run pass is skipped: the project's reason is `EmptyDiscovery` with all counts zero, and no results file is expected.
4. Otherwise run with `--no-build`.
5. Reconcile.

Every declared project is attempted even after an earlier one is incomplete, so the receipt is whole. The exceptions are the producer deadline and cancellation.

**Deadline ownership.** The producer enforces its own deadline, earlier than the declared one, so it can still write the receipt. Its internal deadline is `TimeoutSeconds` minus a reserve of one tenth of `TimeoutSeconds`, with the reserve at least 1 second and at most 30 seconds. At the internal deadline it stops the child process, records the project in flight as `DeadlineExceeded` and every later project as `NotRun`, writes the receipt, deletes scratch and returns `TimedOut`. In the CLI nothing else enforces the deadline, matching how the coverage adapter owns its own timeout ([CoverageEvidenceProducer.cs:110](../../Evidence/ForgeTrust.AppSurface.Evidence.Cli/CoverageEvidenceProducer.cs)). The Aspire host also enforces `TimeoutSeconds` itself and records `TimedOut` with no artifacts when a producer has not returned ([EvidenceHostBootstrap.cs:385](../../Evidence/ForgeTrust.AppSurface.Evidence.Aspire/EvidenceHostBootstrap.cs)). If the producer overruns its reserve and the host deadline fires first, the result has no receipt, the required slot is missing and the manifest verdict is `Invalid`. That is never gate-eligible, and the pitfall documentation says so.

Each project gets exactly one reason, the first that applies in this order, and each reason maps to one outcome:

| Order | Reason | Producer outcome |
| --- | --- | --- |
| 1 | `UnsupportedRunner` | `Unavailable` |
| 2 | `BuildFailed` | `Failed` |
| 3 | `DiscoveryFailed` | `Unavailable` |
| 4 | `RunAborted` (test host crash, or a non-zero exit with no failed result) | `Failed` |
| 5 | `ResultsMissingOrStale` | `Unavailable` |
| 6 | `EmptyDiscovery` | `Failed` |
| 7 | `BelowMinimum` | `Failed` |
| 8 | `AmbiguousIdentity` | `Failed` |
| 9 | `MissingResult` | `Failed` |
| 10 | `UnexpectedResult` | `Failed` |
| 11 | `Failed` | `Failed` |
| 12 | `Skipped` | `Failed` |
| 13 | `Complete` | `Passed` |
| n/a | `DeadlineExceeded` (project in flight at the internal deadline) | `TimedOut` |
| n/a | `NotRun` (project not reached) | `TimedOut` |

`Failed` here means the producer evaluated the discovery-complete assertion and it does not hold. `Invalid` is never returned by the producer; it remains the manifest builder's verdict for a contract violation such as a missing required artifact. The producer outcome is the most severe project outcome in the order `TimedOut`, `Unavailable`, `Failed`, `Passed`. Cancellation propagates exactly as it does in the coverage adapter. Only `Passed` returns the declared assertion ids, so no other outcome can yield a gate-eligible claim.

`RequiredResources` behaves exactly as for other producers: the plain CLI marks the producer `Unavailable` when a profile declares resources ([EvidenceCommands.cs:168](../../Cli/ForgeTrust.AppSurface.Cli/EvidenceCommands.cs)), and the [Aspire host](../../Evidence/ForgeTrust.AppSurface.Evidence.Aspire/README.md) waits for readiness first. That answers the issue's second open question.

### Receipt artifact and summary

`test-receipt.json`, schema version 1, written to the declared slot: per project the path, the SHA-256 of the filter text, `discovered`, `executed`, `passed`, `failed`, `skipped`, `minimumTests`, and the reason code. No test names, no filter text, no console output. `Diagnostic` carries one bounded line, for example `2 projects, 41 discovered, 41 executed. No coverage claim was made.`

The receipt is written for every outcome the producer returns, including `Unavailable`, `Failed` and `TimedOut`, with zero counts where a step never ran. The manifest builder treats a missing required artifact as `Invalid` for any outcome, so an unwritten receipt would turn an honest incomplete run into a contract violation.

The CLI `run` path has no artifact plumbing today: it never constructs an `EvidenceArtifactWriter` and returns results without `Artifacts`. This design adds it for kind `test` the same way the Aspire host does at [EvidenceHostBootstrap.cs:389](../../Evidence/ForgeTrust.AppSurface.Evidence.Aspire/EvidenceHostBootstrap.cs): a writer rooted at the run's artifact directory joined with the producer Id, passed through `EvidenceProducerContext.Artifacts`, with the written artifact returned in `EvidenceProducerResult.Artifacts`.

### Scratch and privacy

The TRX file and build logs live under `ScratchRoot`, never under the evidence artifact root. The producer deletes its scratch directory on every exit path it controls: success, failure, timeout and cancellation. Child-process standard output and error are captured in memory, bounded, and not forwarded to the console or to any log. On an incomplete run the console shows counts, the reason code and the exact `dotnet test` command to rerun locally. An adapter test asserts that after a run with a known test name, that name appears in no file under the artifact root and not in the producer's console output.

- The Aspire host and [`tools/ForgeTrust.AppSurface.Evidence.Validation`](../../tools/ForgeTrust.AppSurface.Evidence.Validation/README.md) register the same class by producer Id.
- `explain` and `evidence-summary.json` list, for each `test` producer, its projects, filters and minimums.
