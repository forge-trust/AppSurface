## Problem and useful outcome

AppSurface's cross-platform coverage fan-in combines a complete primary solution run with required native supplements. Today its [Python producer](https://github.com/forge-trust/AppSurface/blob/main/scripts/coverage_fanin.py) and [shell acceptance helper](https://github.com/forge-trust/AppSurface/blob/main/scripts/coverage-gate-fanin.sh) own capture, composition, replacement, and policy checks. The public [C# verifier](https://github.com/forge-trust/AppSurface/blob/main/Evidence/ForgeTrust.AppSurface.Evidence.Aspire/EvidenceCoverageFanIn.cs) checks their output; it does not supply the downstream execution workflow. The repository's native acceptance executable is not packable.

A library maintainer should install AppSurface packages and its CLI in a separate repository, collect their own solution, combine its declared native evidence, and obtain independently verified aggregate and patch results. They should not copy repository scripts or install Python, Bash, or Aspire merely to combine coverage. A deliberately altered report must fail through the same installed API and commands that produced a successful result.

This is an observed distribution and reuse gap in source, not a measured production incident or a demonstrated performance improvement. No customer interviews, adoption numbers, or speed claims were established in this session.

## Supported C# and CLI contracts

Names below are the proposed v1 API shape, not APIs available today. Public methods are asynchronous, accept cancellation, return typed bounded results, and validate/freeze caller collections before side effects. Callers own their writers and cancellation source; the facade never disposes or retains them after an operation. Shared invocation state and leases remain internal.

| Operation | Inputs and behavior | Result and failure contract |
| --- | --- | --- |
| `CoverageFanIn.CollectAndCaptureAsync` | Consumer solution or explicit complete project inventory, collector settings, configuration, output, policy, SDK/source expectations, and collection deadline. Uses the existing collection/normalization engine and captures only after successful required execution. | Capture reference and measured execution summary; a failed, skipped-required, cancelled, or incomplete run publishes no successful capture. Existing supported runner behavior remains authoritative. |
| `CaptureAsync` | Existing successful producer artifacts: primary normalized report plus complete timings/project inventory, or native raw collector plus normalized report; explicit policy and identity expectations. Verify the supplied inventory and hashes before publishing a capture. | Versioned capture reference and artifact hashes. This validates a trusted producer's declared observations; it is not independent proof that tests ran. |
| `ComposeAsync` | Exactly one primary capture and the policy's exact supplementary set, expected identity, fresh destination by default, and resource limits. An explicit `ReplaceOwned` output mode permits only registered, revalidated fan-in replacement. | Composed report, normalized-path primary report, and composition receipt. Failure preserves unknown or modified material and publishes no complete generation. |
| `AcceptAsync` | Explicit captures, composed generation, gate/diff policy, and owned report destination. Run the existing primary aggregate gate, the composed patch gate when AggregateAndPatch is explicitly selected, and independent verification in that order. AggregateOnly is an explicit baseline policy and produces PatchNotRequested, never patch acceptance. | An accepted generation bound to exact hashes and policy, or a typed rejection with retained failure reports. A producer-reported success alone is insufficient. |
| `VerifyAsync` | Captures, produced reports/receipts/gate results, and expected policy/source/run identity supplied by the caller. Reopen and check them independently. | Read-only verification result with bounded reason codes. It creates no output directory, changes no report, and cannot make historical evidence fresh. |

`CoverageFanInPolicy`, `CoverageOperationLimits`, and the operation-specific collection, capture, composition, acceptance, and verification requests are supported public contracts. Capture references identify schema, generation, policy digest, source/run identity, and retained file hashes. Results distinguish the requested operation from its outcome (`Succeeded`, `Rejected`, `Cancelled`, `TimedOut`, or `Incomplete`) and include bounded reason codes, artifact references, actual partial effects, and cleanup completeness. Successful capture or composition does not mean accepted coverage; only completed acceptance produces an accepted-generation result. Verification reports the validity of the supplied existing generation without claiming fresh execution.

The public policy is an immutable snapshot of the complete intended primary test inventory, exact required supplementary producer IDs/platforms/filters, instrumentation and normalization identity, source/SDK/configuration, run identity, gate thresholds/tolerance/mode, diff expectation, and operation budgets. Resolve `.sln` and `.slnx` through the existing bounded solution discovery path; compare normalized relative project identities exactly and reject duplicates, aliases, missing projects, or unapproved extras. Do not bake in AppSurface's filename, project count, filters, three-platform set, or GitHub variables.

Use bounded provider-neutral run identity fields: producer system, run scope, run ID, and attempt. A local caller supplies an explicit unique run ID; GitHub CI passes its repository/run/attempt through its thin adapter. No implicit CI-provider discovery or connector is added. Run identity is not a place for credentials or user content. Matching source, SDK, hashes, and run fields establish consistency within a trusted-producer boundary, not signatures or cryptographic authenticity.

Add `appsurface coverage fan-in capture`, `compose`, `accept`, and `verify`. Each accepts a strict versioned JSON request file and an explicit result destination where writing is required; `verify` may emit JSON to stdout without a destination. `capture --collect` invokes the same public collection-and-capture operation. Missing, unknown, duplicate, or incorrectly typed request fields fail before mutation. Help names the request schema, prerequisites, defaults, and next action. Human progress goes to stderr when JSON is selected. Exit 0 requires the requested successful operation, rejection/execution failure uses 1, invalid input 2, cancellation 130, and the existing terminal watchdog timeout retains 124. Partial effects and cleanup uncertainty are explicit result fields, never success.

## Identity, composition, and verification

Before capture, resolve and compare the actual clean source commit/tree and selected SDK with expectations. Identity subprocesses retain a 30-second deadline. A successful primary inventory requires every intended test project exactly once, completed execution, a produced coverage artifact, and successful normalization/merge. Native captures retain original collector bytes and verify normalization against those bytes. Readers bind the files they hash and parse; they do not hash one pathname and later trust replacement bytes.

Composition preserves package/class/file identity and record occurrence, method name/signature/occurrence, overloads, repeated records, class lines, method lines, and native-only measurable points. Hits may improve from a supplementary observation. A branch point improves only when its denominator matches and an individual observation proves full coverage; two partial observations cannot be added to invent full coverage. Preserve the primary report's aggregate facts separately from the composed patch report. When AggregateAndPatch is selected, patch acceptance requires an identical diff snapshot, a nonempty measurable patch, and line/branch denominators no smaller than the primary reference. An explicitly selected AggregateOnly baseline retains the existing no-diff behavior and cannot satisfy a patch-required obligation.

The native composer is a production port of the producer's conservative rules. The verifier separately derives expected facts and checks the published output, raw-to-normalized fidelity, capture inventory, timing success, hashes, receipts, gate arithmetic, diff, and denominators. It must not call the production composer or use its generated receipt as its oracle. Shared bounded IO, schemas, and serialization are allowed; semantic identity/count checks need independent assertions. Hand-authored golden expectations and mutations must detect lost class/method records, altered point identities, invented full branches, missing native-only points, forged gate passes, and source/run/policy mismatches even when supplied hashes are recomputed.

The proposed operation defaults are 512 MiB per XML report, 1 MiB per JSON document, 30 seconds per identity subprocess, five minutes per non-collection operation, and a 4 GiB total admitted input/staging-byte budget per operation. Parser defaults are depth 64 for JSON/XML, one million class-plus-method line records per report, and 32 input bundles per operation; the exact admitted set must still equal the policy. Enforce counts while streaming before materializing a report, reject DTD/entity expansion, and do not truncate oversized input into acceptable evidence. Collection retains the existing supervised engine and requires its explicit overall deadline; it does not inherit the five-minute IO-stage deadline. Enforce byte limits while reading and writing, not only through a preflight stat. Larger declared budgets require deliberate configuration and do not relax coverage, identity, or ownership checks. Validate these provisional defaults and peak memory against the full AppSurface inventory and separate consumer before release; they are not measured performance claims.

## Storage, publication, and interruption

Use the existing private artifact manager, native identity/no-follow traversal, private metadata, and shared-reader/exclusive-writer leases. Acquire multiple physical objects in deterministic order and reuse an invocation's existing lease context. No global lock spans test execution. A name, timestamp, PID, run label, or matching content hash alone never grants deletion authority. V2 capture provisions its coordination metadata while holding writer custody; read-only verification requires that metadata to exist and refuses unavailable coordination rather than creating metadata or adopting a tree. The legacy v1 verifier retains its original read-only contract.

Custom destinations are fresh-only by default. `ReplaceOwned` requires compatible registration, purpose, current physical identity, an exclusive lease, exact known inventory and hashes, and no unknown state. Validate the new capture before retiring the prior capture. Retained source handles and exclusive output custody prevent input replacement or redirected cleanup; reject input/output overlap, linked or replaced ancestors, nested repositories, busy writers, changed metadata, and foreign files. Legacy unregistered directories remain untouched and receive a fresh-destination diagnostic; do not add markers to populated legacy trees to manufacture ownership.

Stage and validate a complete generation before atomic publication. Publish its completion marker last. An accepted result names that exact generation, its source/run/policy fingerprint, and retained artifact hashes. A later failed operation cannot reuse a prior success as its result; CI upload and Evidence completion remain guarded by the current operation's successful acceptance. Keep failure reports truthful and separate from accepted receipts. Cancellation, limits, access errors, full disks, and partial cleanup return explicit incomplete effects; retries never expand authority. Required evidence dependencies remain retained and verifiable under the established current/pinned/history policy.
