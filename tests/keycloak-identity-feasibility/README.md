# Keycloak extracted-package replay

The [#888 evidence summary](../../docs/plans/issue-888-keycloak-identity-readiness.md#feasibility-results) records the qualified profile, historical results, and retained concerns. These standalone fixture sources support local verification of a candidate package pair. Run the full repository gate separately.

The measured setup used macOS ARM64, Linux ARM64 Docker, .NET SDK 10.0.402, Aspire 13.6.5, pinned Keycloak 26.7.2, and Playwright Chromium headless shell 1254. Prepare those inputs before the offline consumer replay. The shared host fixture pin for the Keycloak release is in [replay_environment.py](replay_environment.py); the worker image pin remains in the [AppHost fixture](normal-supervised-apphost/Program.cs). The runner derives its tagged and digest-only forms from that shared pin and passes the tagged reference only for the tunnel theme.

1. Pack the Keycloak and Aspire Keycloak projects at the exact candidate source commit and record the archive hashes. Build the [AppHost bootstrap project](acceptance-apphost/AcceptanceAppHost.csproj) in Release to produce the base Aspire host dependencies. Restore the OIDC project needed for the prepared fixtures.
2. Run `prepare-supervised-composition.py` with `--packages <feed> --version <version> --sdk <sdk-root> --playwright-modules <node-modules> --chromium-engine <headless-shell-root> --evidence <new-directory>`. The modules directory must contain `playwright` and `playwright-core`. Pass the resulting receipt to `prepare-normal-supervised.py` with `--composition-preparation <receipt> --pure <archive> --adapter <archive> --aspire-packages <nuget-packages> --evidence <new-directory>`. The latter copies the pinned Aspire orchestration and dashboard tools, replaces the bootstrap entry point with the compiled [normal supervised AppHost fixture](normal-supervised-apphost/Program.cs), and loads the Keycloak assemblies from the candidate archives. Both receipts record the resolved SDK root. For older composition receipts, also pass `--sdk <sdk-root>` to the normal preparer.
3. Copy `run-normal-supervised.py`, `replay_environment.py`, `managed-seed-readback.py`, `prime-legacy-volume.py`, and `cleanup-stopped-normal.py` to an external driver directory. Run `run-normal-supervised.py --preparation <receipt> --acceptance <group> --evidence <fresh-output>` for `cold`, `neutral`, `skoolit`, `tunnel`, and `legacy-uid1000`. Pass `--sdk <sdk-root>` for older preparation receipts. `--docker-endpoint` selects the current user's Docker Desktop socket or `unix:///var/run/docker.sock` and defaults to the Desktop socket. The runtime uses the prepared payload, a private empty NuGet cache, and disposable test-owned Docker resources. The legacy group first lets Keycloak create its test volume as UID 1000.
4. Check each run receipt. Run `cleanup-stopped-normal.py --receipt <run-receipt> --evidence <fresh-cleanup-output>` for a completed fixture. Cleanup reserves the fresh evidence directory before checking Docker or removing resources, so an occupied path fails without cleanup. Cleanup uses the recorded Docker endpoint and independently checks the daemon ID. For older run receipts, pass `--docker-endpoint` if they used the system socket. Retain any uncertain marker and its files. Preserve the package and driver hashes, source commit and tree, and the fixture and cleanup receipts locally.

Run the replay input and preparation tests from the repository root with `python3 -m unittest discover -s tests/keycloak-identity-feasibility`.

The preparation scripts, [packed single-file smoke](verify-packed-worker-single-file.py), and [two-version upgrade check](verify-worker-consumer.py) share the [offline NuGet setup](replay_environment.py). Each consumer starts with fresh private caches. The setup clears package sources and fallback folders and removes inherited restore source overrides. The assets check requires the effective source set to match the fixture policy. Preparation and packed single-file consumers use no sources, and the two-version consumer allows only its generated local feed. Candidate package builds use the normal build cache.

The shared preparation runner requires both command log paths before restore. It verifies assets before starting build or publish and checks them and the empty package cache again before handing off outputs. The worker-anchor preparation also requires the exact private package folder. The runner exposes one failed stage for callers and keeps its command history limited to actual SDK exits. A verification rejection has its own result field and the corresponding command log records the reason.

Before replacing the candidate pure library in the normal payload, the normal preparer verifies the staged composition code inventory and bytes and the copied browser driver hash against the composition receipt. Normal replay checks the exact file inventory and hashes of the prepared runtime directories before launch and after the run.

## Public CaptureAsync from the extracted payload

The [public CaptureAsync fixture](public-capture/README.md) exercises an ordinary consumer boundary with frozen signed inputs. Pass the candidate adapter archive, which contains the recursive worker and pure-library payload.

```sh
python3 tests/keycloak-identity-feasibility/run-public-capture.py \
  --package <adapter-archive> --evidence-root <fresh-output> --phase all
```

The driver accepts the same optional `--docker-endpoint` argument as the normal runner. It compiles and runs from copied sources and the extracted package with cleared feeds, an empty read-only NuGet cache, and networking disabled. It requires stopped verification within 30 seconds before cleanup. See the [sealed credential custody guide](../../docs/sealed-client-credential-reference.md) for the separate Linux ARM64 worker-anchor replay. The repository solution carries the unit, workflow, and native-lane tests. Keep historical experiments and the generated proof captures in their local archive.
