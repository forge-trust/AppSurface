# Coverage Observation plan reference

`EvidenceCoverageObservationPlan` is the root's data-only checkpoint-two planner adapter. It binds copied protected policy and diff bytes to the actual hashes retained by `EvidenceProtectedLaunchInput`, validates the complete policy with [`EvidencePlanner`](../ForgeTrust.AppSurface.Evidence.Planner/EvidencePlanner.cs), and returns the planner's existing `EvidencePlan`. It does not admit a worker, register or lease a producer, retain artifacts, or establish a coverage result. The [restricted coverage producer](../ForgeTrust.AppSurface.Evidence.Coverage/EvidenceRestrictedCoverageProducer.cs) remains the owner of test execution, report validation, merge, and numeric gate behavior.

`Resolve(request, policyBytes, expectedPolicySha256, diffBytes, token)` is the pure-data entry point. Policy bytes must be nonempty, within the shared 20 MiB JSON input bound, and hash to the lowercase SHA-256 of the original bytes. Diff presence must match the request; declared diff bytes must be within the same bound and match the request's digest. Explicit request paths and paths read from the unified diff are passed together to the existing planner, including rename previous paths. A diff-only request is valid when it yields a selected coverage profile.

Every requested profile ID must exist and describe either an empty targeted profile or a targeted, resource-free profile with exactly one supported producer. The selected profile must be the latter, must not be the conservative profile, and its producer ID must be in `ObservationProducerIds`. That producer is fixed to kind `coverage`, version `1.0.0`, no required resources, the sole assertion `appsurface/coverage/behavioral-patch@1`, an explicit coverage gate, and one required `coverage-report` artifact slot at `merged`, media type `application/xml`, capped at 20 MiB. The gate thresholds are validated by the existing planner and later evaluated by the existing restricted producer; this adapter does not duplicate those calculations.

The planner's conservative fallback remains meaningful. An unmatched path, a rename whose old path selects a different profile, or paths spanning profiles select the conservative profile and are rejected here. `ValidatePolicy` runs before profile whitelist checks, so malformed declarations in unselected profiles and rules are also rejected. Producer IDs supplied by the request must be declared by one of its whitelisted profiles; this prevents an undeclared producer from being smuggled into the root selection.

`FromInput(input, token)` reads the actual retained policy and optional diff. It runs a full request/deployment/deadline recheck before reads and after resolution, while the reads perform their own retained-file checks. It uses the original monotonic allowance and propagates caller cancellation. Neither entry point turns a valid plan into admission, a lease, artifact custody, native proof, or a positive coverage assertion. See the [checkpoint-two migration gate](../../docs/plans/issue-779-csharp-supervision-migration.md#checkpoint-2-declared-producer-and-artifact-custody) for genuine Linux execution and failure controls.
