# Private C2 retained-report mutation

`EvidencePrivateQualification=C2` selects one nonpackable private image through the existing [build-owned qualification selector](../ForgeTrust.AppSurface.Evidence.Contracts/EvidenceNativeQualification.cs). Ordinary `None` builds contain neither the mutation method nor its dispatch. No request, environment variable, callback, path argument, producer registration or consumer proof can select it.

After the actual [producer artifact holder](producer-artifacts.md) completes `Capture` and its ordinary `ListReports`, `LinuxCoverageControlOperations.Inventory` invokes the fixed mutation before returning the inventory. `LinuxProducerArtifactCustody.MutateRetainedReportForC2(token)` forwards only to its authentic retained set. `LinuxRetainedReportSet.MutateRetainedReportForC2(token)` selects the first nonempty actual report, uses mandatory `openat2` relative to its retained parent, and opens write-only without create, truncate or append. It validates the original complete metadata and captured hash, changes one byte, and verifies the same inode, ownership, mode and length plus a different complete SHA-256. The original job token bounds the at-most1MiB read/hash loops; synchronous filesystem operations remain externally bounded by the existing root systemd lifetime.

The original inventory then travels through the unchanged authenticated worker protocol. Its subsequent ordinary read must reject before returning bytes and poison custody. No expected-failure receipt bypasses a read, changes a guard, or restores the file. This synchronous operation introduces no task or external rendezvous; STOP can wait only for the bounded mutation to finish, with no reply-order cycle.

The root emits private bounded metadata JSON under `evidence-c2-artifact-mutation-v1`: one `mutated` event with original/changed hashes, length and device/inode, then one `read-rejected` event only when the authentic read throws an I/O failure while the original token and owner remain active. No report path, report bytes, exception text, admission or successful-cleanup claim is emitted. Diagnostic write failure cannot replace the original read failure. The genuine control must bind both events, the failed original root result, absence of a Passed manifest, physical group/pump joins and strict account release. Source preparation and portable reader tests do not establish that native result.
