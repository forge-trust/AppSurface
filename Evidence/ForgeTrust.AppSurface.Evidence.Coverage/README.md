# ForgeTrust.AppSurface.Evidence.Coverage

`ForgeTrust.AppSurface.Evidence.Coverage` is a private implementation package shared by the [Coverage facade](../../Coverage/ForgeTrust.AppSurface.Coverage/README.md), the [AppSurface CLI](../../Cli/ForgeTrust.AppSurface.Cli/README.md), and the first-party [Evidence workflow](../ForgeTrust.AppSurface.Evidence.Cli/README.md). It ships only as a transitive support package; it is not a consumer extension point, direct-install package, or separately supported integration package.

## Local receipt coordination

The CLI workflow and [prepared EvidenceHost](../ForgeTrust.AppSurface.Evidence.Aspire/README.md) share the internal receipt coordinator. Consumers use those entry points; they must not call this private assembly through reflection or build a second receipt protocol. The [reuse guide](../../guides/evidence-reuse.md) defines opt-in input, capacity, audit, output and cooperative-child rules.

| Internal seam | Contract and caller obligation |
| --- | --- |
| `EvidenceProducerIdentityBuilder.BuildAsync` | Reads declared regular Git working-tree inputs under the 60-second preparation budget. Returns a complete identity or an ineligible reason, never a partial key. Component values are hashed; exact relative input paths and file digests support explanations. |
| `EvidenceProducerKeyMaterialExecution.Start` / `WaitAsync` / `DisposeAsync` | Owns the entire callback and returned material enumeration. The bounded wait caps the producer deadline at 30 seconds and adds cleanup grace. Disposal joins the actual task; an active callback prevents fresh work and registration disposal. |
| `EvidenceProducerReuseSession.PrepareAsync` / `BeginExecutionAsync` | Prepares and restores before resource closure, then revalidates and durably admits the complete fresh key set before execution. The session owns canonical-order key leases. Read-only preparation creates no writers, leases, store, or execution channel. |
| `GetWriter` / `GetChildLifetime` / `BeforeCleanupAsync` | Supplies the invocation's bounded artifact writer and execution-only child capability. Call the pre-cleanup hook after actual producers settle and before disposing registrations. A false result retains producer and resource ownership while actual callbacks or admitted children remain active. |
| `CompleteAsync` / `CompleteUnsuccessfulSettlementAsync` / `DisposeAsync` | Revalidates current claims and inputs, checks fresh audits, and admits successful payloads as one atomic invocation batch. Cleanup failure or unknown child settlement preserves durable authority. Actual task joins precede lease release, including unsuccessful runs. |
| `EvidenceReceiptStore` / `EvidenceReceiptQuota` | Uses native per-key execution leases and a short root-index publication lease. Read-only snapshots never acquire or create that lock. The root index binds all authority rows and accounts for metadata, payloads, reserved stages and replacement overlap; unconfirmed deletion retains its reservation. |
| `EvidenceReceiptStore.EvidenceReceiptKeyLease.HashStream` | Internal contract-test boundary for an already opened, readable, length-reporting stream. Verifies the exact manifest length from zero through 256 MiB and its SHA-256 with reads of at most 64 KiB, checking cancellation before each read. Growth, truncation and invalid initial lengths are refused. The caller owns the stream and disposal. |
| `EvidenceReceiptStore.EvidenceReceiptKeyLease.VerifyExactTree` | Internal exact-path inventory verification over a caller-owned native root and immutable canonical relative paths. It owns only child leases, checks directory privacy by default, and separately requires callers to verify hashes and lengths. Its optional `maximumTreeEntries` accepts only stricter budgets from 1 through the unchanged production default of 1,024. Smaller per-call budgets support native limit tests without changing process file-descriptor limits. |
| `EvidenceChildLifetimeSession` | Opens one current-user-only cooperative channel after durable admission. Close enrollment before declaring settlement, reject new clients before work, and join admitted handlers without forcibly disconnecting them. A disconnected admitted client permanently leaves settlement unknown. |

The receipt reader closes all validation and restore handles before invalidating an owned payload. This ordering lets Windows retire the directory instead of treating the reader's own open handle as uncertain cleanup. Invalidation still clears only matching settled authority; if deletion cannot be confirmed, the retired payload and its quota charge remain.

A failed partial admission joins its startup channels and compensates only this invocation's unstarted execution markers. Audit intent survives compensation. Listener unavailability prevents new enrollment but is distinct from an admitted client whose completion is unknown. The internal `EvidenceChildLifetimeSession.Start` has per-call listener-creation and native-wait fault seams; production omits them. An injected wait receives the session-owned pipe and cancellation token, returns its actual operation task, and must not dispose or retain the pipe after that task settles. Injected failures follow ordinary listener recovery and disposal.

Every quota-index read validates its entries. A missing `AuthorityState` is invalid when retained in-flight, audit-intent, or quarantine flags are set; the reader rejects that row before new admission and preserves its bytes. A pristine reservation without retained authority flags remains valid. Candidate entries are validated again before maintenance and immediately before publication; invalid entries fail with `InvalidDataException` before mutation and leave the prior index unchanged. The generated staging component is `payload-stage-{reservationId}` and the committed component is `payload-{reservationId}`; final-component validation rejects the staging prefix case-insensitively. Active, authority-state, and retired payload references must be valid final components. Retired names cannot alias the active payload or a reserved payload, using case-insensitive comparison. The generic receipt store permits at most 256 payload files per tree; the coverage adapter separately caps its recommended `coverage-reports` inventory at 128 files, 256 MiB, and 2 MiB of metadata. These limits serve different boundaries. Capacity and serialized-size checks remain separate so valid candidates can still trigger safe LRU eviction.

The internal `EvidenceReceiptKeyLease.PublishInvocationCoreAsync` has a per-call `beforeArtifactCopyForTests` seam after complete source preflight and metadata staging, immediately before each artifact copy; production callers omit it. Cancellation or a staging failure removes uncommitted stage/payload directories and releases their reservations only after absence is confirmed. If cleanup or quota release is uncertain, the reservation remains charged. The invocation also cleans earlier staged requests before propagating a staging or cancellation exception. Once batch authority commit is attempted, final payloads and their accounting remain intact because the authority update may already be visible.

`EvidenceCoverageProcessRunner` applies cooperative child credentials and SDK isolation through the [coverage process request](../../Cli/ForgeTrust.AppSurface.Cli/CoverageRun.cs) `EnvironmentOverrides` snapshot. Existing overrides, including null entries that remove inherited variables, are preserved; invocation credentials take precedence for their own keys. The wrapper changes only dotnet requests and keeps the request's output budget, strict UTF-8 setting, standard-input snapshot, accounting hook and process lease. Buffered and streamed execution use the same environment contract, so the wrapper never changes the parent process environment.

Caller order is prepare, admit, construct the exact resource closure, await readiness, execute fresh producers, run pre-cleanup validation, join actual children and callbacks, dispose registrations/resources, complete publication, then dispose the session. Original coverage execution reports and writer custody must have separate roots; copying into an existing report path is rejected. Fatal failures propagate after all safely releasable cleanup is attempted. `EvidenceProducerReuseSession.AreChildrenSettled` requires every admitted child to confirm completion; joined handlers alone cannot authorize prepared registration or resource disposal. Unknown child settlement preserves those owners and durable authority, including fatal callback paths. Bounded waits never establish termination or permit deleting unresolved authority.

A non-coverage producer whose declared slots allow an empty artifact inventory can publish and restore that inventory without a source or destination report directory. Admission still validates its passed result, current inputs, origin plan, metadata, quota and execution ownership. The coordinator creates no report directory for an empty inventory. [Coverage receipts](#reusable-coverage-report-custody) require their complete report inventory.

The private engine contains the versioned report-based patch applicability path. The public behavior, exact Git policy, artifact shapes, trust boundary, limits and recovery rules are documented in the [fan-in v3 reference](../../guides/coverage-fan-in.md#opt-in-schema-v3-report-based-patch-applicability); the public typed surface is in the [Coverage API reference](../../Coverage/ForgeTrust.AppSurface.Coverage/README.md#request-and-result-reference). The repository build explicitly selects v3 for pull requests requiring native coverage. The standalone Dogfood adapter defaults `--contract-version` to 2 and selects v3 with value `3`. Pin expected `contractVersion: 3` and preserve all four applicability outcomes; `PatchAccepted` includes valid N/A and needs no separate N/A or measured-only switch. The engine's internal logical-budget snapshot is surfaced only for v3 installed proof and is not a supported consumer API or a process-memory measurement. The accepted `coverlet-collector-cobertura-v1` profile is pinned to Coverlet collector 10.0.1; Microsoft binary-to-Cobertura conversion is not interchangeable.

The assembly owns one in-process implementation of coverage discovery, execution, watchdog supervision, merge, gate evaluation, patch analysis, and controlled artifact writing. The CLI owns command parsing and presentation; Evidence owns policy and claim translation. This direction ensures Evidence produces coverage claims from the same execution engine as `appsurface coverage run` and `appsurface coverage gate`, without invoking a second process. Both surfaces use the fail-mode default. For VSTest test phases with at least 90 seconds remaining, the engine requests no-dump hang blame and reserves part of the current budget for sequence output and summary. Evidence's producer deadline remains authoritative and includes discovery/build time. The [CLI hang-diagnostics reference](../../Cli/ForgeTrust.AppSurface.Cli/README.md#coverage-run-hang-diagnostics) documents the timeout arithmetic, opt-outs, artifact statuses, and migration for healthy long-running tests. Evidence results never include test names or Sequence.xml contents.

This package's coverage orchestration types are internal and visible only to first-party assemblies. Use the [public fan-in API](../../Coverage/ForgeTrust.AppSurface.Coverage/README.md#request-and-result-reference) for C# integration, the [coverage commands](../../Cli/ForgeTrust.AppSurface.Cli/README.md#appsurface-coverage-run) for shell automation, or the [EvidenceHost workflow](../../start-here/evidencehost.md) when coverage is part of an evidence plan.

The v3 [screenshot policy](../../guides/coverage-fan-in.md#screenshot-baseline-updates) reads committed PNG blobs through the buffered process runner. `CaptureBinaryStandardOutput` returns complete stdout in `BinaryStandardOutput` and keeps stderr available for diagnostics. This mode enforces the byte limit while the child runs. A truncated result has no blob. Callers must check the exit status, diagnostics and expected object length before interpreting the bytes.

The shared [process runner](https://github.com/forge-trust/AppSurface/blob/main/Cli/ForgeTrust.AppSurface.Cli/CoverageRun.cs) starts stdout and stderr copying asynchronously on the default scheduler. Already-buffered output must not run one stream's synchronous byte-accounting callback before the other pipe can start. The internal `CreateFaultTerminatingTarget` test seam exercises that boundary with synchronously readable streams; it preserves mandatory per-byte charging, original fault identity, cancellation, drain bounds, output limits, and separate stderr capture. Callers should keep accounting callbacks short and thread-safe; the asynchronous handoff is not a separate timeout or a dedicated thread per stream.

`CoverageRunWatchdogSupervisor.DisposeAsync` cancels artifact publication and joins the internal monitor without capturing the caller's synchronization context. In-flight monitor work retains its existing bounds, including the ten-second default process-cleanup bound. After the monitor finishes, disposal drains an active writer for its configured incident-write bound (two seconds by default). A delayed writer keeps the artifact commit gate, console, and bootstrap directory alive until its observed completion performs deferred cleanup; disposal completion is not artifact publication or cleanup confirmation. State/deadline waits, console diagnostics, and shared process draining also avoid caller-context capture so a busy UI or test continuation queue cannot prevent shutdown. See the [watchdog reference](../../Cli/ForgeTrust.AppSurface.Cli/README.md#coverage-run-watchdog) for stall behavior, diagnostics, and artifact interpretation.

The [coverage storage guide](../../guides/coverage-storage.md) documents the in-progress retention contract shared by CLI and Evidence coverage producers. Its `managed` default permits removal only of verified redundant collector XML after canonical publication; `full` retains it. A CLI run using `--no-clean` preserves prior artifacts in either mode, so retained output can include files from earlier invocations. The Evidence declaration's additive `coverageArtifactRetention` property defaults to `managed`; older JSON omitting it remains valid. The [domain identity validation record](../../docs/plans/issue-899-progress.md) records the installed CLI domain-lifecycle proof and its scope. No universal storage-saving percentage is promised.

### ReportGenerator runtime payload

The private package carries the pinned ReportGenerator 5.5.10 `net10.0` runtime under `tools/net10.0/any/reportgenerator/5.5.10/net10.0/`. The package path is fixed even when a compatible consumer targets a platform such as `net10.0-windows`. Its build-transitive target copies the complete asset set, including `ReportGenerator.deps.json`, `ReportGenerator.runtimeconfig.json`, dependency assemblies, Windows sidecars, and the runtime manifest, beside the consuming assembly at `appsurface-coverage-runtime/reportgenerator/5.5.10/net10.0/`. Source project builds use the same restored package assets. The CLI tool package explicitly carries that same versioned payload at its own assembly-relative path.

New fan-in code should pass `new StrictReportGeneratorRuntimeLocator()` where `IReportGeneratorPackageLocator` is accepted. Its `ResolveReportGeneratorDll()` call anchors the manifest to the private assembly, requires the exact 5.5.10 / `net10.0` inventory, rejects missing, changed, extra, or version-skewed files, and returns the entry point only after complete preflight. It does not search PATH, a global tool, the NuGet cache, or a source checkout. Existing `CoverageRun` commands continue to use `ReportGeneratorPackageLocator` and keep their prior package-cache compatibility behavior.

The independent fan-in verifier validates native projection, composition, and gate arithmetic separately. For native single or indexed captures, original serialized collector class and method facts own the canonical projection. Every load/import independently derives that projection from the retained raw collector reports and checks class, method, line, occurrence, and fact identities plus root totals derived from retained class-line points. Collector root summaries can include compiler points absent from serialized classes; those summary-only points stay byte-exact in the raw originals but do not enter native measurements. The single-project form retains `collector.cobertura.xml`, `coverage.cobertura.xml`, and `manifest.json`; indexed native capture retains byte-exact originals with exact project mappings and timings. The optional `CoveragePath` on the single-project compatibility input is bounded and validated but never acts as a measurement oracle. Historical v2 single-report captures remain readable only when their existing facts and root totals already match the canonical raw-derived projection; folded, reconstructed, inflated, or otherwise mismatched projections must be recaptured from originals into fresh output. The primary aggregate gate remains a separate measurement: it uses the exact original normalized primary root counters, including summary-only compiler points. Composition keeps all primary records and denominators and adds supplementary raw facts conservatively; composed root totals derive from the full retained class-line points; patch metrics also inspect method points. See the [fan-in measurement contract](../../guides/coverage-fan-in.md#historical-v1-evidence) for the complete acceptance sequence.

For v3, the writer emits applicability and gate projections while the independent verifier separately derives the patch diff, line/branch outcomes and metrics from the pinned Git objects, retained reports and composition. A valid zero reported denominator is `notApplicable` with `no-reported-patch-points`, zero measurable/covered counts and a null percentage; invalid evidence is `unverified` with all metric counts and percentage null. The verifier checks every claim copy and preserves original occurrences; it does not use a stored N/A flag or percentage as authority. V3 trusts the accepted collector's reported points, so silently omitted executable points or honored source exclusions may yield N/A or leave a mixed patch passing. It does not make an independent source-completeness claim. See the [canonical outcome and trust contract](../../guides/coverage-fan-in.md#api-outcomes-and-decision-rules).

Portable primary imports use the same measurable-point admission as fresh captures before publication, including class/method numbers, hits, branch counters, and source-relative paths. Matching hashes and successful timing entries do not admit malformed coverage. Original source roots may use POSIX, Windows drive, or UNC syntax; they describe the producer's path mapping and never grant receiving-host access or ownership. The [transport contract](../../guides/coverage-fan-in.md#portable-inputs-replay-and-replacement) explains receiving custody.

This payload supports ordinary .NET 10 framework-dependent applications that retain their assembly-relative files. Trimming, single-file publishing, and Native AOT are not supported by this runtime contract. The packaged [third-party notice](THIRD-PARTY-NOTICES.md) identifies the redistributed ReportGenerator version and Apache-2.0 license.

### Native operation verification

Artifact safety keeps managed decisions and native acceptance separate. Internal,
per-call observations cover file-state decoding, private Unix ownership/mode
checks, Windows rename-buffer encoding, lock-result classification, and
filesystem/mount classification. Windows access policy uses normalized SID and
access-mask facts; candidate-file decisions retain explicit handle ownership and
reject nonregular or unrepresentable sizes before returning a stream. Candidate
handles remain owned by the inspector until a stream is successfully returned;
metadata failures release them on every unwind path. Production defaults call the host APIs and retain
normal no-follow path, identity, and publication checks. The observations are test
seams, not consumer configuration; they never establish another operating system's
ABI or filesystem guarantees. Native acceptance still runs on the supported
Windows/NTFS, macOS/APFS, and Linux/ext4 lanes described in the
[storage validation record](../../docs/designs/coverage-artifact-storage-validation.md).

Observation state uses a single bounded publication slot per private observation
directory. Writers hold that directory's exclusive operation lease while they
reconcile the known slot, flush the new state, and atomically replace the current
state. A failed or interrupted write can therefore retain at most one known slot;
unknown files and changed identities are preserved for inspection. Registry input
validation rejects malformed observation and expiry-receipt entries before they
reach status or maintenance, keeping optional metadata failures separate from the
primary coverage outcome. See the [storage recovery guide](../../guides/coverage-storage.md#recovery-recipes).

The CLI's internal storage-command base renders schema-v1 operation data into human
and JSON results using the [storage result contract](../../guides/coverage-storage.md#status-json-and-exit-behavior).
Its optional domain identifier observation returns `domain-unknown` for nonfatal
failures so rendering retains the primary result and safe diagnostic. Gate commands
validate input and destination policy before acquiring output coordination; invalid
inputs therefore do not create report directories or contend with active writers.
Human numeric fields accept JSON numbers only; absent, differently typed, or
unrepresentable values use the field's documented zero or unknown fallback. This
keeps presentation of partial results from throwing after the operation has
already recorded its outcome and side effects. Operation implementations still
validate their own metadata before producing this result; presentation fallbacks
do not certify an unknown inventory or make an incomplete result successful.

Current-run sidecar publication cleans up its own staging file on failure in both
collection and independent gate publication. Cleanup requires the staged object's
identity to match; a replaced entry is preserved and cleanup failure retains the
original diagnostic. This is separate from private observation-state staging above.

Secure Unix opens share an internal native-flag selector for Darwin, Linux x64,
and Linux ARM64. [Linux ARM64 native open flags](https://github.com/torvalds/linux/blob/master/arch/arm64/include/uapi/asm/fcntl.h) use different directory-only and no-follow bits
from x64; output traversal, collector artifact reads, and storage inspection must
use the matching pair. Unverified Linux architectures fail before opening a
candidate. The selector has decision tests, while the native no-follow tests in
the [platform matrix](https://github.com/forge-trust/AppSurface/blob/main/.github/workflows/build.yml) verify actual host behavior.

Unix metadata calls select libc symbols for the process ABI because callers read
native `stat` and `statfs` structures at fixed offsets. Intel Darwin dispatches both
`fstat` and `fstatfs` to their `$INODE64` symbols; Darwin arm64 and Linux use the
unsuffixed symbols. Dispatch follows the current OS and process architecture. Callers
must still provide a sufficiently large writable buffer and interpret only the layout
for that host. The [XNU `stat.h` declarations](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/sys/stat.h)
define Darwin's inode-versioned symbol mapping; [XNU `mount.h`](https://github.com/apple/darwin-xnu/blob/main/bsd/sys/mount.h)
defines the 64-bit-inode `statfs` structure, and [XNU's syscall table](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/syscalls.master)
distinguishes the legacy and 64-bit `fstatfs` interfaces. Injected dispatch tests cover
Intel and arm64 routing on any host; native tests validate the running host's call and
layout. They do not replace native Intel Darwin validation.

Recovery invoked by an existing coverage session reuses that session's live exclusive output lease only when its physical identity matches the stored registration. Shared, disposed or unrelated leases grant no recovery authority. The manager keeps ownership of any separately acquired leases and never releases a borrowed session lease. See the [storage lifecycle and recovery guide](../../guides/coverage-storage.md#recovery-recipes).

On Windows, deletable archive and staging candidates coordinate through one empty private `.appsurface-coverage-candidates.lock` file in the domain root. A deterministic byte-range offset derived from the candidate's physical identity keeps independent candidates concurrent. The file stays zero-length because locking beyond its end does not allocate payload storage. Source-output leases keep their existing protocol. Every candidate operation verifies both retained directory and lock-file identities; a hash collision causes safe contention. The fixed file is never removed to force admission. See [Windows byte-range locking](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-lockfileex).

Applied maintenance also reconciles missing, unpinned historical archive registrations after an interrupted expiry. It verifies absence through a retained private archive parent under the store metadata lease, records a bounded missing-archive receipt, and clears only stale archive accounting. It never deletes an existing entry or reports reconciliation as a new physical deletion. Current, pinned and pending-reservation registrations are excluded. See the [recovery guide](../../guides/coverage-storage.md#recovery-recipes).

The internal `CoverageFileSystemInterop.WindowsCreateFile` boundary normalizes an absolute filesystem path and uses the Windows extended drive or UNC spelling before `CreateFileW`. This supports deeply nested collector output beyond legacy `MAX_PATH`; see [Windows path length limits](https://learn.microsoft.com/en-us/windows/win32/fileio/maximum-file-path-limitation). Path spelling does not grant access: callers retain the same containment, reparse-point, file-kind, identity and private-access checks. Relative navigation must be normalized before the extended prefix is applied.

### Store domain identity lifecycle

The ordinary Windows component walk tolerates only native ERROR_ALREADY_EXISTS (183) after a missing-name probe. It then reopens the competing object without following reparse points and validates its kind, retained identity and required private ACL; it never changes existing permissions. This idempotent acquisition is distinct from `CreateArtifactDirectory`, whose fresh-destination no-replace refusal remains strict. Its optional `onCreated` callback runs immediately after native creation, before later validation, so callers can preserve accurate partial-state diagnostics. The `beforeWindowsCreate` acquisition seam is per call and exists only to force a competing native creator in tests. Managed error-contract simulations do not prove Windows admission or ACL behavior.

The schema-v1 store marker records the current host's live directory identity tuple so later opens can compare the retained directory with the persisted marker. `CoverageArtifactStore.Open` and `OpenReadOnly` each accept `Func<CoverageRunOutputLease, string>? observeIdentity = null` as an optional internal seam for deterministic comparison tests. When supplied, it changes only the value compared with the marker: native path traversal, no-follow checks, retained-handle binding, and private-access checks still run. An injected mismatch is simulated managed evidence; it does not demonstrate native remount or restart behavior.

`CoverageArtifactStore.CreateNewDomain(destination, apply, cancellationToken, beforeRegistryPublication = null, onDirectoryCreated = null, beforeDestinationInspection = null, beforeDestinationReopen = null)` is the internal fresh-domain boundary used by the CLI. It requires an absolute destination below an existing safely acquired parent. With `apply: false`, it validates and returns the normalized destination without writing; trailing directory separators are removed before deriving the parent and final component. With `apply: true`, it atomically creates a new private root without replacing an existing path, initializes a fresh schema-v1 marker and empty registry, and does not inspect or migrate the configured store. Existing empty directories and existing domains are refused. The optional per-call `beforeRegistryPublication` action is an interruption-test seam after marker/child initialization and before registry creation; production CLI calls omit it. The optional `beforeDestinationInspection` callback forces parent-replacement races after native parent retention; production omits it. The optional per-call `beforeDestinationReopen` callback runs after the attributes probe and before the retained-directory reopen so tests can force a competing destination; production omits it. The optional onDirectoryCreated observation runs immediately after successful native root creation, before subsequent validation can fail; the CLI uses it to report partial effects accurately. Pre-creation refusal reports no effects. Cancellation or a later initialization error preserves any created private state for inspection; callers must select a different fresh path on retry. The CLI does not print the raw destination, so operators should explicitly configure the same selected fresh path after successful creation. See the [canonical identity recovery contract](../../guides/coverage-storage.md#replacing-a-domain-whose-identity-no-longer-matches).

Store-open diagnostic reasons are `MarkerMissing`, `MarkerInvalid`, `MarkerSchemaUnsupported`, `IdentityMismatch`, `VolumeIdentityMismatch`, `RegistryInvalid`, `PolicyInvalid`, and `PrivateAccessRequired`; unsupported native capability is reported as `CapabilityUnavailable`. They explain the failed validation category without exposing persisted identifiers or authorizing repair. Schema-v1 mismatches remain refused. Matching the file-ID field while the device/volume field differs cannot establish continuity. No native persistent-ID format, schema migration, marker rewrite, or ownership transfer is implemented.

For issue #899, six native lifecycle tests passed on macOS ARM64 for current-mount close/reopen identity stability, cloned-file object identity and copy-on-write separation, replacement of the leased root or ancestor, and linked-root refusal. A separate disposable APFS disk-image experiment showed that detach/remount alone preserved the device value on this host. After a second temporary APFS image occupied the original device number, remounting the first image at the same path changed native `st_dev` from `16777239` to `16777243` while `st_ino` remained `16`. The source-built CLI refused the initialized schema-v1 marker as `VolumeIdentityMismatch`, with unavailable data and no side effects. `coverage storage new-domain` preview and apply succeeded while the old mismatched domain remained selected. Old marker and registry hashes were recorded after the experiment. This demonstrates one possible device-reassignment path on this macOS host, not the original issue's cause or cross-process restart continuity. The six lifecycle tests close and reopen handles within one process. Those initial local observations did not include Windows or Linux execution. The later [native CI observations](../../docs/designs/issue-899-domain-identity.md#evidence-and-limits) record the passing Windows, Ubuntu and macOS coverage-security and EvidenceHost lanes at c281c2ad, including Windows ancestor-rename prevention. These results predate the local PR-feedback fixes; the added Windows component-creation race tests still need native execution. See the [issue #899 design/evidence record](../../docs/designs/issue-899-domain-identity.md) for the platform identity evaluation and limits.

### Native fan-in engine boundary

The supported [Coverage facade](../../Coverage/ForgeTrust.AppSurface.Coverage/README.md) maps frozen typed requests into internal `CoverageFanInEngineRequest`/`CoverageFanInExpected` snapshots. The engine returns an internal bounded result, not a CLI or Aspire object. The new facade has intentional friend access; consumers still cannot import orchestration, native filesystem, collector, gate or storage implementation types from this support package.

`CoverageFanInIO` retains no-follow directory/file handles, admitted byte snapshots and bounded XML documents for one invocation. Readers require existing coordination for local v2 generations; trusted producer and portable transport reads grant no deletion authority. After preflight, `BindOutput` acquires the combined strongest input/output modes in physical-identity order and rechecks retained input identity and bytes. The publisher borrows that exact writer lease and never releases it. Partial acquisition unwinds in reverse order; no global lease spans collection.

For v3, `CoverageFanInBudget` owns both the cumulative logical byte allowance and the operation's `TotalRecords` ceiling across readers. Each reader checks per-document structure while streaming, then admits the complete line/condition counts atomically before DOM materialization. A rejected count leaves the shared counters unchanged. Reusing that reader's cached document does not charge records again; a document independently materialized in another reader consumes the shared allowance. The original v2 reader keeps its per-instance accounting. See the [fan-in limits](../../guides/coverage-fan-in.md#v3-applicability-and-diff-artifacts) for the distinction between logical admission and memory qualification.

V3 record-limit admission uses the closed `limit-exceeded` cause and `budget` role, including streaming line/condition and cumulative-record refusals. `CoverageRunProcessBudgetCharge` retains stdin and output pipe failures before internal child cancellation so error classification preserves the originating fault; internal termination cannot relabel an IO fault as a deadline. The [`CreateCommand` test seam](../../Cli/ForgeTrust.AppSurface.Cli/CoverageRun.cs) exposes the real stdin pipe for deterministic write-failure tests without launching a child.

`CoverageFanInBounds.FileBytes` selects the Git reader's fixed 20 MiB UTF-8 limit for retained `diff.patch`, the XML budget for XML payloads, and the JSON budget for other text. Reading, publication, and prior-generation validation use the same selection so a supported Git diff remains verifiable and replaceable. Patch bytes still consume the invocation's total read/staging budget; no artifact is truncated to fit. The [public limits reference](../../Coverage/ForgeTrust.AppSurface.Coverage/README.md) documents consumer defaults and constraints.

`CoverageFanInNativeInputs.Discover` gives the [repository dogfood adapter](../../tools/ForgeTrust.AppSurface.Coverage.Dogfood/README.md) bounded transport selectors under native no-follow directory/file handles. It admits at most 10,000 total entries, depth 64 and 1 MiB per manifest, rejects duplicate/unknown/missing producer IDs, and disposes every parsed document. Returned directory/source-root pairs grant no custody or trust; import reopens and independently validates their complete evidence. Only this first-party adapter has friend access to the discovery helper; it is not a public consumer API.

`CoverageFanInPublication` validates and flushes new payloads before retiring a compatible registered generation. Both direct publication and invocation-bound output acquisition reject a missing `ReplaceOwned` destination before creating its root or lock; first publication requires `Fresh`. Accepted and numerically rejected gate evaluations share a replacement purpose, while the exact previous stage must still agree between private registration and its hashed completion marker. Capture and composition retain separate purposes. Replacement requires exact private current registration, purpose, physical identity and unchanged inventory; it snapshots prior dependencies under the existing store policy. Unknown or altered output survives refusal. Required staging cleanup and planned registration precede `generation.json`, which commits last. Registration alone cannot certify a missing marker. Root creation and later staging effects are separately observed, so replacement cannot claim it created an existing output. A postcommit cancellation reports the committed generation.

`CoverageFanInComposer` and `CoverageFanInIndependentVerifier` deliberately own separate semantic identity, occurrence, path, branch, diff and gate calculations. Shared code is limited to strict syntax, bounded IO, canonical policy transport, immutable facts, custody and diagnostics. Hand-authored golden and mutation tests check the verifier without the composer as an oracle. Native capture retains and hashes original collector bytes; the canonical native projection is built directly from their serialized class and method facts, preserving ownership and occurrence identity. ReportGenerator's normalized output is not a native measurement oracle: it may fold generated classes, duplicate class points, or reconstruct method ranges, and summary counters may include compiler points absent from serialized classes. Those summary-only counters remain available in the original evidence but cannot fill gaps in the native projection. The independent verifier re-derives canonical class, method, line and occurrence facts from each original and checks projection root totals against those facts. The primary aggregate remains a distinct measurement and retains the exact original normalized primary root counters, including summary-only points; composition preserves every primary record and denominator while conservatively adding supplementary raw facts. The [fan-in measurement contract](../../guides/coverage-fan-in.md#historical-v1-evidence) explains this raw-summary sharp edge and why native composition does not change primary aggregate promotion or policy thresholds.

`CoverageFanInNormalization` admits collector XML through the same bounded reader before invoking the pinned runtime, observes generated XML/text file growth against per-file and aggregate staging limits, cancels and drains the runtime on refusal, and rechecks retained source bindings. Final capture independently reopens and hashes completed output. `CoverageFanInIO.EncodeXml` enforces remaining byte/cancellation admission while serializing normalized and composed XML, before buffer growth. Neither path truncates a report into acceptable evidence.

`CoverageFanInEngineRequest.IdentityRunner` is an internal per-invocation subprocess seam used by deadline, failure and source-change regressions. Public adapters leave it null and use the normal bounded runner. Every Git identity probe explicitly disables `core.fsmonitor` so inspecting source identity cannot execute a repository-configured monitor hook. The seam does not alter expected source checks or publication authority. The read-only `verify` branch rechecks source identity and clean state after accepted-evidence validation, then rechecks retained input bindings before setting `Verified`; source rejection changes no evidence. These observations do not make caller source immutable; use the [dedicated-checkout guidance](../../guides/coverage-fan-in.md#c-operations-and-ordering).

`CoverageFanInEngineRequest.RawCoveragePaths` is the frozen native project-to-original-report transport for indexed inventories of one or more projects; supervised collection always uses this form, including for one project. The [native collection implementation](https://github.com/forge-trust/AppSurface/blob/main/Evidence/ForgeTrust.AppSurface.Evidence.Coverage/CoverageFanInNativeCollection.cs) binds attachments to successful timings invocations, preserves byte-exact originals with an explicit ordered index and independently verifies their canonical projection. The [capture reader](https://github.com/forge-trust/AppSurface/blob/main/Evidence/ForgeTrust.AppSurface.Evidence.Coverage/CoverageFanInCapture.cs) requires exact manifest/index/timings/file inventories during import and every subsequent operation. The legacy single-project `RawCoveragePath` form keeps its established filenames and is checked against the same raw-derived projection. `CoverageFanInBundle.AuxiliaryFiles` retains all validated auxiliary payloads so import preserves every original without granting transport-tree custody. Publication reserves the existing storage inventory limit, including its completion marker; native project inventories leave room for four metadata/coverage payloads. See the [public contract](../../Coverage/ForgeTrust.AppSurface.Coverage/README.md#request-and-result-reference) for defaults, file names and API selectors.

### Reusable coverage report custody

The built-in adapter's recommended `coverage-reports` slot is optional for fresh manifest validation. This lets a successful fresh collection and gate retain their original reports when the complete cache-custody set exceeds its bounds. It does not make coverage collection, gate thresholds, or required assertions optional. Receipt publication and restore still require the complete versioned inventory; zero artifacts or an adapter receipt-ineligibility reason cannot authorize reuse. An explicitly declared `Required=true` slot remains required and missing custody invalidates that consumer's fresh manifest. See the [canonical coverage custody contract](../../guides/evidence-reuse.md#coverage-report-custody) for limits, fallback, and the distinction between fresh evidence and receipt admission.

Deep or wide trees can exhaust native file descriptors before reaching the numeric entry bound. Optional receipt custody then refuses admission while preserving the successful fresh result and its original reports; fitting the file or byte limit alone does not guarantee receipt admission. Unconfirmed staging cleanup retains its indexed charge for later safe reconciliation.


Receipt authority opts into native durable metadata publication through `CoverageArtifactMetadataPublication.Write(..., durableDirectoryEntry: true)`. Linux/macOS synchronize the retained directory after rename; Windows uses an identity-checked no-follow write-through rename handle on NTFS. Other Windows filesystems fail closed before workload startup. Existing observation-only metadata callers retain their default publication mode. A sync error can occur after the new index is visible, so admission compensates matching unstarted markers and never treats a thrown write as proof that nothing was published. See the [CreateFile write-through metadata contract](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew#caching-behavior). Native tests exercise calls and ordering; they do not simulate hardware power loss.


The internal `CoverageArtifactInventory.EnableOrdinaryCapture()` opts a coverage execution into primary-report tracking before any writer publishes. `CaptureOrdinary(token)` hashes only the same explicitly registered files and invocation-owned trees, preserving no-follow containment and identity checks. It uses the producer's cancellation/deadline rather than the optional history inventory's 10,000-file, 2-MiB and one-second limits. Normal sessions keep the existing bounded `Capture` behavior. Receipt admission separately retains its 128-file, 256-MiB and metadata limits. Late opt-in after incomplete registration cannot recover missing ownership and is refused. The adapter promotes both passing and failing gate reports; optional capture uncertainty suppresses reuse without rewriting the gate, while a required promotion I/O failure fails delivery and retains an actionable original report path. See [ordinary report delivery and custody](../../guides/evidence-reuse.md#coverage-report-custody).

The native metadata barrier covers the authority index. Complete payload-directory persistence through hardware power loss is not promised; a missing or incomplete payload fails validation and requires fresh work. The required interruption proof covers process-holder death with a live cooperative child while the OS remains running, not a machine power-loss simulation.
