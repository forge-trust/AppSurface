# ForgeTrust.AppSurface.Coverage

Portable .NET coverage capture, conservative composition, acceptance, and independent verification. This neutral facade depends on the [private coverage engine](../../Evidence/ForgeTrust.AppSurface.Evidence.Coverage/README.md); it requires neither Aspire nor CLI command workflows. The [fan-in guide](../../guides/coverage-fan-in.md) is the adoption and migration reference, and the [dogfood examples](../../tools/ForgeTrust.AppSurface.Coverage.Dogfood/examples/README.md) show the installed headless proof, generated CLI requests, and Evidence adapter. Use ordinary [coverage merge](../../Cli/ForgeTrust.AppSurface.Cli/README.md#appsurface-coverage-merge) when you only need combined reports; use fan-in when complete inventories, source/run identity and independent acceptance matter.

The packed facade pins `ForgeTrust.AppSurface.Evidence.Coverage` to the exact same coordinated package version using NuGet's `[version]` range. Keep the facade and its private engine on the same release; an open lower bound could let a consumer resolve a different engine version than the facade was built against.

The supported `CoverageFanIn` operations are `CollectAndCaptureAsync`, `CaptureAsync`, `ComposeAsync`, `AcceptAsync`, and read-only `VerifyAsync`. Requests explicitly supply `CoverageFanInPolicy` and a matching clean Git source context. Capture requires either successful normalized producer artifacts and their timing/raw inventory, or an explicit portable-v2 import with its original source-root mapping. Composition requires exactly one primary and the declared supplementary set. Acceptance retains the primary aggregate gate and explicitly selected aggregate-only or aggregate-plus-patch policy. Collection uses the existing supervised VSTest Coverlet collector and the exact package-owned ReportGenerator payload, never an ambient tool/cache fallback.

A `CoverageFanInResult` distinguishes operation outcome, original observation, local import, evaluation intent, exact generation and partial effects. Capture and composition success do not mean coverage acceptance. Matching manifests and hashes establish consistency within a trusted-producer boundary, not signatures or proof that arbitrary supplied tests ran. Import preserves producer origin; historical replay never becomes new execution. Only completed acceptance records acceptance, and the Evidence adapter additionally requires successful current-operation delivery.

Callers own progress and diagnostic writers; operations do not dispose or retain them. All operations accept cancellation. Precommit cancellation publishes no complete generation; output may require inspection. Postcommit cancellation reports the actual committed generation. Fresh output is the default. Explicit replacement requires compatible private registration, physical custody and exact unmodified inventory; unknown, modified or linked material is preserved. Verify creates no directories, coordination or diagnostics files. Legacy v1 verification remains available through the original [Evidence verifier](../../Evidence/ForgeTrust.AppSurface.Evidence.Aspire/README.md); schemas cannot mix and historical captures are not relabeled as fresh.

Policy includes exact slash-relative test project identities (including names without a `.Tests` suffix), exact supplementary IDs/platforms/filters and optional supplementary project inventories, source commit/tree/SDK/configuration, provider-neutral run identity, instrumentation, thresholds, diff intent and operation limits. Collections are frozen and defaults materialized before side effects. Duplicate/aliased project identities are rejected. `CoverageGateMode.AggregateOnly` explicitly reports `PatchNotRequested`; `AggregateAndPatch` requires a diff base, the same frozen diff for both reports, and measurable changed lines. Composition cannot reduce either measurable denominator; a patch with no changed branch conditions retains the gate's 0/0 branch convention. AppSurface dogfooding keeps its complete inventory, Linux/Windows/macOS evidence, 95% line / 85% branch aggregate and patch gates, 0.5-point tolerance and Codecov patch mode.

`CoverageOperationLimits` defaults to 512 MiB/XML, 1 MiB/JSON and other text, 4 GiB total admitted/staged bytes, depth 64, 1,000,000 lines/report, 32 bundles, 8,000,000 XML elements/report, 32 attributes/element, 65,536 decoded token characters, 2,000,000 branch records/report and total retained records/operation, five minutes/operation and 30 seconds/identity process. Retained `diff.patch` uses the Git reader's fixed 20 MiB UTF-8 limit consistently during acceptance, verification and owned replacement, and still counts against the total byte budget. Collection requires its own 1–86,400 second overall deadline. Explicit limits replace defaults as one immutable snapshot; policy limits never lower numeric coverage thresholds. Parsing rejects DTD/entities on v2 wire XML; the controlled normalization boundary strips only the known inert generator declaration while retaining original raw collector bytes.

`coverage-policy-c14n-1` canonicalizes the typed policy as ordinal properties and set identities, explicit defaults/nulls, valid decoded Unicode without NFC folding, invariant minimal decimal values (0–100, at most six fractional places), UTF-8 without BOM/whitespace. The SHA-256 input is the encoding version plus a newline followed by those bytes. Paths must be normalized slash-relative identities; arbitrary JSON lexical forms do not change policy meaning.

Prerequisites are a supported .NET 10 SDK, Git, consumer-owned test SDK/collector packages, and a supported native filesystem. Single-file, trimming and AOT are not established support claims. The current acceptance target is AppSurface dogfooding; separate downstream consumer validation and onboarding measurements are deferred by user direction.

## Request and result reference

Choose `CollectAndCaptureAsync` when this process should supervise test execution; choose `CaptureAsync` when a trusted producer already has successful artifacts or when explicitly materializing a portable v2 capture. Use `ComposeAsync` to produce a conservative combined view, `AcceptAsync` to run the selected gates and independent checks, and `VerifyAsync` to recheck an existing generation without changing local state. A caller that needs only a merged report should use `coverage merge`; a caller that needs EvidenceHost to close an obligation should use the shipped [Evidence producer](../../Evidence/ForgeTrust.AppSurface.Evidence.Aspire/README.md#coverage-fan-in-producer).

```csharp
var result = await CoverageFanIn.CollectAndCaptureAsync(
    new CoverageCollectRequest(
        policy,
        repositoryRoot,
        freshCaptureDirectory,
        freshCollectionDirectory,
        ProducerId: "primary",
        DeadlineSeconds: 900,
        SolutionPath: solutionPath),
    cancellationToken,
    progress,
    diagnostics);

if (result.Outcome != CoverageOperationOutcome.Succeeded)
    throw new InvalidOperationException($"Coverage collection ended as {result.Outcome}.");
// Collection success records the observed producer operation. It does not accept coverage.
```

This example deliberately takes the policy, repository and fresh destinations as caller values. Do not substitute illustrative hashes or host paths; obtain source commit/tree/SDK from the real clean checkout and use a unique run identity. The remaining operation calls, native import, and a packed-fixture command are in the [examples](../../tools/ForgeTrust.AppSurface.Coverage.Dogfood/examples/README.md).

| Contract | Meaning and constraints |
| --- | --- |
| `CoverageSourceIdentity` | Exact lowercase Git commit/tree object IDs (40 or 64 hex characters), selected SDK version and explicit configuration. The local source must match and be clean, including untracked source files. Declared primary and supplementary projects must be tracked regular files in the pinned repository or its pinned submodules. |
| `CoverageRunIdentity` | Explicit producer system, run scope, run ID and positive attempt. Text fields are bounded to 256 characters, exclude controls/format characters, and must contain no credentials. |
| `CoverageSupplement` | Unique bounded portable ID, actual platform and explicit test filter (up to 4096 characters); optional nonempty test-project set selects the supplementary collector inventory. Omission uses the complete intended primary inventory. |
| `CoverageInstrumentation` | Supported collector/cobertura normalization identity. Include defaults to null; exclude defaults to `[*.Tests]*,[*.IntegrationTests]*`. Filter values are bounded to 4096 characters. These are consumer settings, not authority to change AppSurface's configured scope. |
| `CoverageGatePolicy` | Explicit mode. Percentage values are lossless decimals in 0–100 with at most six fractional places. Defaults are 95 line/85 branch for aggregate and patch, tolerance 0.5 and `codecov`. AggregateAndPatch requires a nonblank Git revision; option-like bases beginning with `-` are rejected before execution. AggregateOnly requires null. |
| `CoverageCollectRequest` | Explicit fresh collection and capture outputs, producer ID and 1–86,400-second deadline. Parallelism defaults to 1. Collection rebuilds the declared projects before testing; `NoBuild` must be false. It rejects ignored files except standard `bin/` and `obj/` directories beside tracked .NET projects. Set `NoRestore` only with trusted restore outputs. `SolutionPath` does not replace or expand the explicit inventory. See the [checkout prerequisites](../../guides/coverage-fan-in.md#c-operations-and-ordering). |
| `CoverageCaptureRequest` | Explicit normalized report plus primary timings or a single-project native raw report. For multiple native projects supply `RawCoveragePaths` (exact project-to-original-report paths) and complete `TimingsPath`; omit both `CoveragePath` and `RawCoveragePath`. Import instead declares a portable capture and exact original source root, with no conflicting report selectors. Fresh is default; `ReplaceOwned` is explicit. |
| `CoverageComposeRequest` | Primary, exact supplementary directory list and distinct output; Fresh and CurrentTrustedRun defaults. |
| `CoverageAcceptRequest` | The same captures, exact composed output and distinct acceptance destination. In patch mode, optional `ExpectedPatchSha256` pins the exact Git patch before either gate runs. The [EvidenceHost producer](../../Evidence/ForgeTrust.AppSurface.Evidence.Aspire/README.md#coverage-fan-in-producer) supplies that pin from its plan. Only a successful independent gate sequence creates accepted coverage. |
| `CoverageVerifyRequest` | Existing captures, composition and acceptance destination. Read-only validity uses explicit CurrentTrustedRun or HistoricalReplay intent. |
| `CoverageFanInResult` | Requested operation/outcome/operation ID/policy digest, actual effects, bounded diagnostics and retained role/hash references. `Accepted`, `Verified`, original `Observation`, evaluation intent and patch outcome have separate meanings. For compose, accept and verify, `PrimaryImported` indicates a primary materialized from transport; `Effects.Imported` indicates that any input was imported. |

Limit overrides replace their typed field defaults before freezing the policy. XML/JSON byte bounds are positive and at most 2,147,483,647 bytes; total admitted/staging bytes are positive and at most 1 TiB. Depth is 1–256, bundle count 1–1024, noncollection seconds 1–86,400 and identity seconds 1–300. Other count/token bounds are positive 32-bit integers. Primary inventories admit at most 10,000 projects; native inventories admit at most 9,995, reserving five entries in the unchanged 10,000-file storage inventory for coverage, timings, index, manifest and completion marker. Inventories reject case/Unicode-normalization aliases while preserving the original valid scalar spelling in canonical bytes. Relative project components reject traversal, reserved device names, trailing dots/spaces and platform-invalid characters.

Native collection supports the complete supplementary project set, including omission of `CoverageSupplement.TestProjects` to select the primary set. For multiple projects it retains byte-exact originals as `collector-0000.cobertura.xml`, `collector-0001.cobertura.xml`, and so on, plus successful `timings.json` and `collector-inventory.json`. The index has `schemaVersion: 1` and a `reports` array of `{ "project": "checks/Example.csproj", "file": "collector-0000.cobertura.xml" }` records in ordinal project order. The capture remains schema v2. Its manifest hashes every retained file. The native coverage projection composes original collector class/method records conservatively; independent verification derives it again from those originals on import, composition, acceptance and verification. Missing, duplicate or reordered project/file mappings, incomplete timings and unknown files are rejected. A one-report capture cannot satisfy a multiple-project declaration. Single-project captures retain their existing raw/normalized format and checks. See the [portable input contract](../../guides/coverage-fan-in.md#portable-inputs-replay-and-replacement) and [API examples](https://github.com/forge-trust/AppSurface/blob/main/tools/ForgeTrust.AppSurface.Coverage.Dogfood/examples/CoverageFanInApiExample.cs).

Original collector summaries may include compiler branches absent from their serialized class records. Indexed capture preserves these summaries in each original file and range-checks their counters; its projected totals derive from the full retained serialized class points. Independent verification also retains every method point and checks the complete class/method identities, occurrences, hit facts and conservative branch combination. Missing serialized points are never explained away as summary differences. The separate primary aggregate gate continues to use the exact original normalized primary summary, as explained in the [measurement contract](../../guides/coverage-fan-in.md#historical-v1-evidence).

Supervised native attachment discovery admits at most 10,000 filesystem entries across the complete project set, applies the policy depth limit to each invocation tree and charges timings plus selected original bytes to the operation byte budget. Large diagnostic trees can exhaust this resource limit even when the declared project count is valid. Selection-time hashes for timings and every original report are checked again under retained capture IO before publication; changed evidence is rejected without publishing a complete capture.

Expected input/evidence failures return bounded stable reasons. Invalid C# request/policy shapes throw `ArgumentException` before side effects; malformed CLI envelopes exit 2. Caller cancellation and deadlines produce typed terminal outcomes, with actual partial output effects. Unexpected dependency details and raw logs are not an acceptance oracle and are not copied into safe diagnostics. See [diagnostics and recovery](../../guides/coverage-fan-in.md#diagnostics).

Supervised fan-in collection emits bounded stage progress to caller writers. Arbitrary test/child-process output and absolute host paths remain in the explicitly selected collection artifacts. Inspect those retained logs locally when collection fails; terminal diagnostics do not copy them. Normalization input and generated-file growth use the declared budgets, and serialized XML is limited before output-buffer growth.
