### Prepare an application handoff under live PostgreSQL Durable authority — issue #869

The PostgreSQL provider adds a scoped `IDurableWorkHandoffFence` for a running Work executor to revalidate current native invocation authority and write application-owned authorization/ledger state in the caller's exact `ReadCommitted` transaction. Preparation remains provisional until the caller commits; callback denial removes callback writes, and the caller releases the transaction and connection before provider I/O.

Use the [handoff contract](../../Durable/handoff-fence.md), [package entry point](../../Durable/ForgeTrust.AppSurface.Durable.PostgreSql/README.md#prepare-an-application-handoff), and [canonical Durable diagnostics catalog](../../troubleshooting/durable-diagnostics.md) for eligibility, lock order, cleanup, host timeout ownership, cause-to-action refusal guidance, and uncertain-commit recovery. The contract records the repository-pinned Npgsql 10.0.3 `SaveAsync` behavior: the SAVEPOINT is queued with the next command, so method completion alone is not server acknowledgement.
