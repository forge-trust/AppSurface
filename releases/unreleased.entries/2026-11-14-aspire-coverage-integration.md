### Aspire security baseline update

The coordinated Aspire minimum for the AppHost SDK, `Aspire.Hosting`, and `Aspire.Hosting.Testing` is **13.6.5**, which includes the fix for [GHSA-f7vh-h5g3-7jrh](https://github.com/advisories/GHSA-f7vh-h5g3-7jrh). The [Aspire integration](../../Aspire/ForgeTrust.AppSurface.Aspire/README.md#dependency-security) has no Aspire CLI NuGet dependency. Strict NuGet vulnerability auditing remains enabled. Aspire 13.6.5 requires Microsoft.Extensions.Hosting and Microsoft.Extensions.DependencyInjection **10.0.14** and MessagePack **2.5.307**. Historical 13.4.4 and 13.4.6 consumer evidence does not establish 13.6.5 compatibility. Both current packed-consumer journeys verify 13.6.5; later versions remain allowed by the open-ended minimum but unverified and require compatibility proof.

The [central dependency graph](../../Directory.Packages.props) also advances Aspire.Hosting.Keycloak to **13.6.5-preview.1.26559.7**, Aspire.Hosting.PostgreSQL to **13.6.5**, the pinned Microsoft.Extensions packages to **10.0.14**, OpenTelemetry packages to **1.17.0**, and YamlDotNet to **18.1.0**. The [Cloud Tasks transport](../../Durable/ForgeTrust.AppSurface.Durable.CloudTasks/README.md) pin for Grpc.Net.Client advances to **2.83.0** to keep shared graphs aligned. These central pins also raise dependency floors in non-Aspire packages that consume them; preserve these minimums in consumer overrides.

The [CLI bundle trust boundary](../../Aspire/ForgeTrust.AppSurface.Aspire/README.md#native-deployment-pipeline) is separate from the application NuGet graph: DCP and Dashboard are version-pinned through the SDK's CLI selection, not hash-pinned or audited as RID-specific application NuGet packages. AppHost examples select the SDK-paired bundle. NuGet auditing, failed-build cleanup assertions, required checks, and coverage gates remain enabled.

The [Durable worker template](../../Durable/ForgeTrust.AppSurface.Durable.Templates/README.md) coordinates its OpenTelemetry pins with the upgraded package graph, preserving strict restore of generated consumers. The [historical compatibility consumers](../../Durable/compatibility/README.md) retain their exact published dependency graph through local central pins, so current dependency upgrades do not change the old-version proof; locked restore, audit, and compatibility assertions remain enabled.

Full-solution CI workers, including package producers and the release documentation exporter, prepare the SDK-paired CLI bundle before parallel builds, with visible setup diagnostics and unchanged build, formatting, native-readiness, and coverage requirements. Existing frozen-producer recovery conditions still control whether package producers run.

The [contributor and CI toolchain](../../CONTRIBUTING.md#local-setup) explicitly selects SDK **10.0.402** with roll-forward disabled. CI installs the pin in a job-owned SDK directory so preinstalled newer major SDKs cannot change repository builds or isolated consumer proofs. Coverage gates and required checks are unchanged.
