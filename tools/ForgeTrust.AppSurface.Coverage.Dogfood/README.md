# AppSurface coverage dogfood adapter

This repository-specific configuration adapter supplies the complete AppSurface solution inventory and exact Linux/Windows/Darwin native policy to the installed [fan-in commands](../../guides/coverage-fan-in.md#installed-commands-and-request-schema). It contains no capture, composition, gate, verification or cleanup implementation. Consumers use the [neutral Coverage API](../../Coverage/ForgeTrust.AppSurface.Coverage/README.md) or installed CLI directly.

Run `dotnet run --project tools/ForgeTrust.AppSurface.Coverage.Dogfood -- --help` for explicit arguments. A native invocation declares `--operation native`, the actual platform, `--raw-index` with an exact project-to-original-report JSON mapping, and `--timings` from the successful two-project collection. The [build workflow](https://github.com/forge-trust/AppSurface/blob/main/.github/workflows/build.yml) uses installed `coverage run` with full artifact retention; each per-project `coverageFile` is a byte-exact staged copy of its original collector attachment. The indexed [capture contract](../../Coverage/ForgeTrust.AppSurface.Coverage/README.md#request-and-result-reference) requires the complete declared inventory and successful timings; missing, duplicate, failed, or additional projects cannot be substituted. Native measurements come from original class/method records; see the [canonical native projection and capture compatibility](../../Coverage/ForgeTrust.AppSurface.Coverage/README.md#request-and-result-reference). A receiving invocation declares `--operation fanin`, the complete primary report/timings and downloaded native input directory. Both provide the matching source repository, installed CLI executable, fresh output parent, configuration and explicit provider-neutral run scope/ID/attempt. An explicit diff base selects aggregate-plus-patch; absence deliberately selects the aggregate-only baseline. No environment variable silently discovers run identity.

The adapter defaults to exact version-2 executable JSON envelopes; `--contract-version 3` opts into a fresh v3 capture/replay using the `coverlet-collector-cobertura-v1` report profile and a base resolved once to a full commit ID before policy freeze. The request writer uses an explicit versioned policy projection, omitting v3 fields from v2 JSON. A v3 patch request derives `ExpectedPatchSha256` from the canonical bytes returned by the same diff context used by the installed engine. Before assigning the v3 profile, the adapter verifies the evaluated `coverlet.collector` 10.0.1 package for every selected project/framework and records that exact version in its proof. V3 also requires the installed CLI to accept and independently verify complete patch applicability and records run/source identity and bounded-operation measurements in `shadow-proof.json`. These measurements qualify the new implementation while v2 remains the repository measurement contract. The additive v3 qualification steps must pass in this change; their failure blocks qualification rather than falling back to v2. Repository N/A enablement still requires complete native, selected-producer and budget proof. Memory sampling is best effort while processes are alive: unavailable or zero-valued peaks are explicit null, never a measured zero or a reason to fail an otherwise successful command. A null observation does not complete the memory proof. Each writing operation has an explicit fresh result destination. Nonzero commands fail the current adapter; retained result files explain actual partial effects. Outputs stay outside tracked source so source cleanliness is independently verifiable. Preserve existing output and select a fresh root after refusal; the adapter never removes it.

Downloaded manifest discovery uses the private engine's native no-follow reader before any output is created. It scans at most 10,000 total entries and 64 directory levels, reads at most 1 MiB per manifest, and requires exactly one manifest for each expected native producer. Linked, malformed, oversized, duplicate or missing inputs fail discovery. Those selectors grant no ownership or execution assurance: installed capture/import still independently validates the full source/run/policy and retained artifact set under the [transport contract](../../guides/coverage-fan-in.md#portable-inputs-replay-and-replacement).

The optional Unix [gate wrapper](https://github.com/forge-trust/AppSurface/blob/main/scripts/coverage-gate-fanin.sh) additionally invokes installed `coverage gate` commands to preserve the existing CI report paths: `aggregate-gate/coverage-gate.json` and `.md` for the primary aggregate, and `coverage-gate.json`, `.md`, and `coverage-patch-targets.json`/`.md` at the coverage root when patch coverage is requested. Inputs remain in the separate composed generation. A numeric rejection still publishes its failure reports and returns failure; an earlier capture/composition refusal does not run these reporting invocations. These reports supplement the immutable native acceptance generation and do not substitute for its independent verification.

AppSurface explicitly sets a 4,000,000-record operation budget: a measured replay of its full primary report plus three raw/normalized supplements exceeded the reusable 2,000,000-record default. This resource setting does not change coverage thresholds, instrumentation or inventory. The native filter retains the existing CLI coverage filesystem/security/gate/storage, process-contract, collector-version preflight, fan-in and Evidence families, and adds seven class-qualified Aspire families: host, prepared-run, key-material execution, key-material failure, reuse package proof, packed reuse journey and native validation program. Both the Aspire and CLI test projects are required in each native capture. Their original method and state-machine branch observations prevent incidental CLI-only coverage of host and validation code from standing in for those components' dedicated tests. A composed patch gate can still reject partial observations; complete matching-denominator coverage must be measured. Native captures identify that exact filter and two-project inventory; supplements do not replace missing or failed primary projects. Every operation retains 95% line/85% branch aggregate and patch thresholds, the existing 0.5-point tolerance, Codecov patch mode and instrumentation exclusions.

The current scope is AppSurface dogfooding. Separate downstream consumers and their onboarding measurements were deferred by the user; successful fixture or dogfood execution must not be described as downstream adoption proof.

## Installed library proof

The adapter's `--package-proof --feed <candidate-feed> --version <exact> --output <fresh-root> --dotnet <absolute-host>` mode checks the public Coverage and private support candidate package identities, creates an isolated PackageReference application, restores first-party packages only from that candidate feed, and rejects Aspire/CliFx/Planner in the headless graph. It builds and publishes the application and executes capture/composition/acceptance/verification plus altered-output rejection from both layouts. Stage logs and a package-hash-bound proof remain in the explicit output root. It does not publish packages, delete outputs, establish downstream adoption, or replace full source/native gates. The [native validation workflow](https://github.com/forge-trust/AppSurface/blob/main/.github/workflows/native-evidence-validation.yml) invokes this proof on all three OSes.

The installed fixture declares two native test projects, supervises both collections and checks the byte-exact per-project original reports, complete successful timings and ordered index. It exercises existing-artifact indexed capture through the [public API example](https://github.com/forge-trust/AppSurface/blob/main/tools/ForgeTrust.AppSurface.Coverage.Dogfood/examples/CoverageFanInApiExample.cs), then imports the portable native set through both the public API and installed CLI before composition, acceptance and read-only verification. The [native input reference](../../Coverage/ForgeTrust.AppSurface.Coverage/README.md#request-and-result-reference) explains indexed capture selectors for one or more projects and conservative projection. Running the fixture on one host establishes only that host's result; the native matrix must independently pass on each required OS.
