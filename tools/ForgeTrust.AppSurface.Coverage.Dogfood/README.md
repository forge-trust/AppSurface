# AppSurface coverage dogfood adapter

This repository-specific configuration adapter supplies the complete AppSurface solution inventory and exact Linux/Windows/Darwin native policy to the installed [fan-in commands](../../guides/coverage-fan-in.md#installed-commands-and-request-schema). It contains no capture, composition, gate, verification or cleanup implementation. Consumers use the [neutral Coverage API](../../Coverage/ForgeTrust.AppSurface.Coverage/README.md) or installed CLI directly.

Run `dotnet run --project tools/ForgeTrust.AppSurface.Coverage.Dogfood -- --help` for explicit arguments. A native invocation declares `--operation native` and the actual platform. The [build workflow](https://github.com/forge-trust/AppSurface/blob/main/.github/workflows/build.yml) passes the output of installed `coverage run` with full artifact retention as `--collection-root`. The adapter uses the project entries in `timings.json` to find each per-project `coverageFile`, a byte-exact staged copy of the original collector attachment. An explicit replay supplies `--raw-index` with an exact project-to-original-report JSON mapping and the matching `--timings`. The indexed [capture contract](../../Coverage/ForgeTrust.AppSurface.Coverage/README.md#request-and-result-reference) requires the complete declared inventory and successful timings; missing, duplicate, failed, or additional projects cannot be substituted. Native measurements come from original class/method records; see the [canonical native projection and capture compatibility](../../Coverage/ForgeTrust.AppSurface.Coverage/README.md#request-and-result-reference). A receiving invocation declares `--operation fanin`, the complete primary report/timings and downloaded native input directory. Both provide the matching source repository, installed CLI executable, fresh output parent, configuration and explicit provider-neutral run scope/ID/attempt. An explicit diff base selects aggregate-plus-patch; absence deliberately selects the aggregate-only baseline. No environment variable silently discovers run identity.

Each Keycloak ARM64 lane uses observed collection on its native host. Pass `--contract-version 3 --include-keycloak-native true --native-producer <id> --collection <fresh-directory>` with the corresponding platform. The macOS ARM64 producer declares both the Aspire adapter and Auth.Keycloak test projects, with one OR filter covering their complete test namespaces. The Linux ARM64 producer retains the Aspire adapter project and its worker-only filter. The same declared project list feeds the supplement policy and collector-version preflight. The fan-in invocation selects `--include-keycloak-native true` and `--primary-compiler-symbols <same-run-directory>` for the same run. The [compiler-qualified async profile](../../guides/coverage-fan-in.md#compiler-qualified-async-pairing) retains the tested compiler symbols in the immutable capture.

The AppSurface build selects the [screenshot diff policy](../../guides/coverage-fan-in.md#screenshot-baseline-updates) for every selected native capture and the receiving job. For a standalone replay using the same policy, pass `--contract-version 3 --diff-policy-id appsurface-visual-baseline-png-v1` to every invocation. Omit `--diff-policy-id` to use the strict text policy.

The adapter defaults to exact version-2 executable JSON envelopes; its existing `--contract-version 3` option remains an explicit v3 opt-in for standalone callers. V3 uses the `coverlet-collector-cobertura-v1` report profile and freezes a full commit ID before policy selection. The request writer uses an explicit versioned policy projection, omitting v3 fields from v2 JSON. A v3 patch request derives `ExpectedPatchSha256` from the canonical bytes returned by the same diff context used by the installed engine. Before assigning the v3 profile, the adapter verifies the evaluated `coverlet.collector` 10.0.1 package for every selected project/framework and records that exact version in its proof. V3 requires the installed CLI to accept the fan-in and independently verify it read-only; run/source identity and bounded-operation measurements are recorded in `shadow-proof.json`.

The checked-in repository PR-native path uses the Evidence Validation tool's `--native-coverage-contract-version 3` setting with the full pinned event PR base and fresh captures from the current workflow attempt. A closed shared producer inventory defines the three baseline captures and, for selected Keycloak PRs, the macOS ARM64 adapter and Linux ARM64 worker captures. The same records drive the workflow matrix, expected producer set/cardinality, and Dogfood supplement project/filter policy. Acceptance still independently checks each actual manifest's source, SDK, base, run, attempt, project/filter, architecture, and gate policy. The producer retains and checks typed patch applicability, bound diff, acceptance receipt and separate verification result. A reported `notApplicable` dimension means only that the accepted collector reported no patch points for it; it does not prove that changed source has no executable code or permit reducing the declared test/producer inventory. A failed v3 acceptance or verification blocks that selected path rather than falling back to a v2 claim. Thresholds, tolerance, instrumentation and required jobs remain unchanged; v2 defaults and historical behavior remain in place. See the [v3 rollout and collector trust boundary](../../guides/coverage-fan-in.md#rollout-qualification) for deployment qualification requirements and status.

The adapter's `shadow-proof.json` memory sample is best-effort process telemetry and can be `null` on Darwin, as observed in earlier shadow runs. `null` means unavailable, not zero, and does not complete the memory proof. For PR v3 native captures on macOS, `build.yml` runs the Dogfood command under `/usr/bin/time -l` and writes the parsed maximum resident set size to `darwin-rss.json`. That workflow measurement is separate from `shadow-proof.json`; it does not populate or reinterpret the receipt field. Each writing operation has an explicit fresh result destination. Nonzero commands fail the current adapter; retained result files explain actual partial effects. Outputs stay outside tracked source so source cleanliness is independently verifiable. Preserve existing output and select a fresh root after refusal; the adapter never removes it.

Downloaded manifest discovery uses the private engine's native no-follow reader before any output is created. It scans at most 10,000 total entries and 64 directory levels, reads at most 1 MiB per manifest, and requires exactly one manifest for each expected native producer. Linked, malformed, oversized, duplicate or missing inputs fail discovery. Those selectors grant no ownership or execution assurance: installed capture/import still independently validates the full source/run/policy and retained artifact set under the [transport contract](../../guides/coverage-fan-in.md#portable-inputs-replay-and-replacement).

When native capture fails, the adapter reports `ASCOV311` with the operation stage and a code or exception type. A typed failure during pinned diff validation includes the [safe recovery guidance](../../guides/coverage-fan-in.md#budgets-diagnostics-and-maintainer-recovery) in the job log. The [build workflow](https://github.com/forge-trust/AppSurface/blob/main/.github/workflows/build.yml) uploads `coverage-capture-failure-<producer-id>-<attempt>` with any retained `native-result.json` and the macOS timing log when available. The timing log shows why maximum RSS qualification failed even after a successful native capture.

The optional Unix [gate wrapper](https://github.com/forge-trust/AppSurface/blob/main/scripts/coverage-gate-fanin.sh) additionally invokes installed `coverage gate` commands to preserve the existing CI report paths: `aggregate-gate/coverage-gate.json` and `.md` for the primary aggregate, and `coverage-gate.json`, `.md`, and `coverage-patch-targets.json`/`.md` at the coverage root when patch coverage is requested. Inputs remain in the separate composed generation. A numeric rejection still publishes its failure reports and returns failure; an earlier capture/composition refusal does not run these reporting invocations. These reports supplement the immutable native acceptance generation and do not substitute for its independent verification.

AppSurface explicitly sets a 4,000,000-record operation budget: a measured replay of its full primary report plus three raw/normalized supplements exceeded the reusable 2,000,000-record default. This resource setting does not change coverage thresholds, instrumentation or inventory. The native filter retains the existing CLI coverage filesystem/security/gate/storage, process-contract, collector-version preflight, fan-in and Evidence families, and adds seven class-qualified Aspire families: host, prepared-run, key-material execution, key-material failure, reuse package proof, packed reuse journey and native validation program. Both the Aspire and CLI test projects are required in each baseline native capture. Their original method and state-machine branch observations prevent incidental CLI-only coverage of host and validation code from standing in for those components' dedicated tests. A composed patch gate can still reject partial observations; complete matching-denominator coverage must be measured. Native captures identify that exact filter and two-project inventory; supplements do not replace missing or failed primary projects. Every operation retains 95% line/85% branch aggregate and patch thresholds, the existing 0.5-point tolerance, Codecov patch mode and instrumentation exclusions.

The [ordered project inventory](https://github.com/forge-trust/AppSurface/blob/dea581f6e39ca8b3c7ea1d89cc4d61b37a86ba49/.github/workflows/native-coverage-test-projects.txt) supplies the build workflow's locked restore and collection projects and the adapter's expected attestation projects. Each line is a repository-relative test project path. The report index must contain one original collector report for every declared project.

The adapter embeds the [ordered selector inventory](https://github.com/forge-trust/AppSurface/blob/8c0d4e165a5a83672e065fc7c72bd0f9963a1645/.github/workflows/native-coverage-test-selectors.txt) for test selection and attestation. Once the adapter is built, pass `--print-test-filter native` for the complete native coverage filter, `--print-test-filter lifecycle-cli` for the native lifecycle workflow's CLI filter, or `--print-test-filter shared-cli` for the terms used by both lanes. Each command writes its filter to standard output. Lifecycle-specific rows precede shared rows in the lifecycle filter. Keep the row order because native filter order contributes to coverage policy identity.

The current scope is AppSurface dogfooding. Separate downstream consumers and their onboarding measurements were deferred by the user; successful fixture or dogfood execution must not be described as downstream adoption proof.

## Installed library proof

The adapter's `--package-proof --feed <candidate-feed> --version <exact> --output <fresh-root> --dotnet <absolute-host>` mode checks the public Coverage and private support candidate package identities, creates an isolated PackageReference application, restores first-party packages only from that candidate feed, and rejects Aspire/CliFx/Planner in the headless graph. It builds and publishes the application and executes capture/composition/acceptance/verification plus altered-output rejection from both layouts. Stage logs and a package-hash-bound proof remain in the explicit output root. It does not publish packages, delete outputs, establish downstream adoption, or replace full source/native gates. The [native validation workflow](https://github.com/forge-trust/AppSurface/blob/main/.github/workflows/native-evidence-validation.yml) invokes this proof on all three OSes.

Before creating output, package admission requires exactly one private dependency pin in every declared
framework group, or one in an ungrouped declaration. Use the canonical package ID casing and the closed
range `[<exact-version>]`. Identical duplicates and pins outside the framework groups fail admission with
`coverage.private-dependency-invalid`. The [packed reuse proof](../ForgeTrust.AppSurface.Evidence.Validation/README.md) applies the same pin rule.

The [candidate catalog](../ForgeTrust.AppSurface.Evidence.Validation/PackedCandidatePackages.cs) supplies the
neutral library set for packing, admission, restored archive verification, and asset checks. Admission reads
each archive into a snapshot capped at 512 MiB and uses those bytes for both NuSpec validation and SHA-256.
The shared reader caps decompressed NuSpecs at 1 MiB and prohibits DTDs. A malformed or oversized NuSpec
is rejected before output creation with `coverage.candidate-nuspec-invalid`. Restore then checks the
private cache against the recorded archive digests.

Each child stage has a five-minute deadline and a 1 Mi-character capture limit per stream. The shared
package proof runner observes the child and both streams together, waits for cleanup after interruption,
and retains up to 2 Mi characters of redacted output in the stage log. A startup marker alone records only the launch attempt.

The build workflow stages all eight candidate archives together on each native runner after the locked restore. The packed reuse journey verifies the archive graph and bundled DLLs, then restores the consumers in isolation. To use a prepared feed in a standalone test, set both `APPSURFACE_PACKED_JOURNEY_FEED` to its absolute path and `APPSURFACE_PACKED_JOURNEY_VERSION` to the exact version in all eight archives. Leave both variables unset to pack a fresh feed in the test.

The installed fixture declares two native test projects, supervises both collections and checks the byte-exact per-project original reports, complete successful timings and ordered index. It exercises existing-artifact indexed capture through the [public API example](https://github.com/forge-trust/AppSurface/blob/main/tools/ForgeTrust.AppSurface.Coverage.Dogfood/examples/CoverageFanInApiExample.cs), then imports the portable native set through both the public API and installed CLI before composition, acceptance and read-only verification. The [native input reference](../../Coverage/ForgeTrust.AppSurface.Coverage/README.md#request-and-result-reference) explains indexed capture selectors for one or more projects and conservative projection. Running the fixture on one host establishes only that host's result; the native matrix must independently pass on each required OS.
