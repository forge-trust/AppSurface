# AppSurface coverage dogfood adapter

This repository-specific configuration adapter supplies the complete AppSurface solution inventory and exact Linux/Windows/Darwin native policy to the installed [fan-in commands](../../guides/coverage-fan-in.md#installed-commands-and-request-schema). It contains no capture, composition, gate, verification or cleanup implementation. Consumers use the [neutral Coverage API](../../Coverage/ForgeTrust.AppSurface.Coverage/README.md) or installed CLI directly.

Run `dotnet run --project tools/ForgeTrust.AppSurface.Coverage.Dogfood -- --help` for explicit arguments. A native invocation declares `--operation native`, the actual platform, normalized report and retained original collector bytes. A receiving invocation declares `--operation fanin`, the complete primary report/timings and downloaded native input directory. Both provide the matching source repository, installed CLI executable, fresh output parent, configuration and explicit provider-neutral run scope/ID/attempt. An explicit diff base selects aggregate-plus-patch; absence deliberately selects the aggregate-only baseline. No environment variable silently discovers run identity.

The adapter writes exact version-2 executable JSON envelopes and invokes installed commands in capture/import/compose/accept/verify order. Each writing operation has an explicit fresh result destination. Nonzero commands fail the current adapter; retained result files explain actual partial effects. Outputs stay outside tracked source so source cleanliness is independently verifiable. Preserve existing output and select a fresh root after refusal; the adapter never removes it.

AppSurface explicitly sets a 4,000,000-record operation budget: a measured replay of its full primary report plus three raw/normalized supplements exceeded the reusable 2,000,000-record default. This resource setting does not change coverage thresholds, instrumentation or inventory. The native filter includes the existing coverage filesystem/security/gate/storage families plus the new fan-in regressions. Native captures identify that exact filter and their explicit CLI-test project inventory; supplements do not replace missing or failed primary projects. Every operation retains 95% line/85% branch aggregate and patch thresholds, the existing 0.5-point tolerance, Codecov patch mode and instrumentation exclusions.

The current scope is AppSurface dogfooding. Separate downstream consumers and their onboarding measurements were deferred by the user; successful fixture or dogfood execution must not be described as downstream adoption proof.

## Installed library proof

The adapter's `--package-proof --feed <candidate-feed> --version <exact> --output <fresh-root> --dotnet <absolute-host>` mode checks the public Coverage and private support candidate package identities, creates an isolated PackageReference application, restores first-party packages only from that candidate feed, and rejects Aspire/CliFx/Planner in the headless graph. It builds and publishes the application and executes capture/composition/acceptance/verification plus altered-output rejection from both layouts. Stage logs and a package-hash-bound proof remain in the explicit output root. It does not publish packages, delete outputs, establish downstream adoption, or replace full source/native gates. The [native validation workflow](../../.github/workflows/native-evidence-validation.yml) invokes this proof on all three OSes.
