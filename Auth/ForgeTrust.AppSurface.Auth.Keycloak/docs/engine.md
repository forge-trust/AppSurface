# Engine and internal decision guide

The public boundary is deliberately small. `Validation` checks closed recipe shape, canonical paths, supported platform/profile/template families, operation ordering, exact material references, and maximum resource values before effects. `Canonical` is the sole recipe/policy identity serializer and strict reader. Do not use a general JSON serializer for canonical recipe or policy bytes.

`SnapshotStore` copies caller material into private verified snapshots, records file hashes and lengths, and exposes an accepted lease. `CapturedKeycloakPlan` owns the read-only plan handle; `Materialization` and `Inspection` enter that lease before copying accepted inputs. Disposal prevents new consumers but does not delete caller-owned snapshots.

`MaterialAcquisition` allows only approved canonical HTTPS origins and namespaces and exact digests. Host-captured bindings may have an empty URI only when the material is explicitly declared as captured. `OciLayout` proves index and manifest graph identity. `OciReader` enforces archive, blob, layer, path, symlink, payload, and targeted-selection budgets. The original embedded CLI is selected to a bounded private file so module verification does not rely on a large in-memory aggregate. Theme inspection hashes each actual declared theme file, rather than trusting only the image-level binding.

`CaptureVerification` checks original source paths against retained source bytes, replacement Maven metadata against explicit coordinates (a missing POM requires the recognized implementation version or the closed Bouncy Castle bundle-version mapping), and embedded original module identities from the selected original CLI. `ArchiveTransformer` changes only the reviewed archive classes, services, and versioned resources and preserves the source manifest and rejects unsupported signatures. `SignedRepository` verifies the approved OpenPGP Release, signed SHA256 table, complete compressed package-index hash and size, requested package tuples, and package dependency facts. `DebPayloadReader` verifies package payload hashes and safe tar paths.

`ContextMaterialization` writes an offline Docker context with an identity manifest and explicit runtime/frontend OCI build contexts. `KeycloakBuildContext` revalidates that context immediately before the host invokes Docker. `DockerInspection` exports only the declared read-only evidence and probes the supplied immutable image. `RuntimeConformance` compares the observed runtime against signed package payloads, dpkg policy, removals, user, certificates, and helper files. `Diagnostics` maps raw causes to safe enum codes, phase, effect, recovery, next action, and correlation ID; raw exceptions and machine paths stay out of the public message.

The internal phases are Validation, Acquisition, Capture, Materialization, Archive, Publication, Build, Inspection, Probe, Evidence, Cancellation, and Cleanup. The safe public phase is evidence for operators; it is not a promise that every phase ran. A failure before a returned plan or context must be treated as unsuccessful even if a private staging directory existed.

The engine intentionally does not include an image publisher, a shell command builder, a package chooser, a remote approval flow, or a security-policy upgrader. Those boundaries remain host-owned and are the reason this package can be used as a migration sample without turning an old tuple into a new security decision.

The internal `DockerInspectionCommand` argument seam is exposed only to the two friend test assemblies. Tests supply deterministic command observations and independently generated OCI bytes to verify immutable handoff, cleanup and comparison branches. Public entry points always execute the bounded Docker adapter. `InspectCoreAsync` shares the complete inspection implementation with the public wrapper; neither seam is a public extension or caller-supplied passing-evidence path.

`ArchiveTransformer.TryDelete` is an internal seam for verifying owned staging-file cleanup against the real filesystem without reflection. Callers supply only engine-created staging-file paths. Cleanup tolerates missing files, I/O failures, and access failures; invalid path arguments and unexpected programming errors propagate to the caller's diagnostic boundary. Keep this best-effort cleanup separate from archive validation and publication, whose failures must still reject the operation.

`ArchiveTransformer` copies and hashes each source or replacement archive once into an owned file before parsing it. Only a copy whose digest matches the declaration is retained, and the transformer removes those copies after success or rejection. [Temporary disk accounting](host-prerequisites.md) charges those verified copies and output writes without an extra discarded source copy. `OciReader` keeps each selected file's output stream open for its bounded hash/copy loop, then closes it before publication; empty selected files are retained, and a failed bound or digest check leaves the output directory unpublished.

`ContextMaterialization.TryDelete` is the corresponding internal seam for an owned staging directory. It recursively deletes that directory, tolerates missing paths, I/O failures and access failures, and propagates invalid arguments or unexpected programming errors. It must receive only invocation-owned staging paths; cleanup never authorizes deleting the caller's inputs or a published context.
