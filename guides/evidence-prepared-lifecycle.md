# Prepared Evidence lifecycle inventory

This is a bounded reference for the prepared-run ownership contract in the [approved #917 design](../docs/designs/issue-917-producer-reuse.md) and [producer reuse guide](evidence-reuse.md). It describes the current implementation and points to focused tests; source inspection alone is not proof of runtime behavior. Test names link by suite: [`EvidencePreparedRunTests`](../Aspire/ForgeTrust.AppSurface.Aspire.Tests/EvidencePreparedRunTests.cs), [`EvidencePreparedFailureCoverageTests`](../Aspire/ForgeTrust.AppSurface.Aspire.Tests/EvidencePreparedFailureCoverageTests.cs), and [`EvidenceHostPreparationOwnershipTests`](../Aspire/ForgeTrust.AppSurface.Aspire.Tests/EvidenceHostPreparationOwnershipTests.cs).

Cancellation requests work to stop; it does not settle or terminate the actual callback, factory, producer, child, or disposal task. Caller cancellation during `RunAsync` can return a `Cancelled` incomplete manifest while cleanup continues in the background. `DisposeAsync` joins that cleanup and can remain pending until actual work settles.

| Event | Cleanup owner | Observable result | Authority release allowed when | Test evidence / limitation |
|---|---|---|---|---|
| Preparation cancelled before registration or during key material | `EvidencePreparedRun` / reuse session retains producer registration and actual key callback | Initial cancellation throws before registration; active callback cancellation throws and starts no producer or resource work | Callback actually settles, owners are disposed, then session leases are released | `NullArgumentsAndInitialCancellationCannotCallRegistration`; `CancelledPreparationKeepsRegistrationAliveUntilTheActualMaterialCallbackSettles` |
| Key callback returns late, invalid data, or a fatal fault | Reuse session owns the callback task and producer registration through `DisposeAsync` | A late value cannot authorize a key; settled invalid material is ineligible for reuse and may proceed fresh; a returned prepared handle rethrows a late fatal failure on disposal | Only after the actual callback settles and its registration is disposed | `SettledInvalidKeyMaterialFallsBackToFreshExecutionWithTypedDecision`; `LateFatalMaterialCallbackRemainsOwnedAndItsFailureSurvivesPreparedDisposal` |
| Prepared run disposed before execution, or used after disposal | Prepared run shares one cleanup task; it owns registered producers and the reuse session | No producer runs; disposal is idempotent; later `RunAsync` throws `ObjectDisposedException` | After joined cleanup; no execution authority is admitted by a run that never starts | `AbandonedPreparationJoinsSynchronousCleanupExactlyOnce`; `PreparedExecutionRejectsNullFactoryRepeatedUseAndUseAfterDisposal` |
| Resource factory remains pending when caller cancels or `DisposeAsync` is called | Prepared run retains the actual factory task, producer registrations, session, and any eventual scope | Caller cancellation returns `Cancelled` with no complete claim; disposal requests factory cancellation and joins. A returned manifest is not evidence that the factory stopped | After the actual factory settles and all transferred owners are disposed; a throwing factory retains responsibility for its partial, untransferred construction | `LateFactoryAfterCancellation_ShouldRemainOwnedUntilActualTransferAndCleanup`; `Disposal_ShouldCancelAndJoinAnActiveResourceFactoryWithoutCallerCancellation` |
| Factory returns a scope after cancellation; host-admission/disposal race | Admission and disposal synchronize on `_cleanupSync`; cleanup takes a late returned scope if disposal/cancellation won | If admission wins, the host owns the execution and disposal joins it. If cancellation/disposal wins, the scope is retained for cleanup and readiness/producers do not start; result is `Cancelled`, claim `None` | Only after the actual factory settles and the returned scope and producer registration are disposed; then the key can be retried | `CancellationWinsFactoryHandoff_ShouldDisposeReturnedScopeWithoutStartingWork(bool disposeRun)` covers caller cancellation and disposal; `LateFactoryAfterCancellation_ShouldRemainOwnedUntilActualTransferAndCleanup` |
| Scope validation or factory fault | Before transfer, the consumer factory owns partial construction; after transfer, prepared cleanup owns the scope | Invalid binding throws `reuse.resource_scope_invalid`; nonfatal factory fault returns unavailable; fatal factory fault propagates after joined cleanup | Transferred scope/producer owners must finish disposal; partial construction remains factory-owned and must be cleaned before factory throws | `InvalidResourceTransferLeavesAllPartialConstructionOwnedByTheCaller`; `UnexpectedFactoryBinding_ShouldBeDisposedBeforeRejectingTheScope`; `FactoryFailure_ShouldReturnUnavailableAndJoinItsExplicitPartialCleanup`; `FatalFactoryFailureIsPropagatedAfterPreparedOwnershipIsJoined` |
| Host running: producer fatal or noncooperative past cleanup grace | Host and prepared run retain producer task, registrations, and resource scope | Fatal producer exception is preserved after actual cleanup; an unsettled cleanup yields `CleanupCompleted=false` and claim `None` | Never on grace expiry alone; release follows actual producer and owner cleanup | `FatalPreparedProducerFailureIsPreservedAfterItsActualCleanup`; `FatalProducerFailureRemainsPrimaryWhenFatalOwnerDisposalAlsoFails`; `CleanupGraceExpiryCannotReleaseThePreparedRegistrationOrProduceACompleteClaim` |
| Enrolled child is unknown after its handler joins, normal or fatal producer path | Reuse session and prepared run retain child session, producer, scope, and execution authority | Normal path is incomplete with claim `None`; fatal path preserves the fatal exception. A disconnected handler is not child settlement | A connected child may settle through its completion protocol. A disconnected, unknown child never becomes proof: preserve its `InFlight`/audit authority and use the [stopped-environment recovery procedure](evidence-reuse.md#admission-failure-and-safe-retry) | `ActiveCooperativeChild_ShouldKeepResourceScopeAndAuthorityUntilActualSettlement`; `DisconnectedChild_ShouldRetainResourceOwnersEvenAfterItsHandlerJoins(bool fatalProducer)` |
| Cleanup grace expires; disposal is repeated | Prepared run reuses its cleanup task; transferred scope disposes readiness before its application owner | Grace expiry reports incomplete cleanup and does not finish disposal; repeated disposal joins cleanup without disposing owners twice | Only after actual disposal completes; elapsed grace never authorizes release | `CleanupGraceExpiryCannotReleaseThePreparedRegistrationOrProduceACompleteClaim`; `PreparedRun_ShouldBeSingleUseAndItsDisposalIdempotent`; `ScopeDisposal_ShouldJoinActualApplicationCleanupOnce` |

Cancellation during preparation can return before an uncooperative key callback finishes, without returning a prepared handle. Cleanup remains owned in the background; its later failure cannot be rethrown through that already-completed preparation call. The late-fatal disposal guarantee applies when the caller has a returned prepared handle. Neither limitation permits early authority release.
